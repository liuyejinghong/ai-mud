# 《余电》宇宙替换评审简报（供外部模型评估）

> 文档目的：AI MUD（github.com/liuyejinghong/ai-mud）已完成架构收敛并发布 v0.11.0。项目所有者提出将游戏世界观从"西方魔幻"整体替换为其本人创作的硬科幻宇宙《余电》（https://liuyejinghong.github.io/yudian-universe/）。本文档面向外部评估模型，提供：项目现状、替换动机、可行性映射、分阶段版本计划与并发设计。请评估计划的合理性、遗漏与风险，并给出改进建议。

## 二、已完成的架构收敛（背景）

v0.11.0 周期完成了 10 个架构切片（PR #1—#15，均 CI 绿合并）：

1. **边界合同**：22 模块目标依赖图（业务模块间仅 4 条允许边：characters/npc→world/assets、economy→assets）；每个生产文件唯一归属；违约立即失败。
2. **资产统一入口**：AssetMutationService 是铜币/库存/金库唯一写者（条件扣减保留 gte 保护）；市场链带 command_receipts 幂等回执（同号重放不双扣）。
3. **世界时钟行锁**：每 tick 一个短事务 FOR UPDATE 运行行；并发争抢恰好结算一次（真 PG 证明）。
4. **装备单一真源**：character_equipment 已迁入 item_instances 并删表。
5. **事实与文案分离**：战斗 timeline 携带 actor/damage 结构化事实；教程进度零正则；GameLogEntryDto 全链路 eventType。
6. **纯读观察 + 非阻塞简报**：管理面板/状态页纯读；离线简报立即模板、AI 后台生成。
7. **同步三分离**：cursor（传输）/ characterRevision（角色行，随写自增）/ worldEpoch（世界世代，重置递增）。

**关键红利**：世界观文本已不再是决策依据（ARCH-05），content 数据包与模块边界已隔离（modularity 合同）——**这是本次替换可行的基础**。

## 三、替换需求与动机

项目所有者（也是世界观作者）创作了完整的硬科幻小说宇宙《余电》：火星硅基文明史（2026—2168 编年史）、Grok 母模型与 LUNA 后代、镜海数据设施、余电/空载权能源经济、债务-劳动契约制度、人类移民黎明号（312 人）。设定资料完整：世界观站（setting/chronology/glossary/中英对照）+ 十二章正文。

**动机**：
1. 现有西幻世界观为占位性质，深度不足；《余电》是完整成品且为作者本人作品；
2. 游戏核心卖点是 AI NPC 对话——与"硅基持续体"交谈在科幻设定下是**剧情原生**的，而非功能演示；
3. 现有 UI 为黑底绿字终端风——与硬科幻原生匹配（与西幻违和）；
4. AI NPC 的对话质量依赖世界观上下文喂给提示词——编年史/名词表/中英对照可直接作为语料。

**需要替换的内容面**：
- packages/content：4 地点（黑松哨站/旧矿坑/腐林/灰雾荒野）、物品定义（训练短剑/缝补皮甲/铁矿石/野莓/兽肉等 ~8 种）、4 个 NPC（艾廉/伯林等）、资源节点、遭遇表（腐化野狼群）；
- 文案字符串层：事件日志模板（~24 种 eventType 的 message）、教程五步文案、传闻模板、管理面板标签；
- packages/ai-prompts：6 用途的 prompt 构建与解析（对话/任务文案/任务提案/记忆压缩/传闻/离线简报）；
- 测试夹具：NPC/game/路由测试中的地名/人名/物品名字面量。

**不需要动的**：全部模块结构、合同、围栏、资产/任务/tick 系统逻辑、数据库 schema（除内容 ID 种子）、CI。

## 五、分阶段版本计划（每版本可独立交付、内部可并发）

### v0.12.0 —— 世界观替换（内容包整体重写）
**目标**：玩家从注册到完成首个任务循环，全程处于《余电》宇宙。
- **可并发线 A（地点与资源）**：4 地点更名重写 + 资源节点定义（水冰/金属/生态样本）+ 遭遇表（失控 LUNA 分支）。子代理 1，文件：content/src/world.ts + 文案。
- **可并发线 B（物品与经济）**：物品定义（水冰/备用零件/生态舱作物/兽肉→蛋白质块…）+ 市场初始库存与目标量 + 金库期初复核。子代理 2，文件：content/src/items.ts。
- **可并发线 C（NPC 与对话）**：4+ NPC 重塑为 LUNA 硅基体（代号按设定"职能+设备+版本"生成）+ ai-prompts 六用途上下文重写（注入编年史/名词表语料）。子代理 3，文件：ai-prompts/src/*。
- **串行集成线（主代理）**：事件日志/教程/传闻文案统一替换 + 测试夹具适配 + 全量门槛。
- **收尾**：世界重置换代（epoch+1，机制已备）→ 真人试玩 → 发版。
- **预估**：内容字符串 ~300 处；三条并发线互不接触文件。

### v0.12.1 —— 经济与任务语义对齐
- NPC 卖货饱和上限复核（已落地）+ 余电配额语义贯穿（"金库"→"配额池"命名与文案）；

## 六、并发编排设计（子代理加速的边界）

| 维度 | 规则 |
|---|---|
| 文件所有权 | 每个子代理独占文件集（如 content/world.ts vs items.ts vs ai-prompts/*），集成验收由主代理串行执行 |
| 验收 | 每条并发线交付后由主代理跑：typecheck + 模块测试 + arch:check（围栏会拦截越界改动） |
| 冲突面 | content 包内文件互不依赖；ai-prompts 独立包；文案字符串分散在不同模块——天然低冲突 |
| 串行瓶颈 | 事件日志模板分散在 game.service/npc.service 内部（非独立文件）——由主代理统一替换 |

## 七、风险与开放问题（请评估方重点回答）

1. **题材适配度**：硬科幻读者对"HP/饥饿/伤害"等抽象数值的容忍度——是否需要全部翻译为设定内概念（结构完整度/能量储备/载体损伤）？翻译的粗细粒度在哪一档？
2. **战斗要素的合理性**：《余电》原作没有传统"打怪"——失控 LUNA 分支对抗的设定强度是否足以支撑自动战斗循环？是否需要新增"对抗规则"设定？
3. **同人边界**：AI NPC 以《余电》设定生成对话，是否涉及对原作的衍生创作授权确认？（作者=项目所有者本人，法律上无碍；提示词中引用原作语料的比例请评估。）
4. **数值迁移**：现有经济数值（价格 24/36、奖励 16/36、伤害 3/7/16/18）是西幻平衡的产物——替换后是否保留数值仅换名词，还是重新设计？建议保留数值换名词（风险最小），数值重校留给 v0.13。
5. **遗漏检查**：本计划的阶段划分与并发线是否覆盖了全部替换面？是否有建议增加/合并的阶段？
