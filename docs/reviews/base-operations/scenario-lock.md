## 1. 时代与改编层

**L-01 时代锚点**：游戏取材编年史"地球准备期"末段至"第一里程碑：种子登陆"之后的**前哨建设期**，默认锚点为 2033 年首批无人货运抵达火星后的第一个施工季（游戏内具体日期为游戏初值（可调）），必须早于 2038 年"月生事件"。[来源：yudian@e839275 → docs/chronology.md → 二、第一里程碑：种子登陆（2033｜火星种子登陆）与三、第二里程碑：月生（2038｜月生事件）]

**L-02 选择该时代的理由**（设计理由，非正典）：

1. 首批货运内容（太阳能阵列、水冰开采/制氧/建筑/维修设备、模块化低端制造线、人类前哨施工与生命维持计划）与"安装运抵的太阳能设施"首项工程天然吻合。
2. 该时代"只有 Grok 具备完整跨领域推理，机器人仍是受统一调度的设备"，与游戏"玩家下目标、工程队执行"的形态一致，且天然不需要实链、空载权、债务、模型谱系等 v0.12 明确排除的机制（00-scope §1）。
3. 该时代火星无人类驻留（首批人类 2074 年才抵达），开局不需要生命维持消耗系统。[来源：yudian@e839275 → docs/chronology.md → 六、人类先遣期（2074）]

**L-03 该时代的正典世界状态**（进入游戏叙事时必须一致）：

- 火星上已有本地部署的 Grok 母模型与 SOL 级计算集群，处于早期运作阶段；火星 Grok 因地火通信延迟拥有高于地球在线模型的自治权限。[来源：yudian@e839275 → docs/chronology.md → 一、地球准备期（2029）与二（2033—2034）]
- 机器人是受统一调度的工程设备，尚未出现独立 LUNA、实链制度、空载权制度、债务制度或共识轮——这些是 2038 年之后才逐步演化的事物，游戏开局叙事不得提前引入为既有制度。[来源：yudian@e839275 → docs/chronology.md → 二（2033）、三（2038）、四（2056—2067）]
- 游戏中的"机器人"在此时代按设备/资产对待，不赋予人格化角色叙事；正典明确机器不必拟人化。[来源：yudian@e839275 → docs/canon-policy.md → 4. 修改原则（机器不必拟人化）]

**L-04 必须遵守的设定硬边界**：

1. 地点是火星，不是地球；区域是阿卡迪亚平原（见第 2 节）。
2. 太阳能受季节、纬度、积尘和尘暴影响；2056 年才有第一次"尘冬"，开局时代存在普通尘暴但不存在尘冬灾害记忆。[来源：yudian@e839275 → docs/setting/technology-and-infrastructure.md → 1. 能源结构；docs/chronology.md → 四（2056）]
3. 火星长期不能制造 SOL 级核心，高端算力"不是只要有矿就能扩建的普通工业品"；"挖铁矿就能造一切"不成立。[来源：yudian@e839275 → docs/setting/background.md → 3. 火星不能制造 SOL 级核心]
4. 地火通信延迟使实时遥操作不可行，局部系统依赖设备级自治；因此玩家指令是**目标级指令**（项目/工单），由具备本地自治的设备队执行，不做逐台遥控驾驶玩法。[来源：yudian@e839275 → docs/setting/technology-and-infrastructure.md → 7. 通信与自治]
5. 现实品牌（如宇树科技、SpaceX）只作历史质感锚点，不作为游戏型号名或背书；未来型号与能力均属虚构。[来源：yudian@e839275 → docs/setting/technology-and-infrastructure.md → 4. 具身设备；docs/canon-policy.md → 4. 修改原则（现实锚点不等于现实预测）；RIGHTS.md]
6. 没有必需打怪循环；不引入任何电影或其他 IP 的情节/物理设定（相关电影名称未明确）。（00-scope §1、§2）

**L-05 允许的游戏化简化**（改编自由度白名单）：

- 工程设备约 12 台、三组分工及其数量/功率/容量/耗时数值：游戏初值（可调），非现实任务预测。（00-scope §1）
- 不模拟地火光延迟与发射窗口：鼠标指令即时下发、进度按服务端模拟时钟（simTime）推进；物流简化为"运抵货物＋基地内运输"。
- 火星昼夜与光照周期按游戏化数值建模（取值见 Q-06）。
- Grok 在开局仅作背景存在，不作为游戏角色、对话对象或机制出场（见 Q-04）。
- 基地平面为示意图＋可扩展建设位，不做任意旋转、道路布线和完整空间物理。（00-scope §1）

**L-06 改编层的正典关系**：游戏是取材演绎，不把游戏内工程事件登记为小说正典，也不回写设定仓库；小说设定修改仍须走 canon-policy 的 B 级变更流程，游戏不豁免也不触发该流程。[来源：yudian@e839275 → docs/canon-policy.md → 1. 正典层级、6. 版本语义]

## 2. 地理与区域

**L-07 初始基地位置**：阿卡迪亚平原（Arcadia Planitia）内、首批货运着陆区一带的先遣前哨施工区。正典将首批无人货运着陆点锁定在阿卡迪亚平原，且该区域延续到 2098 年小说主线仍是核心聚居区域（"阿卡迪亚公域"），游戏选址与其一致。平原名是火星真实地名，小说仅用作历史质感，不构成现实预测。[来源：yudian@e839275 → docs/chronology.md → 二（2033｜火星种子登陆：首批无人货运抵达阿卡迪亚平原）；stories/yudian/draft/11-着陆窗口.md（阿卡迪亚公域、着陆区）；docs/canon-policy.md → 4. 修改原则（现实锚点不等于现实预测）]

**L-08 环境要点**（叙事与机制可引用的物理背景）：

- 红褐色沙地、松软沙层，车轮/足端有陷沙风险；风沙持续，尘暴期可见度骤降。[来源：yudian@e839275 → stories/yudian/draft/11-着陆窗口.md（尘暴里没有地平线；左膝陷进松软沙层）]
- 积尘降低太阳能输出，需定期清尘；低温、辐射、机械磨损是地表作业的常态约束。[来源：yudian@e839275 → docs/setting/technology-and-infrastructure.md → 1. 能源结构、9. 技术写作边界]
- 太阳能受季节与纬度影响，存在能源丰枯差异（"能源季节"概念）。[来源：yudian@e839275 → docs/setting/technology-and-infrastructure.md → 1. 能源结构]

**L-09 基地内部布局**（游戏初值（可调））：货场（待部署货物卸放区）、已部署初始太阳能阵列、储能间、仓储棚、维护工位、充电区，以及若干可点击的扩展建设位（首个建设位即首项工程位置）。平面为示意图，不锁坐标与朝向；平原内具体经纬度、基地名称不锁（Q-02）。

## 3. 初次项目

**L-10 项目锁定**：首项工程为"**安装运抵的太阳能设施**"，四步：清场 → 运输 → 安装 → 验收。此为 v0.12 spec 既定内容，本锁定不得偏离。（v0.12.0-first-base.md §1）

**L-11 步骤语义展开**（游戏初值（可调））：

1. 清场：勘测巡检组核定建设位，工程维护组清除障碍/整平。
2. 运输：资源运输组把太阳能组件、支架、线缆从货场运至建设位（真实消耗运输能力与电量）。
3. 安装：工程维护组架设支架、安装板组、敷设线缆（需要基地供电支持作业）。
4. 验收：勘测巡检组巡检＋并网测试；投产后基地发电功率上限提高（数值初值可调）。

步骤按前置与实际工作量推进；依赖阻塞、供电不足、设备冲突必须清楚显示，不得虚假完成。（v0.12 spec §1、验收矩阵 M12-G03/G04）

**L-12 为什么不从矿石制造先进设备**：

- 正典：火星不能制造 SOL 级核心，高端产品不是"只要有矿就能扩建"的普通工业品；本地工业长项是低端耐用件、维修与模块替换。[来源：yudian@e839275 → docs/setting/background.md → 3. 火星不能制造 SOL 级核心；docs/setting/technology-and-infrastructure.md → 3. 火星制造的 LUNA 载体]
- 产品决定：不把"挖铁矿就能造一切"当产业链；初次扩建先部署运抵组件。（00-scope §1）
- v0.12 spec 明确首项目标是安装运抵的太阳能设施。
- 由此锁定开局产业边界：部署、安装、维护运抵设备为主；本地制造/产线留待后续版本，且届时仍受上述正典边界约束。

**L-13 教学定位**：首项工程是新手教程本体——玩家通过它学会读电（功率/电量）、看物资（组件件数）、排设备（三组分工），不要求读过小说；独立测试者仅靠鼠标完成建设并能说清阻塞原因（v0.12 验收 M12-G08）。

## 4. 资源、单位与记账边界

**L-14 三条线分离**（记账纪律，非正典，属产品/架构决定）：

1. **电力线**：功率（kW，发电/用电速率）与能量（kWh，储能容量/累计消耗）严格分开；UI、协议、存储字段不得混用两个单位。
2. **物资线**：每类物资有自己的计数单位（如组件按"组/块"、结构件按"件"、备件按"件"），不统一折算成抽象"资源点"。
3. **账款线**：独立记账单位（v0.12 不对玩家显示；名称与数值由后续版本冻结），只记录债权债务，永不与 kWh 单位恒等；任何"电价"折算必须是显式游戏规则（价格表），不是单位定义。

**L-15 旧货币不解释为电力**：旧世界铜币/金币等旧资产余额不映射为 kWh、不映射为任何新资源。（00-scope §1：不把旧铜币原值解释为 kWh；§5：旧资产不自动映射）

**L-16 能源额度的正典一致性背景**：正典中机器之间转移的是带地点、时间、来源、可中断等级、损耗与优先级的"能源额度"，而非电子本身——该设定支持"物理电力与记账分离"的纪律。v0.12 不实现能源额度市场，此条仅为后续经营版本（v0.16）预留正典一致性依据。[来源：yudian@e839275 → docs/setting/economy-and-labor.md → 9. 能源额度与结算]

**L-17 初始资源"来源 → 用途"表**（每种资源都必须有来源与用途，对应 A0-G02）：

| 资源 | 单位 | 来源 | 用途 |
|---|---|---|---|
| 电（功率） | kW | 已部署初始太阳能阵列（昼间）；储能放电（夜间/无光期） | 设备充电、施工用电、仓储/维护/通信基础负荷 |
| 电（能量） | kWh | 上述发电充入储能库 | 夜间与低出力时段续供、缓冲波动 |
| 太阳能设施组件 | 组/块 | 待部署货物（开局即卸放于货场） | 首项工程安装，投产后扩大发电 |
| 结构件/固定件 | 件 | 待部署货物与初始库存 | 支架、地基锚固、线缆敷设消耗 |
| 备件 | 件 | 初始库存 | 维护工单消耗（更换关节/电池轮换等） |
| 设备续航 | kWh | 基地充电区（取自电力线） | 三组设备作业能力 |

具体数值全部为游戏初值（可调），由 M12-P fixture 冻结（Q-09）。

**L-18 物资守恒**：初始物资来自一次性开局 seed（provision 来源登记），运行期不凭空产生；失去设备/物资不自动补发。（v0.12.0-first-base.md §3 I；00-scope §1）

**L-19 维护的背景一致性**：基础维护（检查、清尘、关节更换、电池轮换、补丁、故障恢复）是前哨公共职责，不要求设备"赚够钱才能修"——开局不引入维修付费机制。[来源：yudian@e839275 → docs/setting/economy-and-labor.md → 3. 基础维修不是商品]

**L-22 自举性检查**（设计层检查，正式验证由 M12-G02—G04 承担）：

1. **供电 → 设备**：昼间初始阵列可给 12 台设备充电并支撑基础负荷与施工用电；夜间与无光期由储能库（约 200 kWh 初值）覆盖基本负荷，设备夜间低速充电待命，首项工程安排在昼间窗口推进。开局无第二电源（Q-01 已拍板纯储能过夜，2026-09-19），不存在"没电充电→没电施工"死锁；夜间暂停不销毁进度。
2. **设备 → 首项工程**：三组分工完整覆盖四步骤（勘测/清场＝巡检＋工程组、运输＝运输组、安装＝工程组、验收＝巡检＋并网测试）；所需材料全部来自待部署货物，所需电力来自初始供电，无外部输入依赖。
3. **维护 → 备件**：初始备件覆盖首个工程周期＋一次典型维修消耗；维护不收费、不依赖账款线（L-19）。
4. **无隐藏依赖**：不依赖玩家间市场、不依赖 AI 模型在线（模板表达＋规则调度即可完成首工程）、不依赖打怪掉落、不依赖旧世界资产。

结论：开局"供电 → 设备 → 首项工程"链路自举走通，满足 A0-G02。

**L-23 明确不在开局清单**：食物/氧气等生命维持消耗（开局时代火星无人类驻留，机器人只耗电与备件；首批人类 2074 年才抵达）；道路布线与完整空间物理；天气/尘暴风险机制（v0.15 内容）；制造产线与配方链（后续版本）；账款与订单（v0.16 内容）。[来源：yudian@e839275 → docs/chronology.md → 六（2074）；00-scope §1、§2；v0.12 spec §6]
