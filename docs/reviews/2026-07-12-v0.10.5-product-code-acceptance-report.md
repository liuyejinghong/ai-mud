## 2. 阻断级发现

### P0-1 进行中的采集可并发重复结算

`GameService.getSync()` 会在每次轮询中调用 `settleReadableState()`，后者对进行中的采集调用 `settleGatheringAction()`。结算读取旧的 `payload.settledCycles` 和地图资源数量，发放物品后再无条件写回 payload 和资源数量；过程中没有 `FOR UPDATE`、CAS 或唯一结算凭证。

两个标签页或两个并发请求可以同时结算同一批周期，造成：

- 同一周期奖励被发放两次；
- 资源点只扣减一次或发生丢失更新；
- 物品账本记录两次合法 grant，普通守恒检查无法识别业务重复。

相关位置：

- `apps/server/src/modules/game/game.service.ts:458-468`
- `apps/server/src/modules/game/game.service.ts:1437-1477`
- `apps/server/src/modules/game/game.repository.ts:968-972`

### P0-2 市场并发一致性债务仍未关闭

买入流程仍为“读取角色余额和市场库存 → JS 校验 → 原子扣角色铜币 → 绝对值写市场库存”。两个并发买入可同时通过旧快照校验，随后：

- 玩家获得两份物品；
- 市场库存只体现一次扣减；
- 角色铜币可能被扣成负数；
- 价格依据的库存快照与最终库存不一致。

卖出和修理也存在同类“先读后写”的并发窗口。路线图 §4.5 已把 I3 标记为关闭，但实现仍是审核报告原先指出的模式。

## 3. 高优先级发现

### P1-1 `/game/sync` 丢失 NPC 任务和传闻

`withNpcTasksAndRumors()` 只包装旧 `/game/state` 和部分 mutation 返回值。当前前端只消费 `/game/sync`，而 `GameService.buildState()` 固定写入 `npcTasks: []`、`rumors: []`。

实际结果：

- NPC 对话列表能显示 `!`，主界面却没有可接任务；
- 对话提示玩家去“NPC 任务面板”，但该面板没有数据；
- 传闻生成和展示在真实客户端路径中停止工作。

### P1-2 任务和传闻仍由玩家读请求驱动

`NpcTaskService.listTasksForAccount()` 会先执行 `syncOpenTasks()`；该流程遍历 NPC、检查需求，并可能在数据库事务内等待 AI 提案。传闻唯一生产调用同样位于 `/game/state` 的读路径。它们没有进入 world tick，与路线图声称的 I1 已关闭不一致。

影响：AI 开启后普通读取可能持有长事务；AI 关闭时仍有 N+1 查询；当前 `/game/sync` 又绕开了这条路径，导致功能事实上失活。

### P1-3 行动轮询可能退化为近似无间隔请求

`useGameSync` 的 effect 依赖整个 `activeAction` 对象。行动期间服务端每次返回新的 state/currentAction 对象，React effect 会清除 3 秒定时器并立即重新执行 `poll()`。这既可能打高 QPS，也会放大 P0-1。

### P1-4 NPC 物资请求不符合已确认的 AI 产品语义

当前实现使用正则和固定阈值直接决定是否赠予，AI 性格、记忆、牺牲成本和玩家表达不参与取舍。数量在解析阶段先被截断到上限，因此“索要 100 铜”会变成“索要 5 铜”，`quantity_too_high` 分支不可达，甚至可能错误赠予。

正确边界应为：规则确定 NPC 是否拥有、能否承担和最大可给数量；AI 在合法候选内根据人格、记忆和关系提出 `grant/refuse` 意图；规则再次校验并执行。AI 不能创造资产，也不能改写数量。

### P1-5 返回玩家可能被饥饿永久软锁

实测角色处于 `hunger=0`、`hp=1`、`copper=0`、背包无食物。系统禁止出城，但没有城内工作、救济或低保食物路径；市场需要铜币，陌生 NPC 的物资请求会被固定规则拒绝。与此同时 `availableActions` 仍下发出城动作，按钮点击后才被服务端拒绝。

## 6. 产品逻辑结论

### 保留的决策

- 刷宝成长作为基础留存主循环是合理的。
- 完整副本、玩家交易、共享野图继续推迟到内测反馈后是合理的。
- 服务端规则拥有事实、资产和最终执行权是正确边界。

### 必须纠偏的决策

路线图把 AI 定义为“放大器而非主钩子”，实现又进一步收缩为“AI 只能生成文本”。这与产品最初的差异化目标不一致。当前六个 AI purpose 都是表达、摘要或分类，没有 NPC 日计划、行为意图或世界适应。

正确架构不是让 AI 直接写世界，也不是让 AI 只写文案，而是：

`Observe facts → Retrieve memory → AI proposes structured intent → Rules validate → Server executes → Event and memory feedback`

完整 AI 副本可以继续推迟，但 v1.0 前至少需要一个可观察的 AI 原生闭环，建议使用“NPC 每日计划与临时改计划”作为最小垂直切片。

## 8. 修复决策

本报告的问题按四个模块进入 v0.10.6 修复包：

1. A：资产与行动并发一致性；
2. B：统一同步、world tick 与后台生产职责；
3. C：饥饿恢复、NPC 任务与核心玩家闭环；
4. D：HUD 架构、响应式与真实 E2E。

四个模块全部通过后才能将 `PRODUCT_VERSION` 提升到 `0.10.6`。AI 原生 NPC 意图闭环作为独立的 `v0.10.7` 设计，不与修复包混做。
