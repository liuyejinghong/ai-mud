## 1. 产品中心

玩家在地球通过鼠标经营火星基地；工程队按目标、约束、分工和反馈执行。基地平面图显示世界变化，项目板/机器人 todo 显示真实作业过程。不是西幻 MUD 换皮，不以角色升级、WASD、打怪掉落为中心。

新手只需理解电、物资和作业能力；小说提供背景与边界，不要求先理解实链、空载权、模型谱系。开局是一支可自举的先遣工程队；约12台、三组分工是可调游戏初值，不是现实任务预测。

## 4. 版本内部执行方式

每个实施版有7个工作包：P接口/所有权冻结 → A/B/C/D并行实现 → Q独立验收 → I集成交付。P是小型共同合同，不是先写完所有后端。Q可以提前设计/实现独立测试；其最终通过必须在所有实现集成后的同一HEAD上成立。

各包内部按“合同和失败测试→最小实现→真实连接→移除旁路”拆小提交。主代理负责共享文件、事务装配和集成，不吞掉所有业务实现。通常3—4个实现代理加独立验收者即可，不能为开更多代理制造接口层。

提前研发仅限已冻结接口后的隔离工作：Jev适配/测例、内容后台原型、天气纯规则、订单UI样例。不得跨版并行修改同一状态机、schema、客户端session或公共协议；提前工作不等于提前发布。

## 5. 通过状态与版本语义

- CONTRACT_READY：本轮实际文件、输入输出、失败语义与样例已冻结，可按授权并发。
- ENGINEERING_PASS：冻结提交的相关规则/合同/真PG/浏览器验证通过。
- PLAYTEST_PASS：独立玩家完成目标且理解因果，不能由模型自评替代。
- LIVE_MODEL_GATE_PASS：已授权真实模型实验达到预先冻结门槛，和mock/适配器通过分开。
- RELEASE_READY：本版必需门槛、迁移回退与剩余问题经独立确认；不自动授权生产发布。

未运行写NOT_RUN，缺资源写BLOCKED。v0.14真实模型未通过时可以以明确的RULE_MODE继续下游工程，不得声称Jev效果通过；v1.0若仍不启用真实模型必须明确产品范围并重新取得用户确认，不能静默把AI决策卖点删掉。任何启用的用途必须有实测证据。

实际发布才更新PRODUCT_VERSION；不预写schema/API递增值，不使用根package.json的旧版本号替代产品版本。机械内容修订与程序版本独立；已开工工单固定内容修订。

## 6. 与旧计划的关系

`docs/implementation/2026-09-18/` 的未来排期、旧v0.12—v1.1文件以及PR #18原三条改名线，均为历史参考，本目录是后续唯一实施顺序。旧架构PC约束、已实现资产/时钟/护栏等能力继续有效，不重做已完成ARCH/MOD。

旧目标中的共享小镇、角色懒结算和固定职业并非新产品强制中心；独立基地的作用域、暂停和制造按本目录新增合同设计。PC的权威、封装、事务、事实和证据要求不因玩法变动失效。

旧玩法退出要列API/UI/seed/定时器/数据/测试退役清单；保留适用的资产与并发测试，不用删除测试掩盖新问题。不把旧存档里的金币/NPC/装备无声改造成能源/机器人。

## 7. 停止扩框架的条件

v0.12必须出现一次可玩的建设；v0.13证明数据驱动扩展；v0.14证明真实决策接入；之后用经营场景检验框架。没有真实消费者就不创建模块、DSL、通用CommandBus、动态插件、微服务或第二套任务引擎。复杂新行为可以通过批准的ADR扩展，不承诺永久零代码修改。
