# v1.0.0：基地经营内测交付

状态：PLAN_APPROVED / NOT_IMPLEMENTED。前置：M12—M16工程与对应内容基线；模型效果状态透明。目标是可邀请小规模玩家测试，不是未经测量的大型多人上线。

## 1. 本版范围

不临时新增大系统。完善首次体验、平衡、内容权限/兼容、运行恢复、性能、模型费用和独立验收。新用户不需小说背景，不需邀请码/职业选择，鼠标即可建造、制造、安排项目、应对尘暴、完成再投资。

开发试玩可保留简单密码策略，但必须隔离数据/配额和管理权限；正式公开运营若使用不同账号政策，另行验收，不能把开发模式无声用于正式敏感账户。

## 2. 工作包与所有权

| ID | 职责/文件 | 输出 |
|---|---|---|
| M10-P | 主代理：冻结release candidate HEAD、内容/规则/SDK/模型版本、运行环境/范围与验收阈值 | 测试发现/性能/费用预算、迁移与公开试玩范围；避免边测边偷偷换数值 |
| M10-A | 体验线：base/tutorial、文案/空状态/帮助的指定文件及自测 | 按实际里程碑逐步引导、可跳过说明、鼠标/键盘可达、无高概念阻塞 |
| M10-B | 平衡/内容线：批准的release草稿与仿真配置，不并改运行算法 | 自举开局、短链、策略差异、有限失败恢复及版本化调参记录 |
| M10-C | 运行线：配置/健康/部署文档/迁移与恢复测试指定文件 | 暂停/重启/数据升级/备份恢复、权限和日志隐私；生产操作另授权 |
| M10-D | 性能/费用线：隔离基准与分析脚本、AI预算相关指定文件 | SQL数量/锁等待/tick积压/请求费用等实测；必要优化不改规则语义 |
| M10-Q | 独立验收：tests/base-operations/release及真人记录 | 冻结HEAD上全链、真实环境证据，不只读各线总结 |
| M10-I | 主代理：版本/兼容清单、release notes、已知问题与发布建议 | 汇总同一提交/内容版本；未达门槛不标ready，不自动合并/上线 |

A与B都涉及文案时由P拆分确切文件/内容ID；C/D共享配置有单写者。性能修改导致规则/协议变化时回P评审，不能在收尾阶段顺手换库/框架。

## 3. 首次体验验收路径

新账号→基地建立一次→查看电/物资/设备→部署首组设施→安排作业→制造新设备→观察协作/或明确RULE模式→根据预报备灾→风暴后恢复→交付有限订单→再投资。

游戏状态不足时显示实际阻塞，不让玩家手写prompt才能继续。不用假todo/假预测/无限系统奖励拼演示。UI重点显示项目与异常，详细日志/设定作为可选信息；未读小说者能够说明选择代价。

Q招募独立测试者，记录是否成功、在哪一步停下、需要何种提示、是否理解停工和下一步目标。人数/时长目标在P前冻结；没有测试者写PLAYTEST_PENDING，不由AI角色扮演代替真人。小说读者也可做补充，但不是唯一测试群体。

## 4. 工程与恢复

记录真正运行的arch:check、arch:test、typecheck、规则/合同、PG、E2E及测试数量。重点重跑：base权限、注册初始化、制造ordinal、部分取消、运输归属、资源竞争、内容激活、旧payload/epoch、模型过期和停机。

从备份恢复到独立环境，验证基地/资源/工单/内容ref/receipts/AI决策状态一致。恢复后不会补发初始物资、重结算制造、重放历史付费请求。所有迁移与回退必须用实际schema journal，不猜SQL编号。

程序版本、内容release、SDK/model、规则/economy版本、seed、配置一起记录；旧存档不认识的新能力须明确迁移或拒绝，不能fallback造事实。原西幻存档只按批准策略处理。

## 5. 平衡、分析与负载

明确目标测试规模的基地数、每基地机器人/工单/内容数、模拟加速倍率与并发命令；数字在实测报告中出现而非架构承诺。观察端到端响应、tick积压、锁等待、查询次数、内存、队列长度、API使用/费用。

按固定场景比较扩产/储备/维护/运输路线，包含新手失误、离线、天气变长和关键设备停机。不只用账本零偏差证明经营成立。

可用DuckDB读取隔离导出做批量分析，导出包括版本/seed/政策/时间范围；不承担在线余额/库存，不实时双写。Agent分析用去标识的副本、受限文件访问和资源上限；不拿生产连接和任意SQL权限。

性能优化先处理实际查询/调度热点，必要改变能力才提出ADR，不以“AI游戏”名义迁库、微服务或安装完整监控平台。

## 6. AI门槛与诚实发布

每个LIVE purpose独立附中文留出对照、阈值、使用/错误/过期/降级/费用数据。不能用SDK可调用、供应商benchmark或mock概率替代。模型关闭后基础作业与读状态可用，不自动切换更贵总控。

M14真实效果未通过时，下游工程可以继续；本版若仍只运行RULE，发布文案必须明确，且需用户确认是否接受缩小AI能力范围。否则LIVE_MODEL_GATE保持阻塞，不静默删掉用户确认的智能协作目标。

## 8. 交付与非目标

输出release report、操作/恢复说明、用户测试摘要、经济与模型分析、未解决问题和下一步建议。所有证据对应同一候选提交或明确的重新验证提交。

不安装像素引擎，不引入实时多人经济，不因赶v1.0吞掉BLOCKED。版本可以延后，验收事实不能伪造。文档/工程交付不等于生产部署授权。
