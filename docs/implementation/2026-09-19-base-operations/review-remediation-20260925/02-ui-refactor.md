## 1. 玩家结果

玩家进入基地后能定位当前目标、当前是否推进、需要处理的异常；选择建设位后能连续完成“看条件→开工→看结果→继续安排”。进入采购、制造或历史后能返回原对象和未完成计划。

**重构的是信息组织和界面状态，不是把长页机械拆成多个路由。** 单页、标签、侧栏或覆盖层均可；P应冻结一个具体可玩方案，不把所有备选同时实现。自动滚动可作局部辅助，不能成为唯一结构方案。

## 2. 建议的信息层级

| 层级 | 默认显示 | 进入/退出行为 |
|---|---|---|
| 常驻概览 | 基地身份、紧凑时间控制、关键电力/账款摘要、当前目标或异常入口 | 在专项工作区仍可辨识状态；窄窗可缩为摘要，不能让长邮箱挤压操作 |
| 基地主场景 | 基地示意图、活动项目/下一目标、必要世界变化 | 地图是主要选择入口；设备按工作组摘要，完整12+台设备列表按需展开 |
| 对象/任务详情 | 所选建设位/工程/机器人/材料的条件、操作、结果 | 与当前选择建立明显关系；选择后主操作进入可见任务区域；可关闭/返回且保留选择 |
| 专项工作区 | 经营（订单/采购/物流）、制造（配方/工单） | 有明确入口及返回路径；显示当前相关成本和约束，不要求跨整页记忆 |
| 历史/设置 | 协作完整历史、已完成事务、账号/设置 | 默认不挤占主场景；历史增长不改变核心入口的位置 |

不引入自由面板编辑器、插件系统、通用工作流、持久化布局服务、新UI依赖或像素引擎。优先复用现有组件及已有状态/回调；只为实际需要新增少量视图状态。

## 3. 三条必须连续的路径

| 路径 | 同一任务现场必须可获得的信息 | 成功/失败后如何接续 |
|---|---|---|
| 建设位→工程 | 目标、产出说明、材料可用/缺口、时间模式、开工动作 | 就地显示受理和新工程；能直接看步骤；暂停/缺料/缺电有原因及正确出口 |
| 配方→制造 | 单台/批量成本、可用量、产出、当前供能解释 | 工单在当前工作区可见；失败指出条件；完成与取消终态一致 |
| 缺料→采购→原工程 | 原工程缺口、可支配账款、数量/价格、在途与到货规则 | 能找回原工程和缺口；付款不当作入库，返回不丢已输入数量/对象 |

M的新投影尚未冻结时，可在隔离UI切片使用明确标注的共同fixture；没有真实数据接线前不得把材料解释标为通过。模拟fixture不得注入线上存档。

## 4. 状态与输入合同

- 当前工作区、所选对象、表单数量及焦点由明确的客户端状态管理；现有BaseApp的选择状态应先复用，不创建第二套请求/业务裁决。
- 地图→详情→专项工作区→返回，默认至多两次明确导航动作回到原对象。保留对象身份及表单值；账号/基地切换必须清除旧上下文。
- 新快照不抢输入、不开关用户正在阅读的面板、不把滚动位置重置到页首；对象已失效时给可理解说明和可达出口。
- 各命令的busy/成功/错误对当前任务可见；保留已有固定toast，但错误还需指向对应条件，不能仅堆toast。
- 暂停属于实际timeMode：在项目/工单现场说明其对推进的影响，提供正确的恢复入口。不能只按“待开工”推断缺电。
- 后台、离页、恢复、刷新继续遵守原心跳与时钟规则，前端重组不得更改结算时机或额外发命令。
- 浅层低风险查看不加确认；取消等既有有损操作保留影响说明与确认。终态操作由真实状态决定可用性。
- 弹层有焦点进入、Escape/关闭、背景输入隔离及关闭后焦点归还；窄窗详情可占主区域，不能产生被困住的双重滚动。

## 5. 视口验收合同

基准：1200×800；同时复核历史实际1200×701、720×450，另测200%缩放。记录 `innerWidth/innerHeight/deviceScaleFactor/zoom`，不混用屏幕像素与CSS像素。

1. 新号关闭引导后，当前目标、时间状态与进入主任务的入口可见；不能先滚过采购目录才能找目标。
2. 点击建设位，主动作进入当前可见详情区域。长详情允许内部阅读滚动，但要有明确边界，不能让玩家猜结果在整页哪里。
3. 执行一次操作后，受理、结果或具体失败原因留在任务上下文；切回主场景看得见世界/项目变化。
4. 长邮箱、12/13台设备、零设备、50+历史、长名称不会把主要操作挤成竖排或移出主入口。
5. 记录下的像素数是旧版复现条件，不要求新版恰好小于某个整页高度；验收看实际可发现性和操作成本。
