## C：协作记录可读性（F03、C07）

**目标**：玩家先看到正在发生的协作、阻塞原因和需要自己处理的事项；历史不撑长主场景。

- 根据现有请求身份、项目、步骤和状态展示活动摘要；默认收起已结束记录，提供可追溯的历史入口。
- 同一请求的状态变化可合为一条玩家记录；不同请求不能只因文案相同而误合并。显示玩家可理解的对象名称，完整 UUID 留在诊断信息中。
- 失败、阻塞和待玩家决定的请求不能被摘要吞掉。打开详情、关闭后保留原任务。
- 先核对请求生命周期。只有证明同一业务意图被重复创建，才另列后端幂等修复；不得删除数据库历史或把前端折叠当后端去重。

源码定位：`apps/web/src/features/base/CooperationPanel.tsx`；服务端 industry 模块的 `cooperation.service.ts`、`cooperation.repository.ts`。以新基线实际路径和 public 边界为准。

验收 A05：构造含至少53条历史、两个活动项目、一个阻塞请求的隔离样例；主屏高度不随历史条数增长，活动与异常可见，每条摘要可查来源，项目之间不串记录。与0条历史比较同一核心操作的位置和可达性。

风险与回退：错误分组会隐藏工作；保留原始数据，用确定身份而非文字相似度聚合。必要时回退呈现提交，不清历史数据。

## M：材料总量、占用和可用量（F04、C08）

**目标**：玩家在建设、制造和交易现场能预测是否具备条件，失败时知道缺哪种材料及如何恢复。

先调查再冻结：

1. 从基地 snapshot 的库存读取，追到资产 public API 的库存与预留事实，再追建设、制造、采购、订单的所有相关消费者。
2. 记录数量的单位、所有者、更新时间和是否包含预留。在途单独显示；未入库不属于当前可支配材料。
3. 明确总库存、已占用、可支配量的等式及预留归属。如果现有 quantity 实际已是可用量，就修真正不一致的来源，不能再减一次。
4. 在隔离存档复现 F04，记录请求前后状态和受限材料；本次线上“8库存却失败”不能反推“8全部被占用”。

建议最小合同：复用 canonical 资产事实，在现有 snapshot 或必要 public 查询中暴露足够的材料解释；P 决定确切字段、兼容方式和唯一写者。避免第二套库存、客户端计算权威预留、逐卡请求拼接状态。提交时仍由服务端原子重验，预览不是消费授权。

源码指引（本次读自 main 041fe3f）：

- `packages/shared/src/base.ts` 的 `BaseResourceDto` 只有 itemId/name/quantity/description，没有可用/占用字段。
- `apps/server/src/application/base/base-snapshot.ts` 委托 world-runtime 的 BaseService；沿 `BaseAssetPort.listBaseInventory` 和组合根追真实来源。
- `apps/server/src/modules/industry/manufacturing.service.ts` 使用 `reserveBaseInventoryIfAvailable`，失败返回 RESOURCE_INSUFFICIENT。不得绕过该检查让按钮“能成功”。

A06 最小验证样例（**拟定测试数据，不是线上还原值**）：

| 状态 | 玩家预览 | 提交/恢复 |
|---|---|---|
| 总8、占用8、可用0，需求3 | 明确缺3，能查占用去向 | 服务端拒绝，不扣资源 |
| 总8、占用2、可用6，需求3 | 满足条件 | 一次预留；重试不重复扣 |
| 可用0、在途3 | 尚缺3，显示到货条件 | 到货前不可消费；入库后更新 |
| 预览后另一操作占用材料 | 旧预览可能过期 | 提交返回具体缺口，刷新现场状态 |
| 取消或完成有效任务 | 按真实合同更新占用 | 取消释放、完成消耗，各仅一次 |

覆盖建设/制造/订单中确实共用该事实的路径，含基地隔离。不要为本包增加新交易规则。UI 的材料展示归 M；BaseShell/BaseApp/base.css 集成交 U 单一写者，或排在 U 后串行。

风险与回退：最高风险是重复扣减或口径混淆。优先兼容性扩展；无证据不迁移资产。回退展示不能撤销已发生的正常消费。

## T：引导与终态操作（F06、F07；C05待调查后接入）

- 引导按实际可达功能写：首工程前已有的订单/制造不写成奖励解锁；初始已有发电能力，首工程增加容量。不要擅自加前置锁使旧文案成立。
- 已完成或已取消工单不提供“取消”；保留完成结果、产出和可追溯记录。处理中防重复提交；服务端终态拒绝继续保留。
- 功率文案先核对 generationWPeak/availableW/loadW/storageWh 的真实口径，再解释峰值、当前供电和储能，不把夜间数值误当结算bug。
- 长邮箱与计时按钮布局归 U；不要用删除账号辨识绕开问题。

预计文件：`BaseIntroModal.tsx`、`ManufacturingBoard.tsx` 及相关测试；执行前核实路径。终态测试分别覆盖 completed/cancelled 与仍可取消的有效状态，断言能力和请求行为，不只快照文字。

## E：节奏、成长与后续目标调查（C01—C06、C09、C10，V02/V03）

本包先交调查结论；涉及物流时长、离线推进、机器人收益、灾害强度等规则，须形成具体设计提案，不能直接实施。

| 调查 | 对照与记录 | 决策出口 |
|---|---|---|
| 物流时间墙 C01 | 登记主动会话窗口；逐段记录下一目标、缺口、ETA、可做的不同决策和最长无新决策等待；至少尝试制造/订单替代路线 | 若等待超过窗口且替代路线耗尽，比较缩短早期物流、增加真实替代决策等最小方案；离线政策改变单列 |
| 机器人收益 C02 | 相同项目、资源、供电、起始时间条件，对比4/5台有效机组的进度/用时与成本；把实际玩家等待与隔离确定性规则测试分开 | 说明新增机器人改变什么瓶颈；无差异先定位调度条件，不先改数值 |
| 目标链 C03 | A先建、合法B先建；各自完成后从当前视口寻找下一目标并尝试行动 | 发现性问题交U；缺内容或奖励用途另提产品方案，不凭项目列表只有已完成项判死路 |
| 速率/功率 C04/C05 | 记录昼夜、负载、制造与储能变化；核对服务端速率和供电定义 | 只承诺可信信息；变速任务可说明条件，不编固定倒计时 |
| 延迟 C06 | 同一动作记录浏览器受理、网络返回、状态更新；分开前台/后台/工具超时 | 有可复现产品归因后再开修复卡 |
| 压力/维护 C09 | 在授权隔离档验证低电、充电队列、维修上限与恢复；尘暴及真实Jev按对应版本门槛 | 不把未覆盖当通过，也不为制造挑战随意加惩罚 |
| 采购预览 C10 | 实际尝试不同数量采购；记录操作前可知总价、余额与到货条件 | 若存在理解成本，加本地确定性总价预览即可，不增报价系统 |

每个实验交起始条件、变量、时间戳、动作与实际后果、反例、证据限制。至少三圈、跨日回访、真人和真实模型的门槛分别记账；未完成标 NOT_RUN。操纵时钟或固定 fixture 可以验证规则，不能替代真实等待体验。离开前后保留同一存档，不以新账号冒充回访。
