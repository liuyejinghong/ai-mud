# 跨版本领域合同

本合同是批准方向的实施约束，不是当前API或已存在数据库表。具体导出签名、路径、单位精度与迁移由A0及各P包冻结；图/类型不能替代真实PG证据。

## 1. 唯一写归属

| 事实 | 唯一所有者 | 其他模块如何使用 |
|---|---|---|
| 账号/会话 | identity | transport建立可信principal；不接受客户端自报权限 |
| 基地标识、成员授权、空间/建设位、simTime/epoch、天气事实 | world的基地子域 | 公开scope/空间/时钟/环境接口；与character分离 |
| 设施实例/状态、建设/制造工单、步骤、依赖、进度和工位 | industry | 公共命令/查询；Harness是这里的执行协调能力，不另造第二套状态机 |
| 站内电源出力、公共储能、负载分配和能量结算 | industry能源子域 | 纯规则求计划，公开写入口提交；weather不能直接扣电 |
| 物料数量、所有权、货物预留、资金余额、设备资产及资产账本 | assets | 同事务公开能力；内容/模型/前端不直写 |
| 机器人实例的运行身份、载体状态、电量、位置、当前执行分配与可信经历 | npc作业者子域 | 公开参与接口；电量只有npc写，industry供电经用例调用它 |
| 内容草稿、修订、发布快照和激活记录 | content-catalog | 运行时只读已发布定义；pure rules不查DB |
| 订单价格/预算/交易条款及经济结算语义 | economy，长义务生命周期可复用quests | 通过命名用例协调assets/industry，不创建第二钱包 |
| 非权威选择、表达和模型调用审计 | ai | DecisionProvider/NarrativeProvider；没有世界写权限 |
| 已提交快照、项目板/设备todo与显示文本 | observation/client_session | 多视图同一事实；仅展示与发送意图 |

设备资产与机器人作业者以明确ID一对一关联：assets写所有权，npc写运行状态。制造完成不得各自生成一个互不关联的ID。物理拆除、资产处置和作业停用在同一用例中完成。

各模块只经登记public API使用其他能力；跨模块原子事务通过composition绑定的UoW参与接口，不向用例开放裸SQL。platform不反向import业务类型。新增目录/依赖边需按PC-16独立确认，无全仓白名单。

## 2. 五类基础标识与版本

- BaseId：权威数据作用域，不从客户端字符串直接推定权限。
- InstanceId：某台机器人/设施/工单的唯一实体；不可复用已退役身份。
- DefinitionRef：kind + stableId + revision；批量内容由contentReleaseId固定，改显示名不改稳定ID。
- CommandId：绑定principal/baseId/epoch/operation/requestHash；同key同payload重试返回同结果，不同payload冲突。
- DecisionId / PlanRevision：一次模型提案与当前执行计划的关联；只按相关前提判断过期，不因不相关UI事件让所有结果永久失效。

DTO使用运行时可验证的字符串ID而非把每件内容编译成联合字面量；类型/能力kind仍受程序注册表约束。内容发布版本、程序兼容版本、实例修订与传输cursor不可混用。

## 3. 内容目录与实例创建

`ContentCatalogPort`示意能力：读取某release的定义、验证DefinitionRef、列出可见/可制造内容。模块只能收到自己的投影；隐藏规则/管理员字段/模型密钥不发浏览器。

v0.12内置不可变数据快照经同一port加载；v0.13后台发布存储接到同一port。编辑方式可为表单或导入，运行依据只能是已发布快照，不按Git/DB最后修改时间竞争。

RobotTemplate：展示、支持的能力、运行参数、默认受控决策配置。Recipe：输入/输出、设施能力、工作量/能源要求、取消政策。两者分开，参数必须有单位和边界；不让型号决定玩家出生资产或执行SQL。

工单记录开工的recipe/template revisions；新发布不改在途成本和已存实例物理参数。实例升级是明确命令。不存在的旧修订不能静默fallback到latest。

`RobotFactoryPort`只供已校验的制造/初始化/管理用例调用。注册作业者前提供已创建的设备资产ID、模板ref、基地/位置与source operation。首次初始化有唯一setup receipt；重启不因少一台而补发。

每个制造产出使用 `(jobId, outputOrdinal)` 唯一标识。资源扣减、成品资产、作业者初始化、工单产出记录、必要事实/回执在同一短事务中提交；重试不能多发。批量数和每次交付工作量有上限。

## 4. 项目、步骤与todo

项目生命周期：planned → active ↔ paused/blocked/needs_decision → completed；cancelled/failed为明确终态。步骤初始pending，依赖满足变ready，获得设备/资源变running，验收后completed；失败可进入blocked或显式failed，不允许无限自动重试。

Step包含前置步骤、kind/handler版本、目标、所需能力、材料/工位声明、分配设备、已完成工作量、完成条件与阻塞reasonCode。未知kind拒绝加载。每个图节点数/并行数/协作轮数有界；不能把任意JSON当可执行程序。

项目板与每台机器todo均从同一Plan/Step/Assignment生成。展示进度不是权威；自然语言“完成了”不能勾选。清场/运输/安装/验收有真实世界效果，验收写入后才显示完成。

一台设备的互斥时段只能有一个有效分配；分组是观察/调度抽象，不把组资源复制到每台机器。预留不等于消耗，缺料、缺电、缺执行者不能只凭endsAt完工。中途事件按明确边界分段结算，不能假定整个dt持续满负载。

取消只释放未消耗预留；已消耗材料按已发布配方的回收政策处理，已交付产物保留。运输起点、途中货物、终点仓库任一时刻只能有一份实物；预留/搬运/交付各有幂等键。

## 5. 模拟时钟与资源算术

UTC墙钟用于会话、安全、审计、API预算；simTime用于基地供能、作业、天气、订单与物流。暂停、倍速、resume均是授权服务端命令，只影响该基地。浏览器帧率和轮询不是时钟源。

v0.12默认断开控制会话后暂停：P包冻结心跳租期、到期暂停点、多个标签页的统一控制和异常关页行为；按服务端已授予的控制有效期结算，不依赖unload。重启恢复暂停状态，不把停服时间当生产时间。v0.15才加入用户显式选择的有界离线运行，默认仍可暂停。

一个基地tick先锁本基地runtime，重读进度，按统一锁序处理参与根；状态/资源/进度原子提交。不同基地可独立处理，但不由此承诺未测多副本容量。补算步数/墙钟时长有上限，不能在持锁期间调用网络模型。

材料计量、账款和能量使用冻结精度的整数/定点及舍入规则；功率与能量单位分开。每段平衡必须解释发电、可用供电、充放电效率、弃电、负载削减及储能变化；电量到零后的未满足负载不能被clamp静默当完成。电池扩容不生成电；出厂测试/初始充电由制造或场景来源支付。

物理能源与采购额度分别记账；账户有钱不代表电池有电。订单/天气全部按同一基地simTime，独立快进基地不接共享实时经济。

## 6. 事务、并发与幂等

外层命名用例：授权→领取/检查receipt→发现对象并固定锁计划→重读与结算必要到期状态→模块规则→公开参与接口写事实→receipt→commit。发现新的未锁根回滚后有界重建，不反序追加锁。

失败注入至少覆盖：预留/消耗后、产出资产后、作业者登记后、工单终态前、receipt前。所有必要状态一起回滚。账户创建与基地初始化可分为可恢复流程：账号已成功但基地失败时用唯一provisioning操作重试，不要求再次注册、不重复初始物资。

支持的错误至少区分：权限、过期scope/revision、内容不兼容、资源不足、设备/工位占用、前置未满足、预算/超时、幂等冲突。玩家看到安全可理解原因；不能泄漏其他基地/供应商密钥。

## 7. DecisionProvider与调用政策

输入：purpose、decisionId、baseId/epoch、相关实体revision、planRevision、content/recipe版本、受控观测、玩家政策、有限候选、墙钟deadline。输出：选中candidateId或abstain、来源/模型版本、可用的概率信息/usage和审计标识。它不是任何供应商SDK的照抄接口。

代码确定工程步骤、精确数量、供能保护、前置和完成条件；Jev参与合规方案/协作回应/有语义歧义的判断。已知引擎事实不转成文字再付费猜测。每台机器独立状态，共用模型服务，不维持每机常驻会话。

模型返回是提案；重验资源和版本后才承接/调整。协作消息使用requestId、inReplyTo、expiry、round和结构化需求；反提案有上限/终止条件。互相“同意”不代表设备/材料已被占用成功。

同一事件去重、唯一候选直接规则、空候选显式阻塞、普通施工不调用；应用总deadline覆盖SDK所有重试/排队时间，单一重试策略；预算按账号/基地/purpose与全局双层限额。预算耗尽采用安全规则/待决定，不自动升级昂贵大模型。

主程序不中断等待文本；模板默认表达已确认事实。必要记忆保留source eventId、type、对象、数量、时间与证据等级，摘要不能决定分数/授权。首期不实现正典实链制度。

## 8. 观察、注册与UI

一个ClientSession处理命令结果和轮询快照。BaseSnapshot带baseId、epoch、baseRevision、simTime、activeContentRelease、相应领域修订和可见内容；cursor只是通知进度。快照在明确隔离边界读取，断线/过期cursor回全量；低revision或旧epoch响应不覆盖新事实。

所有核心动作有鼠标入口；点击目标→预览消耗/占用→执行→原处反馈。输入态不触发快捷键；可见按钮与Tab/Enter仍有效。右键/拖拽不是唯一入口。危险取消/拆除说明后果；普通选择/暂停不堆叠确认弹窗。

测试注册模式无邀请码/验证/强密码门槛，保留非空与长度上限、哈希、会话、CSRF和权限。server显式识别部署模式，正式模式不能因NODE_ENV误配无声开放；管理员内容权限不随开放注册下放。自动登录失败可正常重登，provision失败可恢复。默认不因注册开放付费模型无限预算。

## 9. 内容发布与退役

草稿可修改；发布修订不可变，整包校验唯一ID/引用/单位/能力/schema版本/流程可达性/限额。内容发布不创建玩家资产；引擎不支持新效果时拒绝发布而非执行任意脚本。

激活在基地明确结算边界完成；一个命令/补算段固定快照，在途工单仍引用旧修订。客户端同步新release后再显示对应选项，不把旧报价当可提交事实。发布、激活、回退均审计。

停用只禁止新创建，旧实例/工单/账本仍可解释。内容回退不撤销玩家已经获得的产物；破坏性修订必须有迁移或拒绝规则。增删游戏机制经代码/测试/ADR，不承诺所有变更无需程序发版。
