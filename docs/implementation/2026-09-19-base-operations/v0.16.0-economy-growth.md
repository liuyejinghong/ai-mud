# v0.16.0：产业经营与长期发展

状态：PLAN_APPROVED / NOT_IMPLEMENTED。前置：M12—M15工程基线；模型模式明确。目标：投入→生产→交付→收入→再投资，资源不只堆库存，发展不只放大同一数字。

## 1. 产品spec

外部订单数量有限、买方/需求/预算/期限/验收明确。订单可以是物资或已支持的维护服务，不因AI叙事自动发钱。自有清场/搬运/建设只是内部作业，不从系统领取奖励。

玩家在自用建设、留备件、接单盈利之间选择。订单不总要求最高产量，支持可靠交付、节能和设备维护等合理路线，但不先实现巨大科技树。

采购分为报价/下单/到货/入库：近处已有补给节点或着陆区物资可以运输，远程补给为明确抽象；付款不等于物料已在本基地。所有节点在本版独立基地同一simTime内结算，不建立跨玩家实时市场。

站内计价先一种同质账款单位，与kW/kWh分开。没有明确兑现节点和条件时不称物理电力；初始预算、系统援助、订单资金都有来源。故事债务/能源期货不进入第一经营循环。

## 3. 交易与物流合同

接受订单前确认权限、需求剩余、买方可支配预算和玩家义务；承诺/托管与订单状态同事务，不能重复卖同一份已预留物料。服务型交付使用规则验证的完工事实，不读机器人汇报文本。

报价固定有效范围：baseId、内容/经济revision、方向、数量、费用、到期/前提；过期要重报并让用户确认变化，不静默改变支付。数量/单位保留原始意图，超限明确拒绝，不能把“100”截成“2”再自动成交。

转移金钱、货物、订单终态、可信交付和receipt在同一事务。货物装载、运输和卸载每阶段只有一份物料；途中毁损/返回按明确状态与恢复政策，不能同时在两个仓库可用。采购取消不吞掉托管款，也不把已发货物资再全额生成。

买方需求/资金不会每次刷新重新补满。公共/外部需求刷新按明确simTime和有限规则，从何处补预算需要标记来源。玩家不能靠暂停/快进在不同计时系统之间套利。

## 4. 经济正确性与可玩性

继承“无外部变化往返不获利”的验收，不继承旧市场具体不合理公式。若采用库存曲线，批量报价和反向边界必须一致，检查拆单、税费/舍入、最大数量、并发库存变化；旧报价函数是否可复用由测试决定。

基础生存/维护与额外经营开支区分；保底恢复资源有限、来源可见，不能循环申请援助刷利润。亏损可以降低扩张速度但不默认使新手永久卡死。初期不把数据许可/人格产权变成可出售的普通道具。

发展路线至少提供可解释的差异：生产规模、能源/储备可靠性、运输/维护效率。目标奖励必须给明确机会或实际资源，不能为进度条凭空发行资产。若一种策略严格统治全部场景，记录并调整参数，不用随机惩罚强行“平衡”。

## 5. 实施顺序

P先固定单基地时间/账户与外部买方模型。A先单笔报价/预算/无套利性质，再订单；B先单段运输/货物归属，再采购；D先所有状态及失败交互，再接真实接口。C在能力合同内编辑数据并整包校验发布。

Q先跑交易重复/故障，再压力订单/恶意拆单、资源囤积/生产中断和无援助循环；最后用相同天气/初始配置比较几条策略。DuckDB可读取隔离导出作分析，不作为本版线上新依赖。

## 6. 验收

| ID | 场景 | 必须结果 |
|---|---|---|
| M16-G01 | 投入到再投资 | 生产消耗→有限订单交付→真实收入→再建设完整E2E |
| M16-G02 | 重复接单/交付/付款 | 只有一份义务和一次资产效果；真PG |
| M16-G03 | 买方预算不足/需求耗尽 | 明确拒绝或合法部分方案，不凭空补钱包 |
| M16-G04 | 往返/拆单/舍入/并发 | 无外部变化不能稳定正收益套利；价格和账本分别验证 |
| M16-G05 | 采购运输中断 | 付款不等于到货，货物不重复，取消/恢复符合合同 |
| M16-G06 | 内容修订与原请求 | 旧工单稳定，新报价按新规则；数量/单位不被静默截断 |
| M16-G07 | 经营策略/恢复 | 至少两条合理路线且能解释代价；失误有有限恢复而非无限刷援助 |
| M16-G08 | scope与时间 | 私有快进不写共享实时市场；别的账号无法获得订单/货物 |

## 7. 非目标与回退

没有PvP市场、期货/借贷金融、大型科技树、跨星球即时送货、无限收购或全自动最优经营AI。

关闭新订单/采购后仍要完成/取消在途义务、退还未使用托管和处理货物。回退保留内容/经济修订及订单历史；不能只删UI和订单表。必须报告已有余额/库存核对结果和备份恢复方式。
