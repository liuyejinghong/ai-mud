# v0.13.0：内容工坊与机器人制造

状态：PLAN_APPROVED / NOT_IMPLEMENTED。前置：v0.12真实目录/实例/建设/能源基线。目标：新增支持的型号无需改业务代码；玩家投入真实材料，批量制造独立设备。

## 1. 产品spec

后台维护资源/物品、机器人、设施、配方、受支持作业模板、初始场景。最小界面为列表、复制草稿、表单、校验错误、预览、差异、发布和停用；不是通用可视化编程平台。

新增型号≠给玩家新设备；发布内容≠发放资产。模板定义能力，recipe定义制造过程，实例记录当前状态。初期标准作业机器人可批量制造，不引入小说连续体复制与身份制度。

玩家建立批量工单，预留材料、排入装配设施，按实际电力和工作量推进；每台验收后即可投入工作，不等整批。一条批准的短生产链支持必要零件，不模拟全套先进制造。专用模块来源仍明确为运抵/采购/已有库存。

## 3. 发布数据合同

Draft可变，Release不可变。稳定ID不能重用；每条定义有kind/revision，release有内容hash、engine/schema兼容要求、依赖清单和审计。一组互相引用的内容整体校验后发布，失败不产生半发布状态。

校验：ID唯一、单位/精度、数值范围、资源引用、能力/handler已实现、设备与recipe匹配、步骤DAG有界、原料和解锁途径可达。循环/回收不是一律禁止，但可能增殖的配方必须做守恒/价格/受限来源场景验证。只有JSON合法不算平衡通过。

未知效果/行为拒绝发布；后台没有JS/SQL/任意模型工具执行。文本仅用于表现，不能加一句说明就改变效果。secret与服务端隐藏数据不进入公开目录DTO。

每个基地在显式结算边界切换release；进行中工单持有旧recipe/templateRef，完成前保留依赖修订。客户端同步release后更新可见选项，不混用不同版本报价/成本。后台发布不自动批量修改已有机器人属性。

## 4. 制造与实例合同

工单状态复用industry步骤；准备材料按assets预留，分阶段消耗；缺料/电/工位/设备暂停。最大批量、队列长度、每tick最大产出由P冻结，不通过一次巨大事务生成任意万台。

逐台产出原子事务：验证实际完工→确认本份材料/能耗→登记设备资产→由已关联ID创建机器人运行实例→记录(jobId,ordinal)→更新工单/事实/receipt。任一步异常全部回滚；重复完成同一ordinal返回既有实例。

出厂电量/工具来自明确工单输入与试车供电，不从模板自动生成免费物资。未完成的材料取消后按已批准损耗政策退还；已经完成的机器人保留；退役不能靠cascade吞掉正在承担的任务/货物。

机器人实例固定templateRevision、独立battery/condition/position/assignment；新机器人可接现有运输任务。factory不直接调用Jev，多个实例不共享可变memory/todo。

## 5. 实施顺序

P复查v0.12Catalog/Factory是否真的被运行入口使用，先消除只包一层而内部继续读静态FIRST列表的旁路。必要迁移列明旧ID与新ref，不批量改已发布SQL。

A先版本/引用负例，后draft CRUD、整体publish、按base激活和停用。B先表单/预览样例，后真实权限与错误定位；导入和表单走同API。

C先单件进度/暂停，再多件ordinal与取消；D先重复创建/资产关联/初始状态，再设备UI；短生产链由P指定内容单写者，不能C/D各发配方。

Q用当前引擎支持的能力新增一种测试运输型号，无新增业务分支，完整制造/承接/更新内容回归。测试内容不自动进正式内容包。

## 7. 非目标与回退

不实现所有新机制无代码、不做模板多层继承、不做脚本沙箱/任意插件。内容底层可复用Postgres，无新增权威库；Git导入/后台编辑只汇入一个发布事实源。

出错先关闭发布/新制造入口，保留已锁定修订和在途工单；不删模板/actor目录解决引用。发布rollback只切可用版本，不回滚游戏事实。实例/schema不兼容时用维护模式、备份和匹配程序恢复。
