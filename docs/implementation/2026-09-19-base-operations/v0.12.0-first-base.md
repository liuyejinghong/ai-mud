# v0.12.0：接管第一座基地

状态：PLAN_APPROVED / NOT_IMPLEMENTED。前置：A0通过，用户指定本版实施。目标：简单注册→鼠标进入基地→指挥已有工程队完成一项真实建设。不是无行为的UI样机。

## 1. 产品spec

开发试玩无需激活码/邮箱验证/强密码；注册后自动登录，不选职业。自动配置一个独立基地，约12台三组工程设备为待平衡初值。已有供能、储能、仓储、维护基础与待部署组件，首次目标是安装运来的太阳能设施而非从矿石制造先进设备。

主界面四区：顶部电/物资/设备摘要，中央可点击建设位，右侧选中对象操作，底部项目与重要提醒。点击建造→位置→成本/占用预览→确认→真实计划执行。地图与todo可互相定位；常规日志折叠。全部核心操作鼠标可达，快捷键不抢输入。

初次项目具备清场/运输/安装/验收步骤，按前置和实际工作量推进；依赖阻塞、供电不足、设备冲突清楚显示。基础发电/储能/设备充电现在就有；高级天气/维护风险在M15，不得把无电施工当临时实现。

先规则调度和模板表达。DecisionProvider、RobotFactory、ContentCatalog建立当前调用所需小接口，复用现有能力，不创建无消费者的空框架。

## 3. 实施顺序

P：走读auth注册返回、现有资产/实例/世界runtime/观察；确认哪些接口已经实现，缺口写最小适配，不照旧ARCH全文重做。新增功能范围与旧世界可共存但默认游戏路由必须明确，只读旧档不能影响新基地。

A：先权限/重复注册/初始化失败测试；实现试玩注册策略、自动会话、base provisioning。账户存在但基地未完成时幂等继续；一账号初始基地唯一；空密码/超长输入仍拒绝。开发模式不得给内容管理员权限，不替所有人共用一个账号。

B：先规则fixture和同事务失败测试；支持初始模板实例，再做一步作业→依赖→多设备分配→能源不足暂停→完成验收。不按Date.now在每次读取时随机加进度。

C：先共同fixture驱动点击流程；组件发命令不改权威库存；pending/accepted/running/blocked/completed清楚；接真实session后重测乱序/重连。原因与处理按钮在对象所在位置展示，不要求读小说或日志。

D：把模板、recipe、初始manifest做成数据；验证引用、起始资产来源、能力匹配及自举。运营新增数据以后走同CatalogPort，不能在业务中switch每个具体itemId。

I：绑定同一个UoW、单一base tick/观察和所有权；开局seed只对new base执行一次，失去设备不自动补发；旧NPC timer不对新数据额外发工资/扣食物。

## 4. 状态/数据/时间

新增具体表名和迁移号由P冻结。BaseId不复用角色ID；初始库存写assets、机器人运行状态写npc、项目/能源写industry、scope与simTime写world。每笔资源与实例都有source operation。

离线默认暂停；心跳失效在服务端控制有效期边界暂停，多标签页不能重复推进。倍速通过命令设定，按同一个simTime结算所有系统，不让前端决定已过时间；基础支持1x及受限加速即可，不追求任意倍率。

模板/文本服务关闭不影响核心作业。AI接口测试替身返回受限候选，禁止在工单事务里等待网络。UI中展示的所有数字来自实际值或明确标记的预测。

## 6. 非目标与回退

不做内容编辑UI、量产、真实模型必须在线、完整天气/市场、像素引擎。不把旧职业/打怪/饥饿映射给机器人。

回退先停止新基地写入/模拟并保留快照，再回到兼容程序或只读维护页；不把新基地塞回旧CharacterDto。迁移若非可逆，恢复备份与配套程序版本；没有生产重置授权。退出旧路径时逐项标记旧测试保留/替换/退役理由。
