# R1 固定工作区与模块交互合同

面向当前玩家。使用 React/CSS 和现有状态管理；保留键盘访问、文本状态和可见焦点。图形样稿须用 HTML/CSS 形成可操作样例，不把静态美术图当功能验收。

## 1. 桌面布局与视口

1280×800、1440×900 为桌面主验收视口。页面为 100dvh 的固定外壳：根容器不随长列表增长，区域用 minmax(0,1fr)/min-height:0 和局部滚动承接。此为布局约束，不能靠裁切隐藏按钮。

    顶栏 56：基地名 | 实际发电/负载/储电 | 时间/暂停/倍率 | 设置
    目标 64：现在要做什么、为什么 | 一个主行动 | 打开完整任务清单
    主区：基地地图/场景（自适应） | 所选对象/操作面板（360–420px）
    队列 96–128：正在施工、运输、加工的紧凑卡与最近结果

右侧只承载当前对象的一个动作上下文；库存、加工配方、生产概览可切换成该侧面板，地图与选中对象继续存在。模态窗口仅用于高影响确认或设置，不把普通选择连套三层。页面最多一个主要局部纵向滚动容器，历史单独打开。

1024×768 缩小侧栏和队列但仍保留主要动作。800px 以下及真实 200% 浏览器缩放使用“场景/操作”切换视图：状态和目标常驻，关闭操作返回原对象，列表可局部滚动。不要通过缩小全部字体假装一屏放下所有内容。

## 2. 模块职责与权威来源

| 模块 | 玩家要作的决定 | 权威事实/写入口 | 必须呈现的结果 |
| --- | --- | --- | --- |
| 地图与选址 | 在哪里安装、采哪处矿 | snapshot.sites/resourceNodes；创建工程/勘探/采矿命令 | 货箱、空地、施工、已运行、矿点未知/可采/耗尽形态明确 |
| 当前任务 | 此刻下一步和原因 | 已完成设施/物料产出事实派生；无资产写权限 | 一个可行行动、阻塞原因、跳过讲解与回看 |
| 仓库/货物 | 还缺什么、哪里获得 | assets 库存/预留，industry 在场/在途读面 | 可用数为主，预留来源与在途 ETA 点开看 |
| 建造操作 | 成本和回报是否值得 | 当前内容配方 + 服务端条件预览；createProject | 成本减少、工程出现、设备投入、完成能力增量 |
| 采集操作 | 节点/批数/人员分配 | world 节点、npc 实际设备、industry 作业 | 可采剩余、采出未送达、已送仓、所占设备 |
| 加工操作 | 做什么、做几批、先后顺序 | recipes/jobs/slot capability；制造、暂停、取消、维护 | 输入→输出、预计范围、槽位状态、成功与恢复 |
| 生产概览 | 资源/电力/设备投向哪里 | 同一 snapshot，不再自建余额 | 当前吞吐、瓶颈、下一扩建收益；新档无卖系统按钮 |
| 协作与事件 | 是否接受真实支援、发生过什么 | 原合作端口与已提交事实 | 缺工原因、候选/代价/去向；可行动时就地出现 |

## 3. 三张截图的逐项替代

### 建造：成本表与可恢复行动

对象卡标题“安装太阳能”；次行“完成后：峰值发电 +4 kW”；成本用最多四列“材料 / 本次需要 / 仓库可用 / 还缺”。详情才显示工程预留和在途，不能一行重复六个数字。

缺料时主按钮变为“准备材料”，旁边明确仍缺项；点它打开可执行的材料来源列表，保留目标工程和位置。已在途的材料显示“等待这批到货”，不建议重复采购/生产。若现有库存不足但在途足够，开工仍不能提交。

物料来源统一由目录 recipe/provision/node 的实际关系生成，不维护另一份前端硬编码说明。“支架缺 4 → 加工结构件 → 缺铁料 8 → 冶炼 → 铁矿采集”逐层可返回原目标，每层只显示当前一步。若没有来源，明确“当前版本无获取方式”，作为验收失败，不伪造按钮。

服务端仍重验不足/状态变化；失败后刷新事实并保留填写数量，在相同卡片显示原因与下一步，绝不只返回大红横幅。成功显示“消耗/预留什么、谁开始做、在哪里看进度”，完成显示“本次增加什么能力”。

### 仓库：普通语言与必要细节

顶栏只显示电力和当前目标关键材料，不把全部物品变成长串 chip。打开仓库后可按货箱、原矿、材料、设备部件分类；默认显示“线缆 2 可用”。有预留时可展开“仓库 8，工程 A 已占用 6，可用 2”；在途独立列出，不能算可用。

角色权限、资产归属与工程预留不是同一个概念。UI 不出现裸 UUID、可支配、ordinal、schema、workPerTick 等内部词；合法单位用件、批、分钟、W/Wh 或适当 kW/kWh。

### 制造：先看用途和产出，再安排作业

从加工间进入同一侧面板，配方用紧凑选择列表；选中后固定显示“2 铁矿 → 1 铁料 / 约 1 基地分钟（足额供电）/ 2 kW”。数量改变后同步显示整单输入、预计产量和库存变化。用电不足提示估计条件，不能精确倒计时保证完成。

无工单时显示一个建议配方及原因，队列折叠为空态提示，不保留空白半屏。队列每张卡显示产出 n/m、当前批状态/进度、正在使用的槽位、原因；取消显示实际退料，暂停不释放已投入材料。

## 4. 教学与反馈状态

每步只教一个新规则：目标 → 明确操作位置 → 玩家实际动作 → 同屏结果 → 下一步。讲解可关闭，进度由服务端真实事实派生。开始前展示随船货单，地图显示待安装设施；不能再用一段“基地已就位”替代安装教程。

第一次缺料给来源入口；第一次暂停/倍率调整给时间政策说明；第一次采矿给“未送达不算库存”；第一次维护解释消耗和恢复。用户已完成后续动作时自动跳过相应说明，不重新要求重复生产。

所有操作覆盖：首次加载骨架、无选择、无结果、可行动、已受理、执行中、低电/缺料/待维护/无人可用、完成、取消、会话过期、断网/状态陈旧。网络过期时停止启用写按钮并提供重连；不显示假库存 0。没有设备候选显示具体冲突任务，不发一个注定失败的请求。

工程/采矿/制造结果至少保留当前与最近记录：使用已提交工单与产出记录投影，刷新后仍可查看。R1 不建第二套独立事件事实库，也不把只有内存 toast 当成历史。

## 5. UI 验收

- 正常桌面根页面 scrollHeight 不大于 clientHeight + 1；主动作和缺料恢复按钮的包围框在当前可见操作区内。不得用 overflow:hidden 把不可达内容藏掉来过门槛。
- 完成“选址→发现缺料→定位来源→开始生产→返回该工程”后，对象、数量和阅读上下文保留。
- 在制造空态、20 条工单、12 台设备、所有材料都缺这四组状态验证布局；首屏一张截图不代表全部合格。
- 纯键盘走首设施安装；打开/关闭面板焦点回原触发点。提示不只靠颜色，暂停/完成有文字，文字能选中和复制。
- 真实 200% 浏览器缩放与 720×450 分别验；CSS zoom 不替代浏览器缩放。
- 视觉样稿接受后再接真实数据。样稿中的按钮、动画和数字必须标为演示，不得作为真实玩法证据。
