## 1. 必须兑现的产品结果

玩家带着设施组件、货物和约 12 台机器人落地，自己选择并安装设施，派机器人取得本地原料，再用加工得到的材料扩建基地。设施运抵与设施已运行必须是两种状态。桌面核心操作在固定工作区完成，遇到缺料时可就地找到来源并回到原任务。

R1 修完后应有 30–45 分钟的首轮教程和至少三轮可重复的本地生产/扩建决策。30–45 分钟是待实测的体验目标，不靠不可跳过等待或修改计时凑数，也不把这一个工作包叫作完整长期经营游戏。

## 4. 复核新增的实施约束

- 现有设施完工只调用 addGenerationWPeak；添加仓库/加工间名称不会自动得到功能。R1 必须实现明确设施效果与开工条件。
- 现有制造 output 固定机器人；产出表 device_id/operator_id 均非空。材料配方要同时扩展内容、运行时、产出记录和 UI，不能只改内容 JSON。
- 现有机器人每工作基地分钟耗 500 Wh，即单机等效 30 kW。该数值与开局 15 kW 总发电、依赖充电的教程不匹配。新规则按新内容版本配置功耗，旧版保留。
- 现有任务分配只有 currentProjectId/currentStepIndex。采矿不能把矿点 ID 塞进 projectId，也不能让同一机器人同时计入施工与采矿。
- 首次教程现由零散项目/订单事实拼六段，第二阵列刚有进度即判完成。R1 完成条件改为玩家确实用自产部件建成一次扩建，并能继续下一轮。

## 5. 一次选定的默认决策

- 保留鼠标操作、独立基地、服务端时间、前台运行/离开暂停和 1/2/4 倍速。
- 保留随船 12 台设备，机器人落地可用；固定设施均以安装套件入库，不额外做十二次唤醒点击。
- 第一批本地资源为铁矿、铜矿；产出铁料、铜料、结构件、线缆、备件。电子控制器和光伏片为明确的随船有限物资。
- 新档不显示 credits，不生成旧回购订单，不开放旧采购命令。旧档继续履行现有订单/采购，UI 显示“旧版外部补给”以说明范围。
- 沿用 React/CSS 与现有模块化单体；用清楚的地图对象、进度和因果反馈完成文字/示意图阶段。不开像素引擎迁移。
- 首次合作不再靠人为压低电量强迫发生；玩家先能直接调整人手和生产优先级。Jev/规则协作继续消费真实约束，不替玩家偷偷改计划。

## 6. 修复规模与边界

这是玩法内容、设施能力、结算和交互的联动修复，不能按 CSS 小修交付。旧时钟隔离、库存预留、幂等回执、内容修订、鉴权与数据保留继续复用。新增能力限资源节点、采矿作业、材料产出与设施效果；不加通用工作流、脚本平台、独立微服务、道路物理、复杂市场或新货币。
