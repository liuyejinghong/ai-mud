# 旧文字路线收尾合同

日期：2026-10-03。状态：**交接就绪；执行现场收尾待完成。**

依据：[本次转向入口](README.md)、[独立外部审查](../../reviews/base-operations/2026-10-03-external-playability-review/report.md)、[原 M1–M4 路线](../2026-10-01-playability-roadmap/README.md)。

## 1. 收尾的目标与非目标

收尾是让下一位 agent 明确：旧方案停在哪里、哪些事实可信、什么要带到新切片、什么已不再采用、哪些现有资产必须保护。

**不是先修完文字版，不是再做一个 v1.0.x 功能版本，不是宣布所有缺陷已解决，也不是删除旧代码和旧存档。**

默认只读核查与文档修改。既有线上玩法保留为运行基线；不新增旧路线功能。发现明确的数据丢失、隔离、结算或安全故障时，单列证据与最小修复建议，请所有者单独授权，不以“顺手修一下”扩大本批。不能用尚未证实的猜测无限阻塞文档收尾。

## 2. 状态语义

- `PROTECT`：跨版本继续维护的不变量；不是本轮重新测过的证明。
- `TRANSFER_TO_G1`：有效问题转入第一段 2D 可玩切片，尚未实现。
- `DEFER`：问题或机会保留，尚无实施批次，不自动继承旧版本号。
- `RETIRE_WITH_PLAN`：旧方案或验收承诺退役；不是底层问题已修复。
- `VERIFIED_FIXED`：只有能指向修复提交与相应验证，才允许使用。
- `UNKNOWN / NOT_RUN / NOT_ACCESSIBLE`：无法确认、未运行、不可访问，必须如实保留。

本合同中的建议处置已按本次产品转向给出；执行 agent 核查现场是否存在已落地的差异，并记录事实，不自行改产品方向。

## 3. 问题与方案处置矩阵

| 对象 | 处置 | 交接要求／完成判据 |
|---|---|---|
| 账本诚实、库存预留、原子结算、命令幂等、账号／基地隔离 | PROTECT | 记录现有实现与可运行的回归入口；保留证据局限，不用历史绿灯冒充本轮验证 |
| 时钟／租约、离开暂停、存档与重开隔离 | PROTECT | 记录服务端实际语义和回归入口；重开是破坏性操作，收尾不调用 |
| R1：反复手动续单 | TRANSFER_TO_G1 | 最小持续采集与加工安排、可暂停／取消、资源不足说明；不是搬入完整 M2 策略系统 |
| R2：目标被代答 | TRANSFER_TO_G1 | 玩家先定建设或生产目的；缺口计算、来源导航、返回上下文继续保留；推荐不是一律禁止 |
| R4：状态与成长不可感知 | TRANSFER_TO_G1 | 场景显示真实建设、任务、产出、阻塞和能力变化；不是再给旧页面堆面板 |
| R8：开场与机器人称呼 | TRANSFER_TO_G1 | 新开场与新规则一致；命名稳定映射到真实设备；不原样接回含旧经济、旧发电数字的弹窗 |
| R3：目标缺少意义 | TRANSFER_TO_G1（问题） | 以自产扩建与新的安排能力作为首轮回报；不能把“暂缓 credits”误记为不再需要成长目标 |
| 首单、credits、稀缺件采购与持续订单经济 | DEFER（方案） | 保留现有代码、旧档履约与防套利约束；重启前一起核定初始库存、用途、冷却、矿量与建设位 |
| R5：揭晓信息与内容深度 | DEFER；地名保留可随 G1 | 不以 120–280 储量和五次随机硬验收作为已批准要求；原问题仍开放 |
| R6：缺少可理解的压力与取舍 | DEFER（完整昼夜）；G1 保留资源机会成本 | 保留应急与恢复路径。G1 不要求新手必须受损，暂不重做整日周期 |
| R7：世界中的对方与 AI 共在 | DEFER | 固定、真实的任务回应与 LLM 调用是不同功能；不先接聊天或大模型 |
| 内部 ID、错误文案与状态名泄漏 | TRANSFER_TO_G1（被触及的玩家界面） | 在新切片触及处本地化；不借此重构所有历史页面 |
| 旧 M1a/M1b/M2/M3/M4 的顺序与版本号 | RETIRE_WITH_PLAN | 不再按旧顺序自动开工；保留历史文档、诊断编号和证据 |
| 15:00 开局且 ×2 约 90 秒日落 | RETIRE_WITH_PLAN + 文档纠错 | 当前公式下是 90 真实分钟，不是 90 秒；不为兑现旧承诺全局乘 60 |
| 离线暂停同时承诺离线“昨夜战报” | RETIRE_WITH_PLAN | 只允许报告实际发生的模拟；不补造离线事实 |
| 每条路线可无损过夜，同时每人必须受损 | RETIRE_WITH_PLAN | 风险存在、优秀部署有效、恢复可理解；不保留强制受损验收 |
| 直接打开旧开场门禁 | RETIRE_WITH_PLAN（具体做法） | 开场问题转入 G1，但旧文案不可原样复用 |
| 循环单称为“重放同一个幂等命令” | 文档澄清，TRANSFER_TO_G1 | 新派生批次须有稳定独立身份；重放同一命令只能返回既有结果，不得再次发资产 |
| “排队最久”直接命名为瓶颈 | 文档澄清，TRANSFER_TO_G1 | 区分等待、缺料、缺电和维护；未经验证不把排序当因果诊断 |
| “五次勘探必须出现意外” | RETIRE_WITH_PLAN | 将来用固定种子覆盖测试与真人体验分别验收，不能让随机概率决定 CI 通过 |

依据与算术解释保留在原审查中，不复制成另一套互相漂移的诊断报告。

## 4. 执行 agent 的四步工作

### A. 冻结现场，不改现场

记录 UTC 时间、仓库、当前分支、HEAD、origin/main、工作树状态、worktree 清单、PR #41 的 base/head/state，以及其他与旧路线相关的开放 PR／分支。必须区分源码版本、文档版本、已部署版本；无生产读取权限就将部署状态写为 NOT_ACCESSIBLE，不猜。

先保存或报告未提交工作，不 reset/clean/stash 他人改动。不要删除分支、关闭他人 PR、合并 PR 或重置数据库。与路线相关但归属不明的进行中工作，记录待所有者协调，不据旧授权自动继续实现。

### B. 核对文档路由，标出历史状态

读取 AGENTS.md、CLAUDE.md、相关 README 和实际 package.json。保留通用架构、唯一写者、权限、内容修订和生产纪律；只收口旧排期入口。

- 2026-10-01 路线总纲与 01–06 文档：在文件顶部标明“历史方案／不再默认实施，正文保留供对照”，链接回本目录。不要重写旧正文来掩盖历史错误。
- 2026-09-19 排期：只修正在役入口中仍把其未实施项目当自动后续计划的路由；已交付里程碑与领域合同保持历史与兼容效力。
- AGENTS.md 中“像素 DESIGN_ONLY”与新方向的关系：此刻仍未获引擎安装或实现授权；未来只有所有者确认框架并指定 G1 后，才为该批次放开，不一次性解除全部限制。
- 核查旧文档直接链接和相对路径；不要为了收尾删除测试、迁移、旧内容包或审计证据。

本 PR 已补充顶层路由与旧路线总纲说明；执行 agent 核对实际合并／分支状态后补齐其余入口，不重复覆盖他人更新。

### C. 核对保护资产与未完工作

制作可追踪清单：项目／模块、实现入口、已有测试入口、已有证据、当前可验证程度、是否影响 G1。

文档收尾不要求为了截图或健康报告访问生产、创建线上账号、运行付费模型或整轮漫长试玩。不要求全部旧测试重新跑一遍。需要验证时先确认测试是否读 .env 或连接数据库；不得连接未知数据库或执行迁移。无隔离环境就 NOT_RUN，不把环境不足伪装成游戏不通过。

若已有相关 CI 结果，只注明提交、工作流、时间和覆盖类型；历史 CI 不代表当前分支、新玩法或真人可玩性已通过。

### D. 提交收尾记录，不启动新游戏

建议新增本目录 `closeout-report.md`（执行者创建，不提前伪造完成报告），内容至少包括：

1. 精确基线与读取时间；工作树／开放工作状态。
2. 本矩阵逐项状态、证据或继承依据；不适用项的理由。
3. 被更新的路由与文档路径；没有动过哪些代码／数据／环境。
4. 实际执行的检查、结果、NOT_RUN 与局限。
5. 需要单独授权的真实运行阻断；没有证据的风险不得写成确认缺陷。
6. G1 接手时的资产与接口风险清单；新框架仍 PROPOSED 的状态。
7. 收尾结论：CLOSED_AS_PLAN 或 BLOCKED_WITH_EVIDENCE。前者只表示旧排期交接完成，不表示游戏好玩、旧缺陷清零或所有建议已实现。

用独立文档提交／PR 交回；若 PR #41 尚未合并且明确要求在它上面续作，先核对最新 HEAD，再顺序追加，不强推、不改写原审查。

## 5. 收尾验收

完成条件是：旧路线不再误导自动开工；每个有效问题有去向；可信资产与证据边界可追踪；存档和线上行为未被动过；G1 仍有清晰授权闸门。

不要求：旧 M1–M4 全实现、所有文案全润色、游戏已好玩、第一完整游戏日可玩、安装 Phaser、生成完整美术或部署一个“收尾版本”。
