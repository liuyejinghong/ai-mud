# 《余电》2D 游戏长期框架提案

日期：2026-10-03。版本：proposal-1。状态：**PROPOSED；产品核心目标已由所有者确认，以下具体技术／美术决策等待确认，不授权实施。**

证据口径：仓库事实以 `c6bd33e416adfe186fd1cd22013bbfbd22bc7cae` 为读取基线；官方技术资料于 2026-10-03 检查，见文末。设计选择、性能预算、试玩长度和规模均为提议，未做接入、性能或真人验证。不能把本文件的建议数字当实测承诺。

## 1. 产品锚点：建造并指挥自己的基地

所有者确认的体验：在荒地上建立自己的基地；机器人执行自己的安排；设施逐渐运转；决定在这个地方留下看得见的变化。

建议定位：**桌面浏览器优先、单人、可暂停的 2D 火星机器人基地建设与经营游戏。** 玩家是远程指挥员，不是一个需要亲自挖矿、走路、逐批盖章的角色。

主循环：想建设／改善一个东西 → 安排有限资源与机器人 → 系统持续执行 → 获得材料并建成 → 基地外观与能力一起改变 → 产生新的建设或优化目标。

第一层意义来自基地本身的成长，不强制先经过卖货赚钱；外部任务与经济以后扩展意义，不取代建设主循环。文字负责解释、世界细节与关键记录，场景负责对象、行动、空间关系和成长。MUD 不再是必须满足的品类清单。

立项首期不做：角色动作冒险、战斗塔防、无限工厂物流、多人市场、自由聊天、每机常驻 LLM、3D、大地图程序生成、原生移动端、离线挂机经济。

## 2. 冻结什么，允许调整什么

确认后形成框架级约定；“稳定”不是永不维护，而是不能由实施 agent 因个人偏好或一篇教程擅自改变。

| ID | 建议的框架级约定 | 改变时必须重新审查的原因 |
|---|---|---|
| F01 | 主体是基地建设与机器人调度，不是操作单个人物 | 核心操作、任务模型、镜头和内容组织不同 |
| F02 | 桌面浏览器优先；单人基地、在线权威存档 | 改为离线原生优先会改变模拟归属、存档、更新与发布方式 |
| F03 | TypeScript + Phaser 4；React 保留为 UI 壳 | 引擎／语言变更影响输入、渲染、工具链和资源接入 |
| F04 | 既有 Fastify/PostgreSQL 模块化单体继续作为权威底座 | 不重做账本，不复制规则，不增加微服务或第二权威数据库 |
| F05 | 规则、权威状态、场景投影、渲染彼此分离 | 服务端不 import Phaser；渲染帧和碰撞不发资产 |
| F06 | 正交方格逻辑；固定轻俯视画法，无镜头旋转；非等距菱形地图 | 投影、点击、排序、所有美术与布局资源都受影响 |
| F07 | 单层地表基地；初期固定合法建设位，后续扩为同一格坐标下的放置 | 不为以后可能的多层建筑／高度系统提前造基础设施 |
| F08 | 克制工业像素风；统一 32 像素美术基准格；清晰非像素中文 UI | 大批资源开始后改像素密度／视角代价高，先看小样再锁 |
| F09 | 服务器模拟时间决定进度；可暂停、倍速；离开不产离线收益 | 日长与批次时长可调，但必须版本化，不改真实守恒与时钟语义 |
| F10 | 生产与调度由确定性代码执行；AI 可选且只提案／表达 | 模型不决定资源、进度、权限或随机奖品 |
| F11 | 地图／美术与运行资产分离，内容与实例都用稳定业务 ID | 不把 Tiled GID、图片名或 Phaser 对象写成资产身份 |
| F12 | 一份玩法规则、多种临时观察入口；旧文字界面只做过渡／诊断 | 不长期维护文字版和图形版两套教程、平衡和产品路线 |

**可持续调整，不必每次重开框架：**配方耗时、成本、昼夜周期参数、界面布局细节、文案、色值微调、动画帧数、第一关大小、具体目标与内容顺序。影响旧档或协议的调整仍需兼容与版本纪律。

**实现前须在小范围接入中核定：**精确依赖版本、32px 样张可读性、DPR／缩放行为、视口基准、权威任务阶段可否支撑连续表现、必要的 DTO 增量和性能预算。通过后锁入 G1 合同；失败给证据和变更提案，不静默换路线。

## 3. 引擎选择：Phaser 4，而不是为“真正的游戏”更换整个项目

### 推荐技术栈

| 层 | 推荐 | 职责／边界 |
|---|---|---|
| 场景引擎 | Phaser 4，WebGL 主渲染路径 | 场景、相机、输入、精灵、动画、图层、基础声音；不持有权威经济 |
| UI 与应用壳 | 现有 React + CSS | 登录、设置、库存／配方详情、可访问性、键盘焦点、命令反馈 |
| 语言与构建 | TypeScript、现有 Vite/pnpm workspace | 不额外引入 GDScript/C#；不趁集成升级整个仓库依赖 |
| 权威模拟／API | 现有 TypeScript + Fastify 模块化单体 | 命令校验、内容版本、每基地时钟、作业结算、资源和状态写入 |
| 持久化 | 现有 PostgreSQL + Drizzle | 沿用事务、迁移、隔离与回据纪律 |
| 地图制作 | Tiled 正交地图，导出 JSON | 初期只用已验证的 tile/object 层和自定义业务 key；运行状态不写回地图源文件 |
| 像素资源 | Aseprite 为建议的编辑源；PNG 图集 + JSON 清单为交付格式 | 编辑器不是运行时依赖；使用合法可用工具，不强迫 CI 安装付费软件 |
| 验证 | 现有 Vitest/Playwright + 真 PG 的隔离测试 | 规则、适配、交互、像素画面和真人体验分层验收 |

仓库现有 React/Vite 与 Fastify/pg/Drizzle 依赖由实际 package.json 核对，见 [R1]、[R2]。Phaser 官方列有 React + Vite 的 TypeScript 模板，并提供场景、动画、相机、输入等能力，见 [W1]、[W2]。这些证明存在集成路径，不证明本仓库已成功集成。

### 版本策略

官方 release 页面在检查时将 **4.2.1（2026-07-09）** 标为 Latest，4.0.0 已于 2026-04-10 正式发布 [W3]。因此不默认从旧 Phaser 3 教程起步，也不写浮动 `latest`。

G1 接入首选候选为 **4.2.1 精确版本**；只有通过本仓库的 ESM、React 生命周期、相机缩放、图集、输入和 WebGL 恢复检查后才写入 lockfile。若执行时已有新补丁，提交对照理由再决定，不无条件升级。大版本升级走独立架构决策；补丁升级走有回归的独立依赖 PR。引擎选择稳定，不等于永远停在一个补丁版本。

### 为什么不是其他选项

| 方案 | 客观能力与限制 | 本项目判断（不是通用优劣排名） |
|---|---|---|
| Phaser 4 | JS/TS、浏览器游戏框架、官方 React/Vite 模板 [W1][W2] | 作为首选；直接贴合已确认的浏览器路线和现有语言／服务端资产 |
| Godot 4 | 可导出 Web，需 WebAssembly/WebGL 2；当前官方文档仍注明 Godot 4 C# 项目不能导出 Web [W4] | 不是做不到，而是要引入新的前端工程与桥接。若目标变为原生离线单机优先，值得重开比较；当前不为换引擎承担额外迁移 |
| PixiJS 8 | 2D 渲染引擎，已有场景图、输入与资源能力 [W5] | 也能实现；但本项目需要一套统一游戏场景工具，不优先自行拼装更多能力。不要误写成 Pixi 没有输入／场景 |
| 自研 Canvas 或把 React DOM 当完整场景引擎 | 可以实现定制表现 | 不把相机、精灵、图层和动画管理都变成自己的长期维护负担 |

不因 Phaser 适合当前而承诺“以后上任何平台都不必改”。本提案选择的是**联网浏览器游戏**，不是已具备断网单机。PWA 缓存或桌面套壳不会自动让 PostgreSQL 权威存档离线可用；原生离线模式需要单独方案，不提前开发第二套运行架构。

## 4. 权威模拟与画面的分工

### 4.1 单向数据流

玩家输入 → 类型化 GameClient 命令入口 → 现有鉴权／命令 API → 模块公共能力与事务结算 → 带版本的快照／事件 → SceneProjection → Phaser 场景与 React 面板。

这里的 GameClient、SceneProjection 是建议的薄适配层，不是已存在的接口。它们只组织具体基地能力，不做万能 service locator、通用脚本引擎或全量事件溯源重构。

- Phaser 场景不直接访问数据库或内部服务；服务端和共享规则不依赖 Phaser。
- React 和 Phaser 共用选择、控制权与命令状态的单一来源；不要各自发同一命令或各存一份可写库存。
- 本地 hover、选择框、建设预览可以立即响应；开工、扣料、入库、完工由服务端确认。
- 网络失败时显示未确认／只读状态，停止新的操作；显示最后同步点，不用动画掩盖断线。恢复后按版本重新对齐，不重放过期画面来暗示离线产出。
- 卸载场景、热更新、React 开发模式重复挂载必须清理监听与资源；输入不能穿透弹窗，中文输入和滚动不能被画布快捷键劫持。

### 4.2 三种时间，不能混成一个倍速

1. 墙钟与控制租约：决定哪些在线时段被服务器确认。
2. 基地模拟时间：决定工作、能源、维护、订单、天气；保留当前确认时段乘 speed 的规则，未来调整须单列。
3. 表现帧时间：决定镜头、选择反馈、动画插值；不决定库存和完工。

目标渲染可为 60fps，但不因此让数据库每秒写 60 次，也不把模拟改成“每帧减电”。现有整分钟结算、快照频率与未来图形体验之间可能有差距，必须在 G1 最小链路中实测；只提高轮询不会凭空产生更细的权威事实。

首期先复用 HTTPS 命令与快照，必要时为已授权场景补最小只读投影字段，明确字段写者、版本与顺序。只有实测表明更新延迟达不到所需表现，再考虑 SSE/WebSocket；不预先上实时联机／状态复制框架。

机器人移动应根据已确认任务阶段、进度、起止锚点和模拟时间表现。缺少细粒度事实时只显示当前已知工作状态，不无限循环伪造完成运输。可插值位置，但不得越过尚未确认的交付／完工边界。调速、暂停、失焦、重新接管后重新锚定；任何相位时间／进度预测字段都不是已批准 DTO。

### 4.3 存档与规则升级

旧档保持原内容／规则版本，不因新画面静默迁移。纯表现绑定通过布局版本把 siteId/nodeId/operatorId 映射到稳定场景锚点；业务身份不由图片序号或 Tiled GID 推导。

若新持续作业、空间位置或阶段投影需要持久字段，逐项确认归属、迁移、shared 协议与组合根唯一写者。不能沿用旧路线“只有 M3 会改 schema”的预测。

先采用可切换的新场景入口和隔离预览；切回旧入口不回滚或重放资产。收尾不删除旧档；正式迁移与旧 UI 退役另作有证据的批次。

## 5. 空间路线：先有地方，再让位置有经营意义

**长期采用正交方格与稳定世界坐标。** “轻俯视”是精灵画法，不引入菱形坐标、可旋转镜头或 3D 高度。

G1：单张小场景，地形与装饰静态，现有合法建设位真实落在场景；玩家选择设施、扩建位与先后次序。场景不应只是十二张卡片换成图标。建设需要过程、永久结果和可感知的能力变化。

G2 候选：在同一格坐标下放开有限建设区域，并加入**一个**真实空间关系，例如运输路径长度影响运输时间，或某设施的服务范围影响部署。不同时加入道路、拥堵、电网、管道、碰撞和地形高度。

空间成为规则后，放置合法性、占地、可达性与计价路径由服务端权威确认；客户端可以预览，不能自己决定运输完成。路径阻断要有恢复或禁止规则，测试地图版本变化和重开兼容。

G1 中示意路径只说明当前任务，不收取假距离成本，也不宣称靠近带来效率奖励。G2 若未获授权，就保持这个边界，不偷偷把 A* 或物理引擎引入结算。

地图素材不是权威内容：Tiled 文件可以带地形与业务 key；经构建校验／转换后进入版本化内容。不能加载客户端地图就直接在数据库创建资源或设施。

## 6. 时间、成长与难度路线

首批聚焦白昼内的部署—生产—扩建，不要求完整首夜。十到十五分钟体验一轮是**目标窗口**，不是让玩家必须跑完的测试时长，也不是当前数据承诺。

把无新信息的等待缩短，把真实决策保留；调配方时长时同步核算功率、能量、维护与机器人预算。不能只把画面和时钟提速而不核对生产守恒。

后续再引入公开的日落／尘暴预告、能源储备与优先级取舍。日长属于可迭代规则参数，而“规则时间决定收益、离开不补收益”是框架约定。当前太阳出力按 UTC 小时判断，短日周期并非现成开关；若采用，必须版本化修改时间、预测和结算合同。

失败首选可预见、可避免、可恢复的机会损失；应急电源与手工恢复继续存在。没有“优秀安排也必须受一次惩罚”的要求。

阶段成长应改变可安排的事情，不只增加相同数字。先达到“第一座会工作的基地”，再达到“可以优化布局与分工的基地”，最后才用新区域、能源事件和外部需求增加复杂度。不是首期承诺无限沙盒或完整战役。

## 7. 美术方向与可执行资源标准

### 7.1 风格：克制的工业像素，荒凉中有建设感

推荐正交轻俯视：能看见设施顶部和少量正面，有体积但不走等距透视。荒地使用低饱和赭红、岩灰；设施以浅灰／米白模块和深色机械部件形成轮廓；能源与运行提示用少量青蓝／暖黄。危险色只用于危险，同时配形状／文字，不能只靠红绿区分。

气质是可信、安静、可照料的先遣工程基地，不做满屏霓虹赛博朋克，不做拟真 3D 贴图缩小，也不做 Q 版农场或密集移动端按钮墙。具体色值先通过一张小场景样张验证，未验证前不批量生产。

昼夜、尘暴表现要跟真实状态走；不能因“夜景更好看”提早变黑。整体气氛和局部灯光不应盖住停机、资源和施工信息。

### 7.2 资源规范（建议在小样通过后冻结）

| 项目 | 建议标准 |
|---|---|
| 美术基准 | 32×32 源像素为一格；这是美术密度，不是屏幕 CSS 格，也不暗含一格多少米 |
| 机器人 | 基本轮廓约一格，四方向；驮运突出货斗，筑垒突出机械臂，望山突出桅杆／探头；不用颜色单独区分 |
| 设施 | 整数格占地；各设施 footprint、底部锚点、遮挡排序、操作热区明确，具体大小按内容定 |
| 状态 | 场地／预览、施工、建成、工作、缺电／维护；只实现机制实际存在的状态，不为凑美术增加新规则 |
| 动画 | 起步可用少量帧：移动 4–6、工作 2–4；8–12fps 的美术播放可先试，镜头和输入独立；均属可调值 |
| 缩放 | 最近邻采样，离散缩放档与像素对齐；验证 DPR 1/2 与浏览器缩放，避免对整个页面做非整数拉伸 |
| 中文 UI | 清晰的常规中文字体、正常字号与布局；不把正文烘焙进像素图，不强迫所有汉字像素化 |
| 声音 | 少量真实动作声：部署、工作、入库、告警；控制并发与频率，可静音／降低；不强制屏幕震动 |

参考输入契约：鼠标点选与上下文操作、拖动镜头、滚轮离散缩放，Esc 取消当前预览，暂停快捷键不能抢占文本输入。精确按键与面板尺寸在试玩中调整，不当不可变架构。

### 7.3 素材生产线

建议编辑源用 Aseprite，地图用 Tiled；运行只依赖 PNG 图集、经过验证的 JSON 清单与已导出的地图。[W6][W7] 证明这些工具有对应导出格式，不代表当前流水线已建成。

资源源文件与导出物必须有可追踪关系；清单至少记录稳定 assetKey、尺寸、帧、锚点、footprint、状态、作者／来源、许可和修订。导出物加入版本控制，CI 做完整性和引用校验；未获授权时不要求 CI 下载或运行商业编辑器。

AI 可辅助概念与首版单体素材，但不能把“生成了一张像素图”当成四方向、同光源、无抖动、透明边干净的动画资产。最终必须按统一尺度、透视、调色、锚点逐项检查。不开局就生成几十种建筑；先固定一块地形、一个机器人、一座太阳能和一个加工设施的可运行样张。

不抓取商业游戏精灵当开发资产；参考图不是素材授权。字体也只使用项目合法可用的资源，不随本方案传送字体文件。

## 8. 开发与验证路线

### 收尾 → 框架确认

先执行 00/02 文档任务，停止旧排期自动开工。所有者确认 F01–F12，再单独授权 G1。确认方案不等于自动批准上线，也不要求原审查问题全部先修完。

### G1：第一座会工作的基地

最小场景里把亲手部署、机器人安排、有限持续作业、采集加工、自产扩建、永久可见成果串起来。至少有两种经过数值探针验证的合理安排；算料辅助保留。旧 R1/R2/R4 和轻量 R8 进入这一批，完整首夜／订单／随机探索／AI 留在批次外。

内部检查点，不拆成三个大版本：

1. **一条真实链路**：场景点选 → 真实命令 → 状态变化 → 真实结果 → 刷新仍在，同时核对引擎、图集、DPR 与输入。
2. **基地执行安排**：跨采集／加工持续执行，能暂停／取消／处理缺料，画面与结算一致。
3. **自产扩建短循环**：材料竞争 → 玩家选用 → 建成后能力与场景改变 → 自发的下一步。

不先交一个只能看动画的“大而全场景”；也不先把所有逻辑做完再让所有者第一次看到操作。

### G2：布局与调度

只有 G1 有继续玩的证据后，放开有限放置，增加一个真实空间约束，扩展生产安排。允许更改任务目标，不把建造玩法退化成效率仪表盘。

### G3：能源与环境

验证短日或事件节奏，再加入昼夜、尘暴与储能策略。规则、显示和能源预算一起改；通过优秀安排可以避免损失。

### G4：基地之外

内容新阶段、任务对象、有限外部经济／采购，再考虑真实信息驱动的通讯。LLM 不是主循环或基础 UI 的依赖，没有模型也必须能完整玩核心游戏。

G2–G4 是演进方向而非批准排期，不预分配版本号、固定工期或自动授权。

## 9. 验收与风险控制

### 证据分层

- 纯规则：相同输入／时间与 seed 给相同结果，资源与能量守恒，取消和重复命令边界。
- 真实 PG：命令、预留、产出、持久化、隔离、重开与版本兼容；隔离测试源。
- 场景：选择与热区准确，命令不重复，状态／停机／完工对应事实，暂停／断线不假忙，重挂载无多实例泄漏。
- 浏览器：实际 WebGL、缩放、中文、键盘焦点、资源加载与长会话表现；Canvas 不能成为只测 API 的借口。
- 真人：能形成自己的安排；知道刚建的设施改变了什么；没有验收指令也愿意再安排一轮。所有者可以随时停止，不强迫玩满时长。

同一份资产与规则配可重置的隔离试玩存档，直接进入关键片段；正式新档流程另验。AI 负责正确性与可发现性，不给真人兴趣代签。

### 预算与首批探针

以下是建议目标，不是测试通过声明：桌面 1280×800 基准、60fps 目标／30fps 下限候选、选中反馈约 100ms 内、以 100 个活动机器人＋50 个设施作为扩展压力探针而非首期内容量。具体硬件、浏览器、分辨率、冷启动网络条件和采样方法必须记入 G1 合同后才可判断通过。

不承诺网络命令总能在 100ms 完成；本地选中与服务端受理分别测。性能不达标先查 draw calls、图集、对象数量、DOM 更新、投影与结算热点，再基于证据决定是否需要换架构。

主要风险与停止条件：

- 画面好看仍没有目标：停止扩美术与地图，修收益和安排，不默认 G2 会救场。
- 权威任务粒度不足：补最小阶段／投影合同，或调整真实结算设计；不得以假动画填空。
- 首批接入失败：冻结资源扩量，给最小复现与替代 ADR，不自动改用另一个引擎。
- 美术不一致：先修样张规范，不把数量当进度。
- 自由摆放引爆寻路／空间范围：退回 G1 合法建设位，G2 另授权；不削弱数据可信性。
- 旧 UI 与新 UI 分叉：保留诊断入口，停做旧产品扩展；一事实一写者不变。

## 10. 确认和变更纪律

所有者可整体确认此框架，也可逐项修改 F01–F12。记录确认时间、准确 commit 和例外；本文件不提前填 APPROVED。

确认后，换引擎、改原生离线优先、改视角／网格、复制权威模拟、改离线收益、引入真人共享经济、改整套美术密度等，必须单列短 ADR：触发问题、测得证据、现方案内的替代、迁移成本、存档／资源兼容、回退、所有者结论。

不为追新每批重选工具，也不为“架构稳定”拒绝被证据要求的改变。玩法数字、UI 排列和动画细节继续快速迭代。**锁定骨架，不锁死寻找乐趣的过程。**
