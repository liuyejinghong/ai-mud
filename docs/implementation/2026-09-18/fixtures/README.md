# 决策种子场景使用说明

`decision-cases.json`是24条公开开发种子，不是已运行测试，不是隐藏集，不可直接用来宣称模型准确率。包含产品语义偏好、纯规则绕过、状态漂移、transport故障四类。

实现runner时先补运行时schema，并为每类场景建立隔离的实际规则快照。case中未列字段必须从受版本约束的fixture builder补全；builder应保存完整展开输入供复核，不能悄悄把缺数据补成有利于模型的状态。npcId/characterId均用测试对象，不能用实际玩家。

`legalCandidateIds`是本计划期望的语义key，不要求模型理解任意数据库ID；完整候选必须由实际game-rules生成并匹配。如果实现合法集不同，先报告合同差异，不把fixture给定名单直接当生产合法集绕过规则。

- `providerCallsMax=0`：只测试路由/硬规则/继续现有目标；不得发外部请求，也不计入模型语义准确率分母。
- `acceptableIds`允许多个合理选择；维护者审阅标签后才进入正式评测。合法选择不必总是唯一“正确”答案。
- `transportFixture`只用于mock故障注入，不冒充供应商真实错误率/延迟。真实benchmark与mock结果分开输出。
- `transitionBeforeCommit`用于执行前状态漂移，验证二次校验，无资产写入是关键，不仅看模型答对。
- 同family改写/顺序变体放同一split；禁止开发集出现一版、验证集只换几个字。
- D14中的eat是硬需求规则，不扩展world goal枚举。
- D08/D09/D12保留原始请求，不论最后是否给partial；partial需要用户确认。

外部真实验证的120场景与开发/校准/冻结验证分组需要另建。不得把24条重复五遍叫120独立样本。原始事实、标签来源、版本、费用与未知项按v0.14报告。
