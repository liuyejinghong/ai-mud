# v1.0.0 — 小规模 MUD 内测发布门槛

状态：PLANNED；前置：v0.11/12/13/15工程通过；v0.14至少有可审计结论，Jev未过真实门槛则保持关闭。该版本以文字MUD内测交付，不把2D视为发布前置。

## A. 产品 spec

### A1. 发布对象与承诺

10-30名受邀朋友，小型在线文字世界。承诺的是一次清楚的冒险/补给/人物反馈循环、持续运行的NPC和可信资产，不承诺无限故事、复杂职业Build、永久全服动态剧情或完整公测经济。

新手默认使用当前机制真正支持的职业。未实现的法术、空内容区、没有掉落来源的装备槽必须在UI中如实标记或暂不作为正式选择，而不是只在发行说明角落写“未来计划”。不得在发布包顺手扩十级毕业、多个副本或传奇装备；这些必须另作玩法设计。

### A2. 验收层次

1. 纯规则与状态机：所有前包验收ID通过。
2. 真实PG：迁移、余额/物品账本、并发、幂等、重启。
3. 真实浏览器E2E：新用户从注册到首次反馈、重登、异常恢复。
4. 人工可玩性：v0.12标准及v0.13行为可观察性有原始记录。
5. 经济/负载压力与预发布持续观察：下述场景具备证据。

缺任意实际环境就标NOT_RUN/PENDING，不以mock或代码阅读替代。加速7天仿真不等于7天墙上时间观察。

### A3. 经济测试场景

NEW `verify:beta-load` 与经济场景runner只允许隔离库/克隆状态，默认不会清空数据库。所有case记录规则/content/provider版本、seed、初始账本与结束对账。

| 场景 | 输入行为 | 必须观察 |
|---|---|---|
| E01 无玩家7/30模拟日 | 只运行NPC与世界规则 | 基础供给是否枯竭、是否停止行动、金库/库存集中 |
| E02 普通10玩家 | 采集、吃饭、战斗、卖货、完成首次旅程 | 食物可负担性、正常循环收入/成本、修理材料需求 |
| E03 30玩家集中卖矿 | 同一时间向集市卖同类资源 | 库存/价格曲线、金库耗尽后反馈与恢复机会 |
| E04 囤积食物 | 允许范围内集中购买 | 新玩家是否仍有自给/明确救济路径，不强行发隐形库存 |
| E05 往返/拆单套利 | 固定seed搜索合法交易序列 | 无外部变化下闭环净收益<=0；账本仍守恒 |
| E06 NPC供应中断 | 暂时无可采资源/不可达/零库存 | fallback/等待不死锁，玩家收到真实可行替代 |
| E07 外部AI不可用 | 429/超时/预算耗尽/断网 | world继续、日预算不重置、未产生重复决定 |
| E08 同命令并发/断线 | 写入已提交但客户端未收到响应 | 同command重试返回原结果，没有双扣双发 |

30天加速用于发现长期趋势，不要求每个tick落真实数据库写满百万记录。保持同一纯规则语义；不要为仿真另写一套“看起来更健康”的经济。

### A4. 经济门槛

硬门槛：负资产0、未对账差额0、无外部变化闭环套利0、无无法恢复的基础行动死锁、无无来源发币/物品、已领取资格可按合同兑现、不出现NPC/玩家持续饥饿却没有可用恢复路径。

产品目标（探索性）：正常新玩家能在15分钟窗口完成一条首次补给路径；因公共库存竞争失败时能从UI找到另一条路径；基础食物短缺和救济触发要有发生率/持续时间，不只给一个“healthy=true”。记录每人每小时净收益、实际消耗、财富集中、金库变化、食物负担、售卖拒绝率、有效选择/纯等待时间。

阈值不应通过反复给NPC/金库加钱来达标。外部商队/资源再生/救济确有必要时必须显式定义source、频率、上限、展示与账本，另提交最小设计修订；不在仿真器后台偷偷修库存。

### A5. 小规模负载与持续观察

10并发正式基线：登录会话、sync、移动、采集、报价、交易和有限交涉；先短smoke再持续至少1小时，记录目标机器/部署位置、DB连接数、队列长度、API p95/p99、错误/超时、CPU/内存、实际模型费用。常规非模型请求p95<500ms是初始目标，不是未测承诺。

30并发作为容量边界探索，允许明确标记性能不足但不能出现资产错误。没有当前生产部署信息，不凭纸面宣称承载人数。

在用户授权的隔离预发环境做7天自然运行观察；结果记录每天错误、过期行动、经济分布、账本、fallback、预算和备份。此计划只是测试要求，不表示编写文档的Agent会后台持续执行。没有真正运行7天就不能把观察门槛勾掉。

### A6. 实际运行与恢复

写清安装依赖、构建、环境配置、迁移、起停、日志、健康检查、备份和恢复命令；所有生产写入另需用户授权。不得用world reset当修复工具。

至少做一次备份恢复到隔离库、一次进程在命令提交前后重启、一次provider关闭、一次schema不兼容启动拒绝。确认备份包含旅程/服务券/命令去重/决策目标以及既有资产表。

## C. 发布判定

可选结果：RELEASE_READY、ENGINEERING_READY_PLAYTEST_PENDING、BLOCKED_ECONOMY、BLOCKED_RECOVERY、BLOCKED_SOAK。Jev未验证但rule模式全部成立时可以RELEASE_READY，发行功能明确写“规则决策；Jev适配待验证/未启用”。

不是“所有未来模型/像素能力都完成了”才能发布，也不是“没P0 bug”就等于好玩。发行说明分别列技术状态、人工体验观察、样本限制和未实现内容。

## D. 回退

没有新玩法数据结构需求就不新增迁移。本包修复只限阻断问题；回退先关闭模型或首次旅程新入口，保留已有资产与维修资格履约。冻结后若源码变化，受影响验证重跑并更新exact head；不得把旧head证据冒充新head已测。
