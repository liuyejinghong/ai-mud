# v1.1.0 — 像素客户端候选方案（DESIGN_ONLY）

状态：DESIGN_ONLY。只有用户明确要求启动2D验证后才能执行B部分；读到这份文件不等于得到安装依赖、制作素材或修改客户端的授权。

前置：v1.0玩法验证已完成，v0.15观察/逻辑地图边界通过，产品仍选择浏览器优先。若用户改为原生客户端优先，先重审ADR，不机械执行本包。

## A. 已选方案与最小产品 spec

选择Phaser世界视图 + React界面 + 原Fastify/PostgreSQL/规则/AI决策后端。不是新写一套Godot服务端，也不是把TypeScript规则搬到客户端。

只做一个已存在区域的最小视觉验证，优先腐林；地图、位置、可交互物和行动进度由SceneSnapshot提供。村庄暂保持文字或粗粒度展示锚点，不因为渲染而创造村内坐标/碰撞规则。NPC无精确位置时不用随机位置伪装为服务器真实移动。

首轮素材使用有明确授权的占位精灵或程序几何块；记录source/license，不采购付费包。不需要AI生成素材，更不需要用大量美术掩盖同一文字玩法的问题。像素尺寸可以选16或32逻辑单位，但只是渲染比例，不改变规则距离。

React保留登录、NPC对话、背包、市场、任务、设置；Phaser负责场景、相机、精灵、选中、高亮、简单动作动画。按键/点击映射既有MoveIntent/InteractIntent，不另写一套网络请求或战斗逻辑。

### A1. 行为一致性

开启一个renderer开关 `text | pixel`；同一会话可以切换，保持同一game controller/state/sync。两个视图消费同一snapshot与event序列，不能分别发交易/采集指令。

移动以服务端ack为准。动画在已知起止位置间插值，不允许插值穿越逻辑墙。战斗播放结构化事件，实际HP/掉落只来自服务端；用户切标签/切renderer/重连不能重复播出资产效果。

### A2. 交互与可访问性

渲染看不清或无法使用Canvas时仍能操作文字界面。NPC交涉和报价必须保留文字说明，不能只依靠颜色。地图输入在对话输入框/弹窗打开时停用，防止打字触发移动。不同缩放、retina、窗口大小下不把CSS坐标误当游戏格坐标。

### A3. 明确不做

不增加实时手操技能、弹道/碰撞裁决、PVP、完整共享野外、复杂预测回滚、独立物理模拟、移动原生打包、离线单机、地图编辑器平台或第二种渲染引擎。

渲染帧率目标与world tick/模型调用频率无关。不能为了60fps把现有NPC API改为逐帧调用。

### A4. 依赖锁定门槛

正式开工时重新核对官方Phaser+React模板，锁定一组可复现的Phaser/模板/React/Vite版本，优先不升级现有栈。记录依据，不能混用Phaser不同major的API。若模板要求大规模工具链迁移，暂停并提交最小集成方案；不是自动升级全仓依赖。

Godot作为备用方案的触发条件：明确转向原生桌面优先、可视化场景编辑成为主要生产工作流，且接受客户端语言/协议适配成本。仅仅“像素风很好看”不是触发条件。此时后端仍可保留，另评客户端观察协议；不宣称Godot直接复用TS源码。

## C. 将来验收目标

P11-A01：同一固定trace在text/pixel最终显示的位置、HP、背包数量、旅程状态相同。
P11-A02：游戏网络请求数不因每帧渲染增加；provider调用次数不变。
P11-A03：断网/重连/重复event/切renderer不产生额外资产变化。
P11-A04：有墙fixture中角色不穿墙；点击不可达目标有明确反馈。
P11-A05：NPC对话输入聚焦时WASD只输入文字，不移动角色。
P11-A06：低性能/Canvas失败时仍能切回文字完整完成首次旅程。
P11-A07：桌面目标机器在一个区域正常渲染，报告实测帧率/内存；没有测试就不宣称60fps稳定。
P11-A08：玩法、价格、奖励、NPC判断策略与文字版本保持一致后再比较体验。

## D. 退出路径

实验不改善理解/操作体验时保留文字版，关闭pixel开关即可；不应需要迁移回旧数据库。没有用户独立开工指令时本包完成状态只能是DESIGN_REVIEWED，不能写IMPLEMENTED。
