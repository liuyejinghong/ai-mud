# v0.15.0 — 表现解耦与 2D 边界准备

状态：PLANNED；前置：v0.13.0工程通过；Jev可保持关闭。这个版本不安装Phaser，不画素材，不改变战斗时间尺度。

## A. 产品与架构 spec

### A1. 目标

让同一套已确认的游戏事实既能生成文字界面，也能被未来像素世界视图消费。保留现有网页、服务端和数据库，清除必须依靠文字表现才能工作的最后一组耦合。

不要把本包变成统一所有游戏类型的引擎，也不把只读观察协议误认为客户端有权计算伤害或交易结果。

### A2. 逻辑地图

ZoneDefinition增加受校验的逻辑层：可通行格、连接/出口、资源/遭遇/交互点。现有地图缺少walkability字段时由明确内容迁移/默认构造把所有现有合法格设为可走，保持原内容不变。障碍能力用测试fixture验证，本包不直接在正式地图增加堵路墙。

movePosition同时检查边界、可通行性和合法连接。NPC寻路不再假定先x再y能越过墙；使用单一纯函数网格BFS（首轮均匀移动成本），输出下一合法格或unreachable。玩家与NPC复用同一通行合同，但各自状态作用域保持不变。

NEW game-rules/pathfinding-rules.ts。不要为了小网格引入导航网格、动态物理引擎或大型路径规划依赖。路径缓存可先不做。

村内已有position=null的NPC仍表示粗粒度地点，不能为了画面往数据库随机写坐标。未来客户端的展示锚点只属于presentation；真正增加村内可行走地形与位置规则要单独内容设计。

### A3. 观察协议

NEW shared/scene.ts定义SceneSnapshotDto（名称可保留，语义不得随意变更）：

```ts
interface SceneSnapshotDto {
  sceneVersion: 1;
  stateVersion: number;
  serverTime: string;
  locationId: string;
  scope: 'player-run' | 'shared-settlement';
  map: {
    width: number;
    height: number;
    cells: Array<{ x: number; y: number; walkable: boolean; terrainKey: string }>;
  } | null;
  actors: Array<{
    id: string;
    kind: 'player' | 'npc';
    displayName: string;
    position: { x: number; y: number } | null;
    publicAction: string | null;
    appearanceKey: string;
  }>;
  interactables: Array<{
    id: string;
    kind: 'resource' | 'encounter' | 'exit' | 'npc';
    position: { x: number; y: number } | null;
    enabled: boolean;
    disabledReasonCode: string | null;
  }>;
}
```

该示意合同落地要有运行时schema；id/版本/cursor必须保持安全整数/字符串约束，不能假定JSON能无损承载任意数据库bigint。若现有number cursor在当前范围安全，本包不为理论问题全仓迁移；需记录限制并拒绝不安全序号。

Scene只提供当前玩家被授权看到的状态。不要直接spreadNpcSummaryDto泄露所有NPC钱包/库存/记忆；不发另一玩家的个人地图、任务或未揭示seed/未来掉落。appearanceKey来自稳定内容key，不来自模型临时编造的素材URL。

### A4. 同步与动作接口

继续使用现有唯一game/sync与useGameSync，按当前行动3s/空闲15s的节奏演进，不新增独立像素轮询器。Scene可作为state的只读字段加入；每个snapshot绑定stateVersion/服务端时钟，先应用有效快照，再播放尚未处理事件。

客户端必须处理重连、重复eventId、旧snapshot晚到、响应乱序、cursor失效。过期cursor的恢复是重新取当前授权快照，不重复执行过去资产事件。新事件用于显示，不是让客户端重算背包。

NEW客户端RendererPort：输入SceneSnapshot+可见结构化事件，输出MoveIntent/InteractIntent。文字与未来像素视图调用同一controller和API；展示组件不得自行fetch第三方模型，不得持有DB或provider。

玩家移动先按现有server-ack语义，不做复杂预测。按键等待回复期间可做轻量忙碌表现，但不把预测坐标当事实。没有必要因为动画60fps把world tick改成60Hz。

### A5. 有界重构

从GameService移出“Scene DTO组装”和“纯文案格式化”两块，而不是按文件行数机械拆十层。继续使用同一事务和现有业务服务。shared不得导入Fastify/Drizzle/Phaser/React。game-rules不得产生网络/数据库side effect。

game-rules的纯函数只返回事实；template formatter输出中文；controller负责用户输入/同步；renderer负责展示。v0.11留下的legacy只读展示可保留，但不得重新引入日志解析参与结算。

## B. 引擎决策记录（本包完成ADR，不实施引擎）

默认：Phaser + React + 现有TypeScript后端。Phaser负责地图/精灵/动画，React保留对话/市场/背包/设置；不把全部界面搬进Canvas。

理由：当前产品浏览器优先，已有TS/Vite/React，官方有React集成模板；减少重写和新的语言边界。Godot是原生客户端优先、重编辑器工作流时的备选，不因像素风自动迁移。官方事实来源见sources-and-baseline。

具体Phaser major/模板版本在v1.1真正开工前重新核对并pin；2024年的模板材料不能当成2026最新API。不会为了照抄一个模板把现有React/Vite/测试体系整体升级。无需现在作出付费插件/商业资产购买决策。

是否改实时动作战斗、是否做离线单机、是否做真正共享野外是独立产品决策，本包不代为决定。

## D. 验收

R15-A01：现有四方向移动与采集/遭遇回归不变；fixture有墙时玩家和NPC都不能穿墙。
R15-A02：无路可走不无限调用AI、不busy loop；返回明确unreachable并走规则。
R15-A03：两个不同玩家不能通过scene请求获取对方个人野图/背包/记忆。
R15-A04：同一结构化combat事件改中文措辞，不改变HP/掉落/播放时间数据。
R15-A05：模拟重复/乱序sync、断网恢复，状态不倒退、动画不触发第二次资产写入。
R15-A06：只有原controller管理网络与输入；未引入第二份权威state/store。
R15-A07：package依赖没有Phaser/Godot、没有引入WebSocket或改world tick频率。
R15-A08：v0.12文字旅程与v0.13NPC决策仍能完整运行。

## E. 版本与回退

主要api/content/ruleset/engine可能变化；没有持久模型变化就不要无意义加表。Scene为可加字段，原文字客户端仍可显示基本状态；若后续移除字段，另开兼容迁移，不能在本包顺手破坏旧客户端。

回退先切回文字renderer；服务端scene字段保留兼容，不回滚逻辑地图中的真实状态。最终交接必须明确：已具备接入2D的边界，但尚无像素客户端；不能拿Scene JSON截图宣称完成2D游戏。
