# AI MUD 分阶段总控 2.0：架构先行

更新：2026-09-18。状态：ARCHITECTURE_REVIEW，尚未实施。源码基线 `690cbc816051b30e323bb005c93c1396e1303c3c`，产品 `0.10.6`。本次仅重写文档；不改版本、依赖、数据库或游戏功能。

> 本总控取代同目录1.0版本的直接开工顺序。旧版本文件保留参考，不因为文件内仍写READY而授权执行。尤其不要继续使用上一轮“按F11-T01至F11-T06实施”的启动指令。

## 1. 为什么暂停旧队列

旧计划把玩法优先级写清了，但仍默认了几个尚不牢固的架构前提：世界推进互斥、统一资产入口、事实与文案隔离、读取与按需结算的归属、模型无关的接口。用户要求先把这些理清，避免新任务/AI/像素层继续复制旧边界问题。

结论不是推倒重写，也不是先搭一套万能引擎。保留当前技术栈，完成一个有限的架构收敛里程碑，随后马上回到小玩法验证。

## 5. 结束架构工作的标准

以architecture-baseline中的ARCH-GATE为准：重复/并发结算、资产全事务回滚、事件不依赖文案、离线懒结算正确、旧响应不能覆写新状态、模型关闭核心路径可用、唯一的装备与资产写边界。

门槛通过就回到B1的小玩法原型，不继续增加抽象、服务、数据库或渲染功能。ENGINEERING_PASS、PLAYTEST_PASS、LIVE_MODEL_GATE_PASS继续独立；没有真实执行记录不得通过相应门槛。
