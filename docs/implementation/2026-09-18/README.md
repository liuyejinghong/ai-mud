# AI MUD 分阶段总控3.0：模块化合同先于功能扩张

2026-09-18；状态 DESIGN_REVIEW，未实施。源码基线 `690cbc816051b30e323bb005c93c1396e1303c3c`，产品0.10.6。本轮文档不修改运行版本、源码、依赖、数据库或仓库保护设置。

本总控替代1.0/2.0入口；旧版本包不凭READY字样自动执行。2.0确定的技术栈与权威/事务/时间方向保留，3.0补上模块公开能力、数据归属、依赖图、功能退役和可执行护栏的落地要求。

## 1. 目标

构建可以增加更复杂玩法的模块化单体：新功能调用已有能力，而不是复制资产/时间/记忆/同步逻辑。复杂度增长应落在明确的领域内部，不增长成任意相互依赖。仍先用现有小规模验证，不能用设计图承诺未经实测的NPC数量/并发容量。

跨模块API默认进程内TypeScript接口，不是HTTP。关键多模块变化用同一UoW事务；非关键传播才用提交后事件。没有新的微服务、通用CommandBus、反射式DI或工作流框架。

## 3. 容易被实现错的地方

### 3.1 UoW不反向依赖所有业务

platform底层事务执行器只知道Db/事务生命周期。composition创建闭包，把同一tx绑定到各模块的bootstrap适配；每个application用例的ports类型只声明需要的public API。application看到 `run(scope, ports => ...)`，看不到裸SQL；platform不import npc/quests等领域类型。不能为了类型方便把所有业务接口移动到platform或shared。

### 3.2 事件不能隐藏新的循环依赖

事件合同属于生产者公开API；消费方使用登记的依赖边。若业务消费者没有直接依赖许可，由application的明确事件适配器读取生产者事件、调用消费者public API，不把所有事件类型塞进kernel。合法的时间推进/因果反馈可以循环，但必须有状态条件、幂等和工作量上限；禁止无边界的同步调用环或事件自激循环。

### 3.3 共表不是共有写权限

角色/NPC行里的铜币列归assets，HP/目标等归原领域；task里的escrow金额归assets，任务状态归quests。初始化的零默认值、锁根读、schema/migration由精确例外处理；不把整张表权限一开了之，也不急着为了归属拆所有表。

### 3.4 护栏要真实运行

MOD-02需先建立精确legacy基线，新增违规立即失败；不能等全部重构后才加检查。配置、声明/API和SQL能力各有局限，真实数据库回滚/权限/并发测试不能省略。文档、目标JSON、分支保护和已经运行的CI是四件不同的事。

## 4. 当前v0.11.0的唯一任务顺序

`ARCH-01 → MOD-01 → MOD-02 → ARCH-02—08（每项完成MOD-03）→ ARCH-09 → MOD-04 → ARCH-10`。

- MOD-01冻结实际文件/数据/接口归属，不批量移动文件。
- MOD-02创建并验证架构检查器：公开入口、允许边、循环、声明/SQL能力、未知文件与负例。
- MOD-03贯穿原ARCH真实迁移，不是重复重写一次功能；迁一条链删一条旧旁路和相应例外。
- MOD-04独立证明模块可通过public消费/替换、失败原子、内容可扩展、功能可安全停用。

仍分小切片审查，禁止整条路线一口气实施。产品版本只有全部相关工程门槛满足才变0.11.0；模块化设计通过不等于实码MODULAR_BASELINE_PASS。

## 6. 停止搭框架的条件

事务与恢复、事实/文案、模型降级、角色懒结算、协议旧响应、数据权限以及模块护栏均有真实证据；新增适用内容和替换provider无需侵入不相关模块；例外清单透明且无新的旁路。

满足后回到小玩法验证。未来新需求可以通过ADR扩展合同，不承诺永久零重构，不提前实现所有功能。ENGINEERING_PASS、MODULAR_BASELINE_PASS、PLAYTEST_PASS、LIVE_MODEL_GATE_PASS各自验收；无环境/真实执行记录写NOT_RUN或BLOCKED。
