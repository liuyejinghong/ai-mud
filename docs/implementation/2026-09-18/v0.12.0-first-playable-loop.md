# v0.12.0 — 黑松第一笔补给

状态：PLANNED；前置：v0.11.0 ENGINEERING_PASS；默认完全 rules + 模板，零外部 AI 调用。

## A. 产品 spec

### A1. 核心体验

玩家帮助铁匠伯林补充一份真实的维修物料，可以自己采矿、从集市购买，或用口粮与矿工托林交换现货。交付后矿石真的进入伯林库存，伯林记住这次帮助，并给予一次能真正兑现的基础维修服务。

这是首轮可玩性切片，名字是“黑松第一笔补给”。不要虚构全服危机：当伯林库存不缺时叫补充储备，不能依旧说全镇即将停工。独立玩家的首次旅程不等于每个人都单独修复了一次共享城镇。

### A2. 成功定义

首次体验目标约10-15分钟（产品设计目标，不是工程工期）：玩家理解一个人物诉求，至少看到两条有明确代价的途径，完成一次真实交付，看到记忆/库存/服务资格发生改变，并能说出下一步目的。重要反馈在交易/交付完成后立即展示，不等到几个现实小时后才展示。

### A3. 世界范围与资产

继续只有玛拉、托林、伯林、艾廉，既有腐林/旧矿坑、野莓/矿石及原战斗。开启四人的对话入口，仍必须检查人物与玩家是否在允许交互的地点，不伪造 NPC 瞬移回村。外出 NPC 显示“在外工作，当前不可交涉”，主流程始终有采集替代路径。

旅程是 player-npc 的个人首次记录；所有矿石、野莓和 NPC 钱包仍是真实共享资产。初始人物资源不增加，不能为了让三个按钮亮起给玩家偷发金币。测试 fixture 可以设置钱包/库存，但只在隔离测试库，并有测试种子标记。

规则初值（集中于 NEW `packages/content/src/first-journey.ts`）：交付 `iron_ore x3`；托林唯一换物配方为玩家 `wild_berry x2` ↔ NPC `iron_ore x3`；NPC 完成交换后矿石保留>=3；对方现有可食库存<=1；NPC饥饿<=2；每NPC每世界日最多3笔这类优惠交换；每角色仅首次旅程至多1笔。所有值可通过单一内容版本变更，但不得在 service 多处硬编码。

配方是刻意有限的帮助机会，不是自由交易市场。禁止来回换、交换铜币、任意物品、借贷、未来产量承诺或跨NPC自动物流。库存/需求不足时协商路径可以关闭；UI必须说明原因，不能让玩家先交食物再说没矿石。

### A4. 三条路径与取舍

| 路径 | 实际动作 | 代价/优势 | 无法选择时 |
|---|---|---|---|
| 自己采矿 | 原地图/采集/战斗系统 | 时间与探索风险，不要求本钱 | 显示可到达的另一矿点；首次基本路径不得依赖所有公共库存 |
| 市场购买 | 原市场报价+确认，购买3矿或补足差额 | 花费真实铜币，快 | 报价/余额不足就禁用并解释；不赊账 |
| 帮助托林 | 同地点交涉，现货原子换物 | 消耗食物、受NPC需求与库存限制 | 指向采集/购买；不假装所有玩家永远有同一优惠 |

选择标签只是引导，不决定奖励。允许混合来源；不得根据UI上选过哪个选项虚构矿石来源。已有矿石的玩家可以直接交付，仍记录真实扣减。交易/采集事件可用于显示来源摘要，但不增加掉率或发重复奖励。

### A5. 旅程状态和数据

NEW `player_supply_journeys`：id、character_id、chapter_key（固定 blackpine-first-supply-v1）、status（offered/completed）、offered_at、completed_at、delivery_command_id、barter_completed_at、repair_voucher_used_at。UNIQUE(character_id,chapter_key)。没有独立奖励钱包，也不是第二套通用任务引擎。

服务使用 existing npc_tasks 处理原有真实需求任务；首次旅程单独标识为 onboarding-supply，不能伪装成同一NPC无限刷新的一般缺货任务。本包不改变原任务的奖励托管合同。首次旅程没有铜币/经验奖励，因此不存在新奖励资金来源。

新增业务命令，统一走 v0.11.0 receipt：

- `offerFirstSupplyJourney`：只建立个人旅程，幂等、无资产变化。
- `previewFirstSupplyBarter`：只展示当前可行性与固定配方。
- `commitFirstSupplyBarter`：锁相应角色/NPC/双方物品，重读需求、库存、次数；同一事务玩家-2莓+3矿、NPC+2莓-3矿、记账、次数更新。预览不是承诺；不符合时无任何转移。
- `completeFirstSupplyJourney`：同村与伯林交互，玩家-3矿、伯林+3矿，状态completed，记录唯一 system_verified favor 与一次性维修资格。一次事务完成，不重复交付。
- `redeemFirstSupplyRepair`：仅completed且未使用时；选择当前拥有并装备的一件损坏装备，物品等级<=8；伯林消耗1块实际矿石且消费后保留>=3；玩家不付铜币，该件耐久修满；资格只成功消费一次。没有损坏装备时保留资格；伯林没矿石时说明暂不可兑现，不能烧券或凭空造矿。

维修服务是物料消耗和明确的一次性劳动优惠，不增发铜币。满耐久/不属于本人/装备已换下/等级>8/重复使用均拒绝，无side effect。新业务通过现有 ItemService/repository/ledger 的同一tx扩展，不直接 set 一个假的背包总量。

兑换资格不因离线过期；未交付旅程不产生离线惩罚。既有角色同样可领取一次首次旅程，但同一character/chapter不能重置刷券。发码内测以现有账号约束控制重复账号，不宣称已解决公测女巫攻击。

### A6. 实际反馈与对白

交付后显示简短三行事实：交给伯林3矿；伯林记住一次实际帮助；一次基础维修可用（列条件）。对话开场读取这条 verified memory，而不是每聊一句都涨信任。

NPC仍可以有不同口吻，但原型只用模板。玛拉解释食物用途和补给路线；托林解释自己的现货和吃饭需求；伯林展示订单与维修回报；艾廉解释市场与保底补给。禁止文案承诺玩家未获得的战斗能力或全服价格变化。

### A7. 新手 UI

将主引导改为：认识伯林 → 查看方案与成本 → 获得3矿 → 交付 → 查看回报/下一步。只有一个主要目标卡；展开最多三条路径。目标卡直接列可行性、当前位置、预计规则耗时/风险提示，不要求玩家盲走找图例。

保留快捷键，补地图图例和资源/危险方向提示。任务完成后折叠，引导不会盖住正文；1440/980/390宽度检查阅读与输入。这里做可读性，不换整站皮肤。

术士当前法术未实现，不得暗示其智力已经产生法术优势。本包先明确标为“职业机制预览，暂不推荐首次验证”，默认新手战士/游侠；保留旧术士角色可继续游玩。不在本包添加法术系统，避免同时调多个玩法变量。

## C. 测试场景

F12-A01：零铜币玩家仅靠既有可达个人资源完成采集路线，真实减少3矿并增加伯林库存。
F12-A02：有钱的测试玩家按当时报价购买路线，所有付款流向市政账本，无隐性初始赠款。
F12-A03：托林饥饿2、食物0、矿石6、玩家2莓，换物后NPC3矿2莓/玩家3矿；两边守恒。
F12-A04：托林矿石5或食物2、次数耗尽、人物不在场，换物拒绝且双方资产不变。
F12-A05：两个玩家争最后一份优惠，最多一个成功；同一个command并发只一次效果。
F12-A06：三条途径与混合来源最终奖励一致，交付重试不增加第二张券/第二条favor。
F12-A07：服务券兑换实际损坏装备；满耐久/换装/他人物品/材料不足时不消费资格。
F12-A08：刷新、断线、进程重启后旅程/券/记忆仍一致。
F12-A09：关闭外部AI全部功能后以上闭环仍完整，无请求到第三方。
F12-A10：三个断点下目标、费用、主要操作可见；失败不要求重建角色。

## D. 产品试玩门槛

先找5名未读设计文档的人做约15分钟会话（时间是玩法测试窗口，不是对用户的交付承诺）。不给口头操作教程，允许使用产品内帮助。记录首个有意义选择耗时、完成情况、等待占比、困惑点、原话，不仅收集满意度分数。

探索性通过目标：至少4/5能指出伯林要什么和至少两种获取方式；至少4/5能指出自己的交付造成的实际变化；至少3/5表达一个具体的继续游玩动机。样本很小，不能外推留存率或市场成功。

若未通过：记录哪段体验失败，只调这一包的提示/等待/代价，重测；不要先增加Jev或像素图。未招募到人时状态是PLAYTEST_PENDING，不得编造反馈。
