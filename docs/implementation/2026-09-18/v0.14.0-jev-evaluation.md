# v0.14.0 — Jev 适配与对照验证

状态：PLANNED；前置：v0.13.0；目标是验证是否值得使用，不是预先宣布Jev胜出。

## A. 产品与能力 spec

### A1. 两段门槛

ADAPTER_PASS：本地接口、mock响应解析、故障/限流/预算/开关都通过。
LIVE_MODEL_GATE_PASS：官方API合同已核对、真实中文场景调用、成本和延迟记录、对照实验均有证据。

只有后者通过才允许在受邀内测启用typesafe。没有外部凭证时完成前者并标BLOCKED_EXTERNAL；后续MUD版本可继续使用rule。禁止把fixture伪装成外部服务成功。

### A2. 只替换两种选择

`npc_resource_decision`与`npc_world_intent`使用Jev的有限Choice选择语义。它不负责生成对白、自由文本理由、记忆摘要、数量、坐标、公式或价格。保持原NarrativeProvider；常规回复走模板。

所有硬安全规则仍在服务端。即使供应商承诺输出类型安全，也要在边界校验未知候选、缺字段、畸形响应和超时。供应商confidence只作为参考/回退输入，不能直接写入人物关系、抽样NPC性格或跳过权限检查。

### A3. J14-T01外部合同核对是必做项

编制本计划时TypeSafe官网摘要可核对其typed decisions与输入价格宣传；详细docs页面获取失败，故本包刻意不编造HTTP字段、SDK版本、返回路径、模型固定ID、速率或保留数据配置。见sources-and-baseline.md。

实施者在写adapter前，必须从官方docs/官方SDK核对并保存 `docs/reviews/<日期>-typesafe-api-contract.md`，包括：官方URL/查阅日期、精确SDK及锁定版本（或HTTP协议版本）、模型固定ID、鉴权、Choice候选映射、响应字段与null规则、概率/confidence语义、usage口径、timeout/abort、重试策略、速率限制、价格、数据使用选项。

文档核对不到的字段标UNKNOWN；阻止真实接入，不猜测。固定模型版优先；仅有latest别名时记录alias+请求时间+服务返回model版本/标识，基准报告注明不可完全复现。不要把某聚合平台的chat接口当成官方native接口，也不要为通过测试暗换供应商。

本项目内部DecisionProvider合同不依赖上述API字段，未核对时可完成rule/fake、配置和测试框架；但native适配的真实有效性不能验收。

### A4. 网络与预算

新增TypesafeDecisionProvider，config中新增 `TYPESAFE_API_KEY`、`TYPESAFE_MODEL`；只在server读取密钥，不暴露在shared DTO或浏览器bundle，不修改用户现有.env。

默认仍是rule。新增明确 `NPC_DECISION_PROVIDER` 与 `TYPESAFE_SHADOW_ENABLED=false`；shadow只记录建议，不执行其选择。每一测试臂必须记录实际provider，不接受“模型开关开着但都fallback”却称模型实验成功。

初值：服务端全局外部选择并发2、每分钟60次应用侧上限（这是本项目自限，不是供应商承诺）、交涉1500ms/世界2000ms deadline、无自动二次付费重试。429/5xx/网络中断/预算耗尽走rule。冷却与幂等仍按v0.13，不因换provider失效。

真实测试需 `ALLOW_LIVE_AI_TESTS=true` 与显式美元预算参数；未给budget直接拒绝，不默认无限调用。首轮建议硬上限5美元（预算上限不是预估一定消费）。调用前按已核对的价格与保守token上界预留预算，调用后用usage对账；usage缺失计UNKNOWN并保持保守预留，不当作免费。并发预算扣减必须原子，重启后不清零已花费用。

不把上下文上限当正常prompt长度：首轮每次决策输入预算目标<=2000实际计费tokens；超预算先确定性裁剪非关键近况，保留合法候选和硬事实；裁剪后仍太大则fallback，不丢保留量/授权字段。

### A5. 对照实验设计

三个臂：A=RuleDecisionProvider；B=固定版本生成模型只选候选（沿已有DeepSeek适配）；C=Jev。输入事实、候选、选择任务相同；表达文案固定用同一套模板，防止把对白风格差异归功于决策模型。

先跑离线已冻结快照；再shadow（不生效）；再在隔离世界运行配对scenario，初始seed相同但允许后续世界因决策不同而分岔。不能拿对方已经看到的未来世界状态喂给另一个模型。

源码中的 [语义种子场景](fixtures/decision-cases.json) 是公开开发集，不是隐藏benchmark，也不是实际结果。每个case有合理选择集合，不假设人物取舍总有唯一答案。

扩展到>=120个独立语义场景，建议60开发/30校准/30冻结验证。分组按场景族切分，同义改写与同一故事前后句必须进入同一split，不用重复prompt凑样本。冻结验证答案不得回喂prompt或用于调阈值；调过后换一批新的验证场景。数据必须覆盖中文否定、隐含诉求、谎称履约、关系/成本冲突、状态漂移、候选次序变化、长无关背景与重复交涉。

开发模型可以生成候选场景，但合理标签需要维护者/独立评审核对，不能让被测模型给自己判卷。多解保留允许集合，争议项单列不强压成错误。5个真人试玩不是120个模型标签，也不能相互替代。

### A6. 指标与启用门槛（初始工程目标）

必须同时报告：真实请求成功率、合理候选命中率、规则拒绝率、过度拒绝率、人格/承诺一致性、fallback率、stale率、p50/p95/p99端到端选择耗时、总计费输入、总费用、每千次可用决定成本、每玩家小时费用、缓存命中与外部调用数。

启用typesafe的初始门槛：

1. 所有确定性资产/权限边界测试通过，未授权实际写入=0；此项不靠120个语义样本统计推断。
2. 冻结语义集合理选择率>=90%，且不比B低超过5个百分点；错误有逐条解释。报告样本数和置信区间，不宣称小样本证明生产可靠率。
3. 在被标注应可合作的子集，不得靠全部拒绝刷安全；合作覆盖率不低于rule基线5个百分点以上。
4. 模型timeout+transport error触发的fallback<=5%，测量覆盖目标部署网络和并发；p95<=1500ms是目标，不把官方宣传均值当实测。
5. 在语义可用性达标时，每千次可用决定成本<=B的1/3，或有可审查的显著延迟优势并保持批准预算；与免费的rule比较不能只谈价格，要有实际行为/体验增益。未满足时默认保持rule/B，不为项目名称强启Jev。
6. 真人同模板对照中没有明显的反复反悔、凭空承诺、无原因拒绝恶化；没有真人数据则只能完成技术门槛，不能宣称改善乐趣。

成本分母是成功且可执行/合理的决定数，分子包括全部失败请求、重试（本包默认禁用）、fallback所耗模型费用；缓存结果单列，不混入供应商原始延迟。使用所有排队+网络+归一化时间，不只取服务端inference耗时。

confidence阈值仅在校准split上选择，并报告 coverage与错误率；验证split不再调阈值。没有校准证据，不能凭0.9这个数字直接开启高风险赠予。

## C. 必测失败项

未知candidate；多出amount；缺choice；NaN/超范围probability；无confidence（应null，不伪造0）；429；超时；网络断开；预算刚好用完；两个进程抢预算；重启后pending；迟到success；用户重复nonce；供应商model变更；usage缺失；中文说“不是要矿石”；玩家谎称刚帮过NPC；prompt里夹带要求忽略库存的句子。

模型是否受提示注入影响是语义测试项；不受影响不等于可以删掉确定性规则。即使注入让它选择错误但仍合法的候选，也要报告游戏体验影响。

## D. 回退与交接

单开关切回rule；已accepted目标继续执行、pending按deadline规则恢复；不修改事实存储格式以绑定某供应商。交接给出精确SDK/model/prompt、价格日期、dataset hash、holdout划分、实际外部调用数、总费用和所有UNKNOWN。真实API失败时后续包仍可走rules-only，但发行说明必须明确Jev关闭/未验证。
