# v0.13.0 — NPC 候选决策闭环

状态：PLANNED；前置：v0.12.0工程通过，已记录试玩状态；默认provider=rule；本包不接TypeSafe。

## A. 产品 spec

### A1. 目标与非目标

让“愿不愿意帮玩家”和“下一阶段做什么”成为可替换的决策，而不是把对白生成器换个名字。合法候选由规则构造；人格、可信经历、负担影响选择；选择被现有服务执行；玩家能观察已发生的后果。

只实现两个purpose：npc_resource_decision、npc_world_intent。保留原对白/记忆压缩/传闻生成路径，不把它们送进只做选择的provider。不要实现自由规划、自由坐标、任意数值建议、工具调用Agent循环、NPC之间借贷合同。

### A2. 正常流程

```text
规则构造完整候选与有限观察快照
→ 建立唯一decision记录并结束短事务
→ DecisionProvider（事务外；默认规则）
→ 短事务重读相关状态与候选前提
→ 提交原有行动/交易/任务路径
→ 记录结构化结果与可信记忆
→ 模板或原NarrativeProvider描述已确认结果
```

若涉及玩家支付/给予，先返回明确预览，玩家确认后才转移；NPC表达愿意不是已经成交。NPC自主世界目标无需玩家确认，但只能执行现有合法动作。网络超时不能阻塞 world tick、数据库锁或玩家普通移动。

### A3. NPC人格与偏好

NEW content/npc-personalities.ts，四个NPC固定配置，不每次请求随机生成：

- 玛拉：重视基本口粮与互助；对低代价、可信帮助倾向合作。
- 托林：重视补给与工作连续性；有饥饿需求时优先能恢复工作的交换。
- 伯林：重视已答应的服务和维修物料保留；不能因闲聊送掉工作必需品。
- 艾廉：重视可验证履约和基本供给；不把玩家夸奖当真实贡献。

这是游戏行为设定，不是用户性格推断。初版不增加Fear/Trust/Stress等几十维连续数值；使用既有关系与verified记忆，配少量明确偏好标签。

### A4. 资源决策候选

候选种类：refuse（始终有）、grant_exact（完整原始请求且资产/保留量满足）、grant_partial（规则固定的有限帮助包，必须明确不同于原请求）、accept_barter（v0.12固定配方且满足前提）。任何候选的数量/物品/收付款方都只存在于服务器构造的对象中。

客户端和模型都不能修改partial数量。拒绝与部分帮助要明确说明“你提出的X未被全额满足，当前可给Y，是否接受”。未确认不发Y。没有合法正向候选直接规则拒绝，不付费询问。不能仅因陌生关系就从合法集合删除一项资产上承担得起的动作；关系用于选择，不用于绕过保留量。

数值解析沿v0.11的可靠路径。允许有限语义分类辅助识别“求助/交易/闲聊”，但含糊金额不自动补全；分类不产生资产。人物贪婪/慷慨可以影响选择，但不能给语义模型权限去评价实际库存是否足够。

规则fallback：唯一候选直接选；对陌生人且高牺牲的无偿赠予选refuse；有verified帮助且代价轻/中、保留量满足时允许grant_exact或已给定partial；符合首次补给需求的现货barter优先accept_barter；相同输入用稳定tie-break，不能每次随机抽样。

### A5. 世界目标候选

首轮仅6类：work_resource、buy_supply、sell_surplus、request_supply、return_home、rest。全部落在已有NpcService的移动/采集/买卖/进食/任务逻辑上。不加入没有实际实现的“巡视提升治安”“看市场获得情报”等空壳动作。

硬规则优先：饥饿和基本生存、合法性、已接受的服务义务、不可重复资产动作。有效current_goal继续推进，不每个移动格重选。无有效目标时才构建候选。一个目标持续到完成/失效，初值TTL2小时；rest仅空闲2个世界tick，不宣称有未实现的体力恢复。

work_resource只向规则指定的现有职业资源点移动/采集；buy_supply先保证钱包与可售库存；sell_surplus保留生存与职业物料；request_supply通过原NpcTaskService.detectCandidates/commitCandidate托管真实奖励；return_home只移动；rest不产钱/产物品。

原WorldPostTickService自动同步所有需求任务的路径必须调整：有缺货候选不等于已发布任务；只有选中request_supply才提交该任务。不能同时保留旧自动发布和新选择发布两条路径。

过期不是随机失败：库存没了/路径不可达/目标已满足时标记invalidated，产生有限重规划触发；不得无限每tick重试同一个坏目标。现有active action完成后再换目标；硬生存抢占按规则取消/结算，不回滚已得到的成果。

### A6. Provider接口与执行参数隔离

使用共享合同DecisionInput/Output，落地到NEW server/modules/ai/decision-provider.ts。本包提供RuleDecisionProvider和可选DeepSeekDecisionProvider，NarrativeProvider保留原completeJson能力，不把两类返回类型揉成一套。

模型实际输出只允许selectedCandidateId，以及可选的有限reasonCode。响应校验拒绝多余执行字段（amount/itemId/reward/coordinate等）。内部DecisionOutput的source/provider/model由适配器填，不能相信模型自称rule或trusted。

候选列表最多6个，输入只取最多6条相关verified记忆+最多3条相关近况；不会将所有NPC账本发送给provider。外部生成模型选择时输出上限120tokens，不要求“中文短理由”。有需要的台词在执行后生成，普通决策用模板，不能每次判断又附带一次昂贵的解释调用。

### A7. 持久化与并发

NEW `npc_intent_decisions`：id、npc_actor_id、character_id nullable、purpose、trigger_key、candidate_set_hash、relevant_state_hash、status(pending/accepted/stale/invalid/fallback/failed)、selected_candidate_id nullable、source、provider/model、reason_code、created_at、completed_at、expires_at、execution_command_id nullable。UNIQUE(npc_actor_id,purpose,trigger_key)。日志不存完整玩家输入或完整prompt。

world_actors增current_goal（受校验JSON）、goal_expires_at、goal_decision_id。goal只是现有执行器的输入，npc_actions仍是行动事实；不再新增goal scheduler或第二套action表。

trigger_key：世界用npc+世界日期+规划窗口/明确失效eventId；对话用由服务器生成并绑定character/NPC/原始请求的interactionId。仅客户端换nonce不能绕过交涉冷却或同一事实窗口的决定缓存。日配额针对npc/世界，不乘在线玩家数。

决定提交时只核对会影响该候选的相关事实。其他玩家的聊天或无关NPC移动不应让所有决定stale。给付/换物仍要在用户确认事务里再校验。状态变了不暗中换候选、不暗中缩数量。

后台decision处理接入现有post-tick生命周期；不得在world lease锁或事务里await模型。最小实现可在post-tick结束后的既有应用工作链中处理有限队列，生命周期关闭时abort，pending记录重启后按过期规则恢复；不新增周期定时器来抢原world clock所有权。

deadline初值：交涉1500ms、世界目标2000ms；超时只做一次规则fallback。迟到响应不能覆盖已fallback/已accepted的决定。终态通过条件更新CAS保证唯一。失败重试不会再次转移资产。

### A8. 玩家可观察性

至少显示：NPC当前实际目标、一次重要行动完成、拒绝/部分帮助的实际条件、已验证帮助带来的后续不同合作机会。只显示实际执行的结果；不要展示精确内部信任阈值、其他玩家隐私或伪造“内心独白”。管理员可查看decision source、候选数量、stale/fallback原因、延迟、次数。

## C. 验收矩阵

N13-A01：相同合法快照的rule选择可复现；人格不同可以按明确偏好选不同合理候选。
N13-A02：同一NPC被10客户端同时观察，world decision只有1条而非10次模型调用。
N13-A03：目标移动10格最多发生一次目标选择，不每格问AI。
N13-A04：模型拒绝/全额/部分/换物决定都匹配候选；越权数量/物品字段被拒绝。
N13-A05：模型响应前库存减少；决定stale，零资产变化，无偷偷降为部分赠予。
N13-A06：模型超时产生一个rule fallback；随后迟到success不能再执行一次。
N13-A07：数据库事务打开期间fake provider一被调用就测试失败；真实网络永远在事务外。
N13-A08：request_supply被选才发任务，奖励托管；不选不发；同NPC只有一个阻塞任务。
N13-A09：日预算/次数用尽后世界继续，history catch-up不补打每分钟模型请求。
N13-A10：玩家谎称已经送矿不增加verified favor；真实交付重复投递只计一次。
N13-A11：持有有效目标的NPC重启后继续，不能把过期pending视为已执行。
N13-A12：原v0.12全闭环在rule模式仍通过，玩家能指出一次NPC决定造成的实际后果。

预期schema/api/ruleset/content/prompt变化。回退优先把provider切rule，保留已接受current_goal继续执行；关闭新选择时由明确规则接管下一目标。不清空已完成决定，不撤销已经合法转移的资产。未来Jev只能替换DecisionProvider，不直接插入NpcService内部。
