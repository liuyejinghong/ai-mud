# 架构阶段提示词

## 1. 继续设计审查（当前默认）

你正在审查AI MUD的架构，而不是执行玩法版本。
读取AGENTS.md、docs/implementation/2026-09-18/README.md、docs/architecture/2026-09-18-review.md、docs/architecture/target.md和architecture-baseline.md，并对照当前源码。

只输出：发现的事实错误、未闭合的职责/并发/恢复边界、必要的减法、针对现有玩法的最小修正。明确区分现状/目标/未实测假设。不得添加游戏功能、迁移、依赖或真实模型调用。旧F11—v1.1包都不是当前开工授权。

## 2. 架构实施（必须由用户明确选中批次）

本轮仅实施用户明确指定的ARCH任务。先读取上述文件，核对main/当前工作树与690cbc8审查基线的差异；遵守项目命令与真实测试约定。

按architecture-baseline.md顺序：先测试现状/不变量，再迁移真实入口，删除对应旧路径。不要新建空泛基础设施，不改变玩法数值，不升级所有依赖，不开发补给/Jev/像素。一个聚焦任务一个commit，结束记录exact head与GATE证据，不自动合并或进入下一批。

关键设计冲突无法按target解决时，提供最小冲突证据和建议，保留当前可运行状态；不要自行扩成新系统。没有PG/浏览器只能写NOT_RUN，不能用mock冒充真实验收。

## 3. 独立架构验收

从实施提交的冻结head独立读取，不只看汇报。逐条审AR-01—AR-08和G01—G10：写入口是否真收敛、事务是否完整、旧lease/装备双真源是否退场、read是否偷写、协议版本是否自洽、provider能否越权、失败与重连能否恢复。

重点独立走读三条跨模块链：市场交易、NPC任务交付、世界tick。保留保护约束，但拒绝没有当前用例的抽象层。列出CONFIRMED/REQUIRES_TEST/DESIGN_TRADEOFF，不用“测试绿”替代架构推理，也不把静态风险描述成已经发生的事故。验收报告不授权生产发布。
