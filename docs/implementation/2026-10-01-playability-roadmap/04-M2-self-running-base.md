# M2「基地自转」产品需求

版本目标：1.2.0。前置：M1 签字。来源：诊断 R1（玩家即传送带）＋R4（死屏/不可感知）。

## 1. 产品一句话

玩家设计一次生产安排，基地就持续执行它——玩家离开决策界面的每一分钟，基地都在产出，等待期从死屏变成"看着自己的系统运转"。

## 2. 玩家旅程（目标体验）

- **下达循环单**：玩家在采矿面板勾选「自动续作（至余量 50 停）」提交一次，机器人持续开采运输；在冶炼面板勾选「队列不足自动补 2 批」，加工槽不再跑空；
- **离开与回望**：玩家去扩建面板做下一个决策，5 分钟后回看：事件流滚动着"筑垒-2 第 3 批送达 / 望山-1 勘探完成"，仓库铜矿稳定增长；
- **看懂自己的系统**：生产总览顶部一行速率（"铁矿 +2/分 · 铁料 +0.8/分 · 储能净 -0.1/分"），瓶颈环节高亮（"冶炼排队 3 单——最慢一环"）；每个工程卡有预计剩余时间；
- **中途改向**：玩家改主意→暂停循环、改批数、换优先级，系统正确响应且说明结果（"循环已暂停：铁矿余量到达 50"）——**指挥权始终在玩家手里，自动化只是执行者**。

## 3. 功能清单

| # | 功能 | 产品描述 |
|---|---|---|
| M2-1 | 工单循环模式 | 下单可选「完成后自动续作」（可设批数上限或余量停点）；资源不足**明确暂停并说明**（绝不静默丢单——v1.0.2 教训） |
| M2-2 | 采集策略 | 勘探完成的矿点可设「持续开采」（系统自动拆批、复用上次编队）；矿点面板显示当前策略与一键停 |
| M2-3 | 队列保持 | 有排队工单时编队不遣散；全部队列空才回"待命" |
| M2-4 | 速率与瓶颈面板 | 生产总览：每资源"产出/消耗/净额 每基地分"；瓶颈=当前排队最久环节，高亮＋一句人话解释 |
| M2-5 | 预计剩余时间 | 工程卡与工单卡显示"预计剩余 ≈N 基地分"（关闭历史 D001 残余） |
| M2-6 | 活的等待期 | 任务卡分批进度＋下一批倒计时；事件流默认展开为底部滚动区（v1.0.3 已建事件历史，本批做呈现） |
| M2-7 | 建设回响 | 设施建成后地图行即反映新职能外观（最小版：状态与职能文案变化＋命名差异） |

## 4. 数值草案

自动续作批数上限 ≤10/单；"余量停点"最低值由矿点储量推导；瓶颈判定=队列等待时长最长者（阈值探针定）；速率数字的更新节奏跟快照轮询（5s）。

## 5. 验收标准

1. 玩家离开决策界面 5 分钟（页面开着），基地自行完成 ≥2 项生产（含一次跨环节：采矿→送达→冶炼入仓）；
2. 中途改向：暂停/改批/换优先级全部正确响应且界面说明结果；
3. 资源不足时循环工单暂停并给出原因，零静默丢失（对账：提交数=完成+在队+已说明暂停）；
4. 速率/瓶颈面板与实测一致（探针脚本对照）；工程预计剩余误差 ≤20%；
5. 盲玩代理能自主发现并使用循环模式（无提示）；
6. **用户本人试玩签字**：等待期"有东西可看"、感到"基地是我的系统在转"；
7. 回归卡：幂等重放、防重放收据、事件历史、账本诚实。

## 6. 非本批范围

跨设施物流网/蓝图全托管（明确砍——"持续作业"是终点不是起点）；勘探文字回报（M3）。
