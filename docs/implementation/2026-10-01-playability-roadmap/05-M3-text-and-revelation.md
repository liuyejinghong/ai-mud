# M3「文字与揭示」产品需求

> 本文件为 2026-10-01 历史方案；2026-10-03 起旧 M1–M4 停止默认实施，正文保留供对照；当前入口见 [../2026-10-03-2d-transition/README.md](../2026-10-03-2d-transition/README.md)；其中经外部审查证伪或退役的表述（如 90 秒日落、离线昨夜战报、强制受损验收、五次勘探随机硬验收）以 [../2026-10-03-2d-transition/closeout-report.md 处置台账](../2026-10-03-2d-transition/closeout-report.md)为准（该台账由收尾执行者创建）。

版本目标：1.3.0。前置：M2 签字。来源：诊断 R5（假探索三连）＋R2 完整版（取舍呈现）＋R8 叙事部分。

## 1. 产品一句话

让这个文字游戏的文字值得读：勘探揭晓有惊喜有意外，事件流是有人味的战报，取舍摆在玩家面前而不是藏在配方背后。

## 2. 玩家旅程（目标体验）

- **勘探是揭晓，不是换标签**：派望山-2 去北坡磁异常——2 基地分后读到一段场景文字（"望山-2 在磁异常北坡停了三小时。返航时货斗里除了铁矿样本，还有半块烧蚀的旧卫星外壳。"），储量揭晓带方差（这次 240，下次别的矿点可能 130），偶有意外（富矿脉 +50%、伴生铜矿、或一片什么都没有的风化层——不影响主线，只改数字与故事）；**风味地名保留**（北坡磁异常还在那，"铁矿 余 240"是它的第二行而不是它的替换）；
- **事件流是战报不是工单**："驮运-4 顶着暮色把第 4 批铁矿运进仓库。储电 2.1/5.0，够撑到日出。"——信息密度不变（对象＋数量＋时间），句式有场景；
- **取舍可见**：扩建面板并列三选项时，"机会成本"一行明示（"选第二加工槽：结构件 4→0，扩建位 B 的阵列要等下一轮铁料"）；产线面板呈现备件双路线的真实差（"路线甲：铁料+铜料→备件×2，耗矿 50%；路线乙：铁料→备件×1，耗矿 25%——你现在的矿量只够养一条"）。

## 3. 功能清单

| # | 功能 | 产品描述 |
|---|---|---|
| M3-1 | 矿点 description 字段 | schema 矿点加描述字段（**全路线唯一 schema 变更，须单列 Architecture Policy Change 往得用户确认**）；揭示后地名与资源标签并列呈现 |
| M3-2 | 储量方差 | 勘探揭晓储量区间随机（草案 120–280）；同种矿不同矿点差异明显 |
| M3-3 | 意外池 | 勘探小概率意外事件（富矿/伴生/风化层等 3–5 种），概率 ≤20%、无重复刷收益（同一矿点意外一次性） |
| M3-4 | 揭晓场景文案 | 每矿点 2–3 句场景文字（两矿区不同文案库）；以机器人名册指代 |
| M3-5 | 事件流叙事化 | 完工/送达/交付/夜报等事件文案升级为场景句式（信息密度不减）；文案模板按情境区分（晨/昏/夜不同句式池） |
| M3-6 | 取舍呈现 | 扩建面板"机会成本"行；产线面板备件双路线吞吐差并列 |
| M3-7 | 内部 ID 净化 | 工单编号改人类可读短名（"工单 №4-冶炼铁料"），"解锁能力：warehouse"等本地化（捎带关闭遗留 P2） |

## 4. 数值草案

储量方差区间 120–280；意外概率 15%（其中富矿 5%/伴生 5%/风化层 5%）；文案量估算：2 矿区×3 变体＋6 事件类型×3 情境 ≈ 60–80 条场景句（内容包承载，P 握手）。

## 5. 验收标准

1. 勘探 5 次 ≥3 种不同结果（含 ≥1 次意外）；盲玩代理能复述最近一次揭晓的文字内容（证明读进去了）；
2. 风味地名在揭示后仍在界面可见；
3. 同一存档两条扩建路线的机会成本在同屏可比；
4. 事件流场景句信息密度不降（对象/数量/时间三要素齐全——自动断言）；
5. schema 变更走完 Architecture Policy Change 且用户已确认；contentVersion bump；旧档不受影响（回归卡）；
6. **用户本人试玩签字**：揭晓时刻"值得看"、战报"有人味"。

## 6. 非本批范围

隐藏关卡式秘密设计（全信息经营是正当体裁，本批只修"揭晓瞬间"）；共在层（M4）。
