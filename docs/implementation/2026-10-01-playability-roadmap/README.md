## 独立外部审查（2026-10-03）

[审查报告：诊断、重建路线与玩法方向](../../reviews/base-operations/2026-10-03-external-playability-review/report.md)已单独存档，固定审查基线为 `c6bd33e416adfe186fd1cd22013bbfbd22bc7cae`。报告保留三项任务、R1–R8 裁决、置信度、源码依据与可证伪的验证方法。

审查建议：**当前 M1 不应原样冻结实施**。首要待澄清项为时间换算（15:00→18:00 在 ×2 下为 90 真实分钟，不是 90 秒）、首夜三路线可行性、离线暂停与夜报一致性、无损部署与强制受损验收冲突，以及首笔收入是否打开有用的新选择。审查另建议将最小持续作业与关键反馈纳入同一经营短切片，并前移真人验证。

本节只提供审查入口；下文保留原方案用于对照，**不表示路线已被自动重写、建议已成为实施合同或像素化已获授权**。审查没有新一轮线上试玩，不以静态分析代替真人可玩性签字。后续批次需先处理这些审查意见，再按既有授权纪律推进。

## 目标

把《余电》从「经营题材的单机派单工单系统」改造为**玩家想坐下来玩的游戏**：新档首小时有身份、有选择、有第一次日落危机、有第一笔收入；基地在玩家离开决策界面时自己运转；等待期有东西可看；文字有回报。验收定义不是"功能存在"，是本文 02 号文档的**可玩性验收标准**——最终裁判是用户本人试玩。

## 三方向 → 里程碑映射（为什么不是三条并行线）

| 诊断方向 | 主诉 | 落进 |
|---|---|---|
| C 重立核心循环 | 首小时没有欲望、没有张力 | **M1 第一个游戏日**（时序上必须最先：它重排开局时钟与引导结构，是其他一切的地基） |
| A 把经营做完 | 不像经营：无自动化、无收入、被代答、不可感知 | **M2 基地自转**（自动化＋可视化）＋收入端提前进 M1 |
| B 把 MUD 做成 | 不像 MUD：无身份、无回响、无探索回报 | **M3 文字与揭示**（叙事层）＋ **M4 世界与共在**（深层，可选后置） |

合并依据：压测证明 A 与 C 共享交叉根因（代答＋死屏），B 的叙事回报依赖 M1/M2 建立的事件流与循环基础；三线各自独立做会互相踩同一批文件（landing-release、LandingShell、事件流）。

每批附带：P2 打磨捎带清单（内部 ID 泄漏、D001 工程预计剩余等，见 01 号文档第 9 节）。

## 纪律（每批相同）

1. 用户指定批次 → **P 冻结**：public 合同、schema/字段归属、文件所有权、数值探针 → A/B 并发（独立 worktree）→ Q 独立验收（回归卡＋盲玩代理无提示通过）→ 用户本人试玩签字 → 统一发版。
2. 可玩性验收**由用户本人执行**：AI 代理只验功能与无提示可发现性；"是否变好玩"的最终判定归用户，任何里程碑不得以代理验收代替。
3. 版本与兼容：每批 bump PRODUCT_VERSION；触及 schema 的批次（M3 矿点字段）相应 bump schemaVersion 并**单列 Architecture Policy Change 征得确认**；landing-release.ts 的经济字段变更按其文件头要求走 P 握手。
4. 发版照既有 runbook（合并 PR → VPS 重建 → /health → 线上回归卡）。

## 非目标（本轮明确不做）

- 像素表现期（v1.1 仍 DESIGN_ONLY）；
- 通用工作流/脚本平台、微服务、权威 DuckDB；
- 真人聊天室/排行榜（共在层走 AI 代理填充路线，且后置）；
- 新货币系统（复用已验证的 credits）；订单防套利规则沿用 v1.0.0 教训（订单标的为本地产部件，不收可直接外购的原材料）；
- 不推翻已验证的引擎资产：诚实账本、租约/时钟隔离、事件历史、幂等命令、防重放收据全部保留复用。
