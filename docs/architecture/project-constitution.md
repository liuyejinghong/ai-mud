# 项目级架构约束

版本 3.0 / 2026-09-18；状态 PROPOSED。用户批准后作为后续增删功能的设计约束；本 PR 不实施运行时或 CI。不存在“只靠本文就永远不会腐化”的保证，必须有检查、测试、审查和小步迁移。

## 1. 固定决策与可变部分

短期固定：服务端权威、模块化单体、显式事务、事实/叙事分离、供应商和 renderer 可替换、独立验收。

可演进：规则数值、任务内容、模块能力、存储形状、传输与部署。变更必须先说明玩家价值和影响，不能以“架构不允许”为由永久冻结玩法；也不能以赶需求为由绕开约束。modularity.md 管模块封装，target.md 管运行/一致性语义。

## 2. 项目不变量（PC）

| ID | 必须保持 | 如何证明 |
|---|---|---|
| PC-01 权威 | 客户端、模型、文案都不能直接成为世界事实 | 越权请求/模型伪造事实的拒绝测试；接口能力审查 |
| PC-02 归属 | 每种可变事实有唯一写所有者，现有混合表按列定义 | 数据归属清单、所有写路径清单、SQL适配审查/故障测试 |
| PC-03 封装 | 跨模块只能用登记的公开 API，不读写 peer internal/repo | import/export图、公开声明扫描、编译失败探针 |
| PC-04 依赖 | 业务依赖有向无环；未声明边默认禁止 | catalog图检查、源码/注入依赖图、非法依赖探针 |
| PC-05 原子 | 一次业务变化的资产/义务/必要事实/收据一起提交 | 真PG逐阶段故障注入、跨模块回滚 |
| PC-06 重试 | 相同命令不重复产生效果；不同payload同key冲突 | 双提交、并发、超时重试、旧epoch响应测试 |
| PC-07 时间 | 真实时间/模拟时间明确；调度频率不改变应得结果 | Clock注入、不同唤醒/重启序列对照 |
| PC-08 表达 | 事实生成文字/动画，规则不解析显示文本 | 改语言/formatter不改规则结果的测试 |
| PC-09 模型 | 模型I/O在事务外，超时/预算耗尽有降级与迟到保护 | provider mock与真实adapter分层测试；未测不启用 |
| PC-10 可见 | 玩家只能读到有权知道的事实；不能把全库塞上下文 | 作用域/受众合同、跨账号/NPC记忆泄漏测试 |
| PC-11 兼容 | 公开协议、事件、内容、存档有版本/迁移或显式拒绝 | 新老payload/存档/未知枚举/重复迁移测试 |
| PC-12 退出 | 功能可停用、待执行工作可终止、预留/义务有归宿 | feature-off、退出、重置、退役演练 |
| PC-13 有界 | tick、模型并发、队列、重试、缓存/日志保留都必须有上限 | 超载/超时/积压观测，不虚报未测容量 |
| PC-14 证据 | 静态、mock、真PG、E2E、真人试玩、模型实测分开 | exact commit与实际命令/环境/NOT_RUN记录 |
| PC-15 最小化 | 先用现有领域与能力；无真实调用者不造万能抽象 | spec说明复用/新建理由；架构例外独立审查 |
| PC-16 护栏自身 | 不能靠改allowlist/删测试/标无测试通过让新增违规消失 | 基线diff、负例自测、门禁配置与业务改动分别审查 |

PC-02 的静态检查不宣称能证明任意动态 SQL 安全；对允许的 schema 访问和明确 `.set` 写法建立可分析子集，无法分析的 raw SQL 必须精确登记并审查。保留真实约束和 PG 测试作为最终证据。PC-13 的预算阈值在实际基线后设定，未测不能承诺上千NPC/并发。

## 3. 每次变更的入口

用 `change-spec-template.md` 写最小规格：玩家结果；主所有者；参与模块；新增/改变公开 API；前置条件/作用域/锁/权限；正常/失败/重试/旧版本；资产来源与退出；验收 ID。

简单本模块内部修复可用 PR 正文精简填写，不为一行改动另写十页 spec。跨模块合同、数据写归属、事务、权限、存档格式、世界时间和网络语义变更必须有单独规格或 ADR。实现模型不能自己扩大本轮授权。

新模块必须说明：现有模块不能合理容纳的责任、自己拥有的生命周期/数据、最小 API、消费者、允许边、迁移/停用方式。只有名词、没有独立行为和状态的内容不成为模块。禁止新建十个未来占位模块证明“扩展性”。

## 4. 审查顺序

1. 先审玩家需求与模块归属，再审合同/事务/失败，再写实现计划。
2. 开发优先补合同测试和失败用例，逐条迁移真实调用，移除旧路径；空壳接口不算收敛。
3. 独立审查不能只看是否符合新目录；必须追踪真实命令至数据库提交及客户端反馈。
4. 仅在精确提交的相关验证通过后标工程完成。玩法与模型效果用各自证据验收。

AI 作为实现者可以提交修正规格提案，但不能在实现时悄悄重定义余额归属/新增允许依赖/降低验收阈值。约束文件或门禁变更须在 PR 单列 Architecture Policy Change，并由维护者或独立审查确认；“另一轮模型说可以”不是已经确认。

## 5. 变更种类与门槛

| 变更 | 最小门槛 |
|---|---|
| 内容数据 | schema/引用/可达性/规则范围/旧存档；明确没有新增可执行脚本 |
| 模块内部实现 | 本模块测试 + 公开合同 + 边界扫描 |
| 跨模块能力 | 消费者合同 + 集成测试 + 事务/作用域/依赖变更审查 |
| 资产或义务 | 真PG并发/回滚/幂等/来源/退还/非负与账本核对 |
| 模型适配 | 原生输出合同 + 不可信输入 + 超时预算 + 真实与mock证据分离 |
| renderer/传输 | 同一状态投影等价 + 旧响应/重连/权限测试 |
| 模块退役 | 关闭新命令、清理在途、释放预留/托管、消费者替换、兼容/备份演练 |

## 6. 退役协议：停入口，不丢义务

示例退役一个打造模块：禁止新开工 → 列出现有工单与材料预留 → 按已承诺合同完成或取消退款 → 等待在途提交结束并记录结果 → 移除消费者/事件订阅 → 数据只读兼容/迁移 → 最后删代码和表。

不能关闭 feature flag 后让已有任务永远卡住，也不能删除任务后顺便丢掉托管。重置世界是独立维护用例，不能被模块级“卸载”偷偷调用。没有强制要求支持在线热插拔。

## 7. 架构债迁移纪律

只允许在确切基线登记已有违规，记录 ruleId、source、target、symbol/字段、理由、负责人、修复任务、到期版本/删除条件。禁止 `modules/**`、某整个包、全部测试等宽泛豁免；源文件增加新违规不可因已在名单中而通过。

迁移期间对新增代码/新依赖立即失败，对已确认legacy精确豁免；迁移一个调用链就删除对应豁免。严格无环校验先针对目标图与已迁移子图，legacy实际循环登记为债务，不能把整个仓库标成“不扫描”。架构基线完成时关键旁路清零，非关键剩余项必须明确列为尚未完成，不能宣称全仓严格通过。

## 8. 自动化不是文档口号

计划新增 `pnpm arch:check`（命名可在MOD-02落地时冻结），至少包含路径解析/公开入口/允许边/循环/声明泄漏/归属覆盖，以及违法负例自测。当前仓库并没有因为此PR而获得这个命令；不得把未创建脚本写进“已通过”证据。

推荐复用 dependency-cruiser 做模块解析/图检查，固定开发依赖版本；针对本仓边界做薄规则，不另造通用架构平台。包级 exports 与 TypeScript 构建引用是辅助，不替代路径和SQL归属检查。实际工具若无法处理某种别名/动态导入，必须明确禁止该写法或补测试，不能静默跳过。

CI中必须有实际失败的红色探针证据：错误deep import、type-only循环、间接export、跨域写入、provider获取DB、前端导入服务端秘密等。分支保护/required checks 属于仓库设置，本轮未配置；只有用户授权并配置成功后才可声称无法绕过合并。

## 9. 不为将来复杂而现在复杂

不新增通用CommandBus、反射式DI容器、跨模块HTTP、DSL、全量事件溯源、动态插件loader或分布式Saga。确有新需求时用ADR记录触发证据、替代方案、迁移成本与失败语义，不用“可能有一天”作为开工理由。

复杂玩法可增加，复杂依赖不自动增加。模块数量、接口数、文件行数不作为健壮性成绩；关键看增加一个玩法是否需要修改不相关模块内部，删除一个玩法是否破坏旧义务，以及故障是否被限制在明确边界。
