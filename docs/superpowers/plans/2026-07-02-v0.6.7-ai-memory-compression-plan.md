# v0.6.7 AI Memory Compression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Replace the current template-only NPC memory compression with a bounded AI compression path while preserving evidence levels and all game-authority boundaries.

**Architecture:** Add a structured memory-compression prompt/parser in `packages/ai-prompts`, expose it through `AiOrchestrator`, and inject an optional compressor port into `NpcMemoryService`. The memory service still owns grouping, retention, evidence-level calculation, fragment creation, and compressed markers; AI may only return a short summary string. If AI is disabled, unsafe, or unavailable, compression falls back to the existing deterministic template.

**Tech Stack:** TypeScript, Vitest, existing `AiProvider`, existing `NpcMemoryService`, existing `ai_call_logs`, Fastify route wiring.

---

## Scope Check

This version includes:

- AI prompt/schema for compressing a batch of NPC memory summaries into one short fragment.
- Safety parser that rejects OOC text, reward promises, rule changes, and evidence-level changes.
- `AiOrchestrator.compressNpcMemory`.
- Optional `NpcMemoryCompressorPort` in `NpcMemoryService`.
- AI call audit logs with purpose `npc_memory_compression`.
- Version bump and Chinese release note.

This version does not include:

- AI deciding which memories are compressed.
- AI changing `dialogue_claim` into `system_verified`.
- AI changing memory importance, source IDs, character IDs, assets, tasks, rewards, relationship values, or favor scores.
- Vector retrieval, cross-NPC memory sharing, or player-visible memory UI.
- New database tables or migrations.
