# v0.8.0 双底盘执行包

> **给执行代理：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐项执行。步骤使用 checkbox (`- [ ]`) 跟踪进度。

**目标：** 在不新增完整刷宝玩法的前提下，完成 v0.8 的两块底盘：资产/装备统一写路径，以及客户端 HUD/输入/同步底盘，为 v0.8.1 的刷宝垂直切片提供稳定基础。

**架构：** 后端把物品、装备、库存、掉落、装备实例、账本收敛到 `packages/content`、`packages/game-rules` 和唯一 `ItemService`；前端把键盘输入、弹层、同步轮询、事件反馈收敛到统一框架。`/game/sync` 必须是纯读端点，增量游标来自 `sync_events` 投影表，世界推进仍只走 tick/runtime。

**技术栈：** TypeScript monorepo, pnpm, Fastify, Drizzle/PostgreSQL, React/Vite, Vitest, Playwright, `packages/content`, `packages/game-rules`, `packages/shared`。

---

## 0. 执行方式

沿用此前约定的开发方式：

1. **先执行包，后代码。** 本文是 v0.8.0 的执行包；代码开发不得跳出本文范围。
2. **分模块并行。** A 测试/迁移底座、B content/rules 初稿、C 前端输入底盘可以并行；B3/C2 这类依赖数据库或 DTO 的任务必须等前置任务稳定后再做。
3. **每包独立提交。** 每个任务至少一个 commit，commit 使用仓库 Lore trailer 规范。
4. **每包独立验收。** 任务完成必须贴对应测试输出，不允许只靠手测。
5. **v0.8.0 范围刹车。** 若 v0.8.0 超过 2 周，优先保 A1、B3、C2、C1；Panel Registry 深化、ErrorBoundary 细分、开发态事件过滤顺延。

推荐执行顺序：

1. 先做 A1，建立 Postgres 集成测试底座。
2. 并行做 B1 和 C1。
3. 做 B2、B3、C2。
4. 做 B4、C3。
5. 做 F1 总验收与中文发布说明。

不建议现在直接进入 v0.8.1。v0.8.1 的升级/掉落体验依赖 `ItemService`、`sync_events`、反馈层和 DTO 稳定。

## 1. 总范围

### 本版必须完成

- Postgres 集成测试底座：空库迁移、种子、基础冒烟、资产/铜币断言。
- content 统一物品注册表：food/material/ore/equipment，装备定义、词缀池、内容校验。
- game-rules 资产规则：堆叠、装备校验、词缀 roll、确定性掉落。
- server 唯一资产写路径：`ItemService`、`item_instances`、`item_ledger`。
- `sync_events` 投影表与 `/game/sync` v1 纯读端点。
- 前端输入上下文栈、HotkeyRegistry、ModalManager，结构性防止弹窗打开时移动。
- API 错误码/401 统一处理。
- v0.8.0 中文发布说明与验证证据。

### 本版不做

- 玩家交易、装备上市场交易。
- NPC 自动穿戴装备。
- 传奇/特效词缀/强化洗练。
- v0.8.1 的完整升级掉落体验。
- 旧矿坑、zone 注册表、遭遇冷却。
- 大厅聊天、在线列表、排行榜、WebSocket。
- AI 新 purpose 或 AI 新权限。
