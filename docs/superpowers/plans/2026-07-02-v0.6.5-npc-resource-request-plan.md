# v0.6.5 NPC Resource Request Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Let players ask nearby dialogue NPCs for small real resources while the server rules decide whether the NPC can and will give them.

**Architecture:** Add reusable request parsing and decision rules in `packages/game-rules`, then use them inside `DialogueService` before the normal AI dialogue path. If a request is recognized, the service mutates only real NPC/player inventory or copper, writes deterministic NPC dialogue, and records a `system_verified` memory; if it is not recognized, existing AI dialogue continues unchanged.

**Tech Stack:** TypeScript, Vitest, Fastify services, existing NPC/player repositories, existing NPC memory service.

---

## Scope Check

This version includes:

- Parsing simple player requests for `wild_berry`, `iron_ore`, or a tiny copper favor.
- Rule-owned decision based on NPC inventory/copper, reserve requirements, and relationship familiarity/trust.
- Real transfer from NPC inventory/copper to player inventory/copper only when rules grant the request.
- Deterministic NPC acceptance/refusal messages for recognized resource requests.
- `system_verified` NPC memory for granted and refused requests.
- Web state refresh after dialogue sends so granted resources appear in inventory/money.

This version does not include:

- AI deciding whether to give assets.
- AI creating items, money, experience, or equipment.
- NPC proactive gifts.
- Complex bargaining, pricing, loans, debt, or reputation economy.
- New database tables or migrations.
