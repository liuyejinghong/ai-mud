# v1.0 产品收口执行包

**目标：** 不增加新系统宽度，用现有探索、自动战斗、掉落、装备、采集、经济和 NPC 交互构成可理解、可追求、可持续 10 天左右的封闭内测内容。

**前置门禁：** `v0.10.7` 已发布；AI 意图、fallback、世界仿真和资产守恒全部通过。

**架构：** 内容仍由 `packages/content` 定义，成长/掉落/首件保障仍是 `packages/game-rules` 纯规则，服务端只执行并记账；客户端只根据 `/game/sync` 展示服务端事实，不复制毕业、掉率或引导判定。

---

## 1. 产品完成定义

### 1.1 首 15 分钟

计时起点是玩家提交注册，终点是玩家在装备详情中看到第一件战斗掉落装备。目标路径：

```text
注册 -> 登录 -> 创建角色 -> 进入腐林 -> 移动 -> 自动战斗
-> 获得首件掉落装备 -> 打开详情 -> 对比并装备
```

门禁：

- 自动化真实链路必须稳定完成；
- 3 个从未接触项目的全新测试账号中，至少 2 个无需口头指导在 15 分钟内完成；
- 键盘和鼠标两套路径都能完成；
- 新手引导只说当前目标和世界内信息，不显示开发验收术语；
- 玩家不能因为随机掉率在第一件装备之前无限刷。

### 1.2 内测毕业线

首批内容毕业定义：

- 等级达到 10；
- weapon、chest、head、accessory 四个槽位均装备 epic；
- 击败旧矿坑头目并至少获得一件头目独占装备底子；
- 玩家仍可以继续追求更合适的词缀组合，但不以“永远刷不完”掩盖内容不足。

目标分布：

| 玩家类型 | 模拟行为 | P50 毕业时间 | 额外约束 |
| --- | --- | --- | --- |
| 休闲 | 每日 1 小时 | 10-14 天 | P80 不超过 21 天 |
| 重度 | 每日 3 小时 | 4-6 天 | 不得 3 天内稳定毕业 |

模拟只能用于数值核算；最终留存判断仍由真人内测反馈决定。

## 2. 范围

### 2.1 包含

- 两张有效野图：腐林、旧矿坑；空的灰烬哨路不计入内容量，也不作为新手可见入口。
- 四槽装备完整掉落来源。
- 不少于 5 个普通/强化怪物配置和 1 个旧矿坑头目；新增内容必须只改 content 即可接入通用区域/战斗/掉落路径。
- 至少 2 个头目独占装备底子或独占词缀来源，优先增加追求深度。
- 10 级内测等级上限和匹配的 XP 曲线。
- 一次性首件战斗装备保障。
- 新手流程、键位帮助、状态解释与可用性收口。
- 基于实际规则的成长模拟和三组参数对比。

### 2.2 不包含

- 第三张正式地图、完整副本、任务剧情线、玩家交易、生活职业扩展；
- 新战斗操作模式，战斗继续自动执行；
- 为拖长时长而增加日次数硬上限、强制等待墙或不可解释的商店库存上限；
- 通过降低所有掉率让玩家“理论上能玩很久”。

## 3. 内容与规则合同

### 3.1 内容完整性

`packages/content` 必须通过架构测试保证：

- 每个装备槽至少有 2 个可掉落装备底子；
- 每个装备底子至少有一个真实 encounter 来源；
- 每个正式 zone 至少有 2 个可重复遭遇或 1 个遭遇 + 1 个头目；
- 所有 monster 的掉落 item ID 存在，装备 slot 与 affix pool 可用；
- 动物不掉金币和不符合来源的武器；装备来源必须能从怪物身份或场景解释；
- `ASH_WATCH` 若继续作为架构测试 zone，必须标记 `playable: false`，不能进入玩家可用入口。

### 3.2 首件装备保障

不新增独立 milestone 表，优先复用 `item_ledger` 的 canonical 历史事实：

- repository 查询角色是否已有 `reason="action.combat.loot"` 且 `item_instance_id IS NOT NULL` 的 grant；
- 若没有，第一次胜利的合格遭遇在正常掉落之外保证一个 content 指定的 uncommon 装备；
- 保障装备仍使用 `rollEquipment`、确定性 seed、`ItemService` 和 item ledger；
- 逃跑、战败、取消、重复结算不触发；
- 保障只针对第一件战斗掉落，不保证槽位毕业或高稀有度。

如果实际实现证明 item ledger 无法在同一事务中可靠回答该问题，必须先报告再考虑新增 milestone；不能默认增加第二事实来源。

### 3.3 等级与 XP

- 内测硬上限设为 10，并作为 `rulesetVersion` 合同；未来版本通过 bump 提升，不在 service 内写特例。
- XP 继续只来自规则认可的战斗/固定任务来源。
- 1 级玩家在新手路径内可以击败首个腐林遭遇；旧矿坑头目要求明显成长，但不得依赖手动释放技能。
- 同级旧内容在玩家变强后战斗耗时自然下降，继续由攻击、防御、HP、敏捷/ATB 推导，禁止预设固定挂机时长。

### 3.4 掉落与毕业

- 装备稀有度继续由确定性 `rollRarity` 生成；参数必须由模拟报告决定。
- 头目独占深度通过 content drop table 或明确的 source tag 实现，不在 GameService 写 encounter ID 分支。
- 不为毕业直接发装备；首件保障之外，毕业仍来自战斗掉落。
- 模拟若显示全紫毕业过慢，先调整高难遭遇的掉落质量或头目深度；若过快，先调整 epic 权重和遭遇节奏，不先增加新地图。

## 4. 成长模拟合同

新增 `pnpm verify:content-progression`，使用当前 content 与 game-rules，固定随机种子批量运行至少 10,000 个虚拟角色。

模拟策略是显式、版本化的玩家行为模型，不冒充真人：

- 新手先完成腐林路径；
- 满足推荐战力后转向旧矿坑；
- 自动装备评分更高的同槽装备；
- 在饥饿、耐久和受伤约束下购买食物、修理或恢复；
- 休闲模型每日最多 60 分钟，重度模型每日最多 180 分钟；
- 所有战斗时间、掉落、XP、耐久和价格调用生产规则函数。

报告至少输出：

```text
sampleCount
parameterSetId
firstEquipmentMinutes p50/p95
level10Days p20/p50/p80
fullEpicDays p20/p50/p80
bossClearDays p20/p50/p80
dropsBySlotAndRarity
injuryCount
foodConsumed
repairCopperSpent
marketCopperFlow
graduationRateAtDay3/7/10/14/21
```

三组候选参数必须只通过 content/rules 配置差异表达：`conservative`、`balanced`、`generous`。最终选择和拒绝理由写入报告，禁止把调参分支留在运行时代码中。

## 5. 新手引导合同

### 5.1 引导步骤

现有采集型引导改为事件驱动的核心玩法引导：

1. 选择腐林并离开哨站；
2. 使用 WASD 或地图方向按钮移动；
3. 到达遭遇并开始自动战斗；
4. 查看战斗进度/结果；
5. 打开首件掉落装备详情；
6. 比较并装备；
7. 回城后提示集市、NPC 和采集属于后续自由活动。

### 5.2 状态来源

- 引导只根据角色位置、current action、sync events、inventory/equipment 和 server available actions 推进；
- 不用包含“移动/获得”等中文文本的正则作为唯一事实来源；
- 本地存储只记录折叠/已读状态，关键完成度应能从服务端事实恢复；
- 引导步骤对应的按钮不可用时，不能继续要求玩家点击；
- 引导完成后不常驻占用主叙事区。

### 5.3 输入与可用性

- 键位说明从 `HotkeyRegistry` 生成，不另写一份静态键位表；
- modal/text-entry 打开时 WASD 继续结构性屏蔽；
- 所有关键操作同时有鼠标入口；
- 1440x900、1180x900、980x900 主流程无外层滚动；
- 390x844 允许降级为分区浏览，但状态、聊天、当前行动和主要按钮可用；
- 长 NPC 文本、装备词缀、玩家名和聊天内容不溢出容器。

## 7. Package B 验收标准

- 两张正式野图均有可重复的战斗与采集价值；
- 四个装备槽都有不少于两个真实掉落底子；
- 角色第一场合格胜利稳定获得一件 uncommon 装备，且不可重复利用；
- 休闲模拟 P50 10-14 天毕业、P80 <= 21 天；重度模拟 P50 4-6 天；
- 3 天毕业率不构成主流，且不是靠硬次数上限拖延；
- 新玩家无需口头指导即可看到并理解首件掉落装备；
- 键盘、鼠标、桌面和窄屏降级路径均可用；
- 新增内容不在 service 中制造区域/怪物专用分支；
- 7 天 NPC/经济模拟在最终内容参数下继续通过。

## 8. 停止条件

- 模拟器使用与生产不同的掉落、战斗、XP 或价格公式；
- 为达成 10 天目标引入每日出售上限、每日掉落上限等机器化限制；
- 首件保障绕过 `ItemService` 或账本；
- 需要新增第三张地图才能让毕业时间达标；
- 新手引导依赖日志文案变化而频繁失效；
- UI 为了展示全部功能重新变成页面瀑布流；
- 内容修改暴露引擎无法数据驱动新增 item/monster/zone，但仍用 service 特判继续堆。
