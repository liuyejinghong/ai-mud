# v0.6.3 Dialogue Task Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Let NPC dialogue reference real NPC demand tasks without allowing AI to create rewards, mutate assets, or bypass task rules.

**Architecture:** Keep `NpcTaskService` as the only authority for task creation, acceptance, completion, escrow, and inventory transfer. Add a read-only task context to dialogue targets and AI prompt input so NPCs can naturally mention real open or accepted tasks. The web client only displays hints and still calls task endpoints for all task actions.

**Tech Stack:** TypeScript, Fastify, React/Vite, Drizzle, Vitest, Playwright, existing `@ai-mud/shared`, `@ai-mud/ai-prompts`, and server module ports.

---

## Scope Check

This version includes:

- NPC dialogue targets can show whether the NPC has a real task available or already accepted by the player.
- Dialogue prompt context includes a short, read-only summary of that NPC's real tasks for this player.
- Prompt version increments so AI audit logs can distinguish task-aware dialogue.
- Frontend NPC list shows a task marker and short hint in the dialogue modal.
- Tests prove task context is read-only and does not create assets.

This version does not include:

- AI-generated task creation.
- Player asking NPC for arbitrary items.
- Relationship-based gifts.
- New task reward types.
- New demand categories.
