# v0.4.1 Durability And Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the first equipment durability and repair execution loop inside the `v0.4.x Economy World` track.

**Architecture:** Add server-authoritative equipped item instances with current/max durability. Pure rules calculate durability loss, effective stat ratio, and repair cost; the server persists equipment, consumes player copper plus player-held basic iron ore, and writes events; the web client only displays returned equipment state and calls repair endpoints.

**Tech Stack:** TypeScript, pnpm workspaces, Fastify, Drizzle/PostgreSQL, React/Vite, Zod, Vitest, Playwright.

---

## 1. Scope Boundary

This is `v0.4.1`, not `v0.5`.

Included:

- Equipped item DTOs with durability.
- Initial starter equipment for new characters.
- Repair quote based on real equipped item durability loss.
- Repair execution for one item and all equipped items.
- Repair consumes copper and `iron_ore` from the player inventory.
- Repair cannot run while an action is active.
- Repair can only run in Blackpine Outpost.
- Combat causes equipment durability loss on settlement.
- Equipment at zero durability keeps only 20% of its stat value.
- Web UI shows equipment durability and repair controls.
- Chinese release note.

Excluded:

- Hunger and food consumption.
- Tool durability for gathering.
- NPC blacksmith personal inventory.
- NPC wages or autonomous buying/selling.
- AI dialogue or AI tasks.

## 3. Data Model

Add `character_equipment` as separate item instances rather than adding durability to stackable `character_items`.

Reason:

- Stackable inventory items such as berries, meat, hide, and ore should remain quantity stacks.
- Equipment needs instance-level durability.
- Future gear quality, affixes, binding, item level, and source history belong on equipment instances.

Fields:

- `id uuid primary key`
- `character_id uuid references characters(id)`
- `slot text not null`
- `item_key text not null`
- `name text not null`
- `item_level integer not null`
- `attack_bonus integer not null default 0`
- `defense_bonus integer not null default 0`
- `max_durability integer not null default 100`
- `current_durability integer not null default 100`
- `created_at timestamptz not null default now()`
- `updated_at timestamptz not null default now()`

Initial starter equipment:

- `training_sword`, slot `weapon`, name `训练短剑`, item level `5`, attack bonus `2`, defense bonus `0`, durability `100/100`.
- `patched_leather_vest`, slot `chest`, name `缝补皮甲`, item level `5`, attack bonus `0`, defense bonus `2`, durability `100/100`.

## 5. Pure Rule Design

Add `packages/game-rules/src/equipment-rules.ts`.

Rules:

- Durability is clamped between `0` and `maxDurability`.
- Effective stat ratio is:
  - `1` when durability is above `0`.
  - `0.2` when durability is `0`.
- Combat durability loss:
  - weapon loses `2` durability per completed combat.
  - armor/chest loses `1` durability per completed combat.
  - no durability loss when escaping before combat settles.
- Gathering does not damage equipment in `v0.4.1`.
- Repair quote:
  - no repair needed when durability is full.
  - otherwise reuse `calculateRepairQuote` with actual loss ratio.

Functions:

```ts
export interface EquipmentDurabilityInput {
  currentDurability: number;
  maxDurability: number;
}

export function calculateDurabilityPct(input: EquipmentDurabilityInput): number;
export function calculateEffectiveStatRatio(input: EquipmentDurabilityInput): number;

export function applyCombatDurabilityLoss<T extends {
  slot: "weapon" | "chest";
  currentDurability: number;
  maxDurability: number;
}>(equipment: T[]): T[];

export function calculateEquipmentRepairQuote(input: {
  itemLevel: number;
  currentDurability: number;
  maxDurability: number;
}): RepairQuoteResult | null;
```
