# v0.6.6 Verified Memory Favor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Let verified player history influence NPC resource-request decisions without giving AI or raw dialogue memory asset authority.

**Architecture:** Extend NPC memory service with a small `system_verified` favor profile derived from trusted entries/fragments. Feed that numeric profile into the existing NPC resource-request rules so completed real tasks can satisfy the relationship gate, while repeated recent gifts cause refusal.

**Tech Stack:** TypeScript, Vitest, existing `NpcMemoryService`, existing `DialogueService`, existing game-rule kernel.

---

## Scope Check

This version includes:

- A `VerifiedFavorProfile` derived only from `system_verified` memories.
- Favor score from verified helpful acts such as completed tasks or救命-style system records.
- Recent grant count from verified NPC resource grants.
- NPC request rules can accept a player with low familiarity if verified favor score is high enough.
- NPC request rules can refuse repeated asks after multiple recent grants.

This version does not include:

- Trusting raw player dialogue claims.
- Letting AI rewrite favor scores.
- Long-term reputation economy.
- Complex gift cooldown tables.
- New database tables or migrations.
