# v0.6.1 NPC Memory Compression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让长期 NPC 开始拥有可追溯、可压缩、可检索的玩家交互记忆，并把压缩后的记忆接入后续 NPC 对话上下文。

**Architecture:** 记忆是服务端持久化状态，不由 AI 直接改写资产或关系数值。对话、赠与、交易、任务等事件先进入 `npc_memory_entries` 原始记忆表，服务端定期或按需把旧记忆压缩到 `npc_memory_fragments`，对话 prompt 只读取短摘要和少量相关碎片。首版压缩可以走模板压缩器，后续再接 DeepSeek 结构化压缩。

**Tech Stack:** TypeScript monorepo, Fastify, Drizzle ORM, PostgreSQL, Vitest, `@ai-mud/shared`, `@ai-mud/ai-prompts`, existing `DialogueService`, existing world runtime settlement.

## 0. 当前阶段判断

当前代码已经完成：

- `v0.5.0` 长期 NPC、NPC 移动、采集、买卖、吃饭、工资和后台仿真。
- `v0.5.1` NPC 世界按现实时间自动推进。
- `v0.6.0` AI 对话护栏层、DeepSeek/OpenAI-compatible provider、结构化 JSON 输出、安全兜底、AI 调用日志和玩家-NPC 轻量关系。

当前还没有完成完整 `v0.6.x AI Layer`：

- 没有长期记忆事件表。
- 没有记忆压缩和遗忘机制。
- 对话 prompt 只读取 `npc_relationships.shortSummary`，无法回忆具体事件。
- AI 任务、NPC 主动赠与、玩家索要物品都还没有规则链和资产托管。

因此下一步是 `v0.6.1 NPC Memory Compression`，不是 `v0.7 Admin And Simulation`。

## 1. Scope Check

本版本只实现“记忆基础设施”，不实现 AI 任务和赠与。

Included:

- 记忆事件 DTO 和压缩碎片 DTO。
- `npc_memory_entries`：细粒度短期记忆事件。
- `npc_memory_fragments`：压缩后的长期记忆碎片。
- `NpcMemoryService`：记录对话事件、压缩旧事件、检索对话上下文。
- 对话成功后写入记忆事件。
- 对话 prompt 中加入压缩记忆摘要。
- 模板压缩器：不调用模型也能跑通压缩和遗忘效果。
- 管理员只读查看最近 NPC 记忆，便于验证。
- 发布说明 `docs/releases/v0.6.1.md`。

Not included:

- AI 任务创建。
- AI 给奖励或 NPC 主动赠与。
- 玩家向 NPC 索要物品的资产裁决。
- DeepSeek 真实记忆压缩调用。
- 跨 NPC 共享记忆。
- 向量检索。
- 玩家可见记忆 UI。

## 3. Data Model

### 3.1 `npc_memory_entries`

Short-term raw memory events. These are small and factual.

```ts
export const npcMemoryEntries = pgTable(
  "npc_memory_entries",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    npcActorId: uuid("npc_actor_id").notNull().references(() => worldActors.id),
    characterId: uuid("character_id").references(() => characters.id),
    sourceType: text("source_type").notNull(),
    memoryKind: text("memory_kind").notNull(),
    evidenceLevel: text("evidence_level").notNull().default("dialogue_claim"),
    sourceIds: jsonb("source_ids").notNull().default([]),
    importance: integer("importance").notNull().default(1),
    summary: text("summary").notNull(),
    occurredAt: timestamp("occurred_at", { withTimezone: true }).notNull(),
    compressedAt: timestamp("compressed_at", { withTimezone: true }),
    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow()
  },
  (table) => ({
    npcOccurredAtIdx: index("npc_memory_entries_npc_occurred_at_idx").on(
      table.npcActorId,
      table.occurredAt
    ),
    characterNpcIdx: index("npc_memory_entries_character_npc_idx").on(
      table.characterId,
      table.npcActorId
    ),
    compressionIdx: index("npc_memory_entries_compression_idx").on(
      table.npcActorId,
      table.compressedAt,
      table.occurredAt
    )
  })
);
```

Allowed `sourceType` values in this version:

- `dialogue`
- `system`

Allowed `memoryKind` values:

- `conversation`
- `favor`
- `conflict`
- `trade`
- `task`
- `world_event`

`favor/trade/task` are reserved for later versions, but the type is defined now so the service API does not need a breaking rename when v0.6.2 adds AI tasks.

Dialogue-created memories must use `evidenceLevel: "dialogue_claim"`. Future `favor/trade/task` memories may only use `evidenceLevel: "system_verified"` when they are written by a rules service with source ledger, task, or inventory IDs.

Compressed long-term memory fragments.

Create `apps/server/src/modules/npc-memory/npc-memory.service.ts`:

```ts
const RAW_MEMORY_RETENTION_MS = 24 * 60 * 60 * 1000;
const HIGH_IMPORTANCE_RETENTION_MS = 7 * 24 * 60 * 60 * 1000;
const MAX_DIALOGUE_MEMORY_LINES = 4;
const MAX_DIALOGUE_MEMORY_CHARS = 500;

export class NpcMemoryService {
  constructor(private readonly repo: NpcMemoryRepositoryPort) {}

  async recordDialogueExchange(input: {
    npcActorId: string;
    characterId: string;
    playerName: string;
    playerMessage: string;
    npcReply: string;
    occurredAt: Date;
  }) {
    const summary = summarizeDialogue(input.playerName, input.playerMessage, input.npcReply);
    await this.repo.createEntry({
      npcActorId: input.npcActorId,
      characterId: input.characterId,
      sourceType: "dialogue",
      memoryKind: "conversation",
      evidenceLevel: "dialogue_claim",
      sourceIds: [],
      importance: estimateImportance(input.playerMessage, input.npcReply),
      summary,
      occurredAt: input.occurredAt
    });
  }

  async compressDueMemories(now: Date) {
    const cutoff = new Date(now.getTime() - RAW_MEMORY_RETENTION_MS);
    const entries = await this.repo.listUncompressedBefore(cutoff, 100);
    const compressible = entries.filter((entry) => {
      if (entry.importance >= 4) {
        return entry.occurredAt.getTime() <= now.getTime() - HIGH_IMPORTANCE_RETENTION_MS;
      }
      return true;
    });

    for (const group of groupByNpcCharacterKind(compressible)) {
      const summary = compressSummaries(group.entries.map((entry) => entry.summary));
      await this.repo.createFragment({
        npcActorId: group.npcActorId,
        characterId: group.characterId,
        memoryKind: group.memoryKind,
        evidenceLevel: weakestEvidenceLevel(group.entries.map((entry) => entry.evidenceLevel)),
        importance: Math.max(...group.entries.map((entry) => entry.importance)),
        summary,
        firstOccurredAt: group.entries[0].occurredAt,
        lastOccurredAt: group.entries[group.entries.length - 1].occurredAt,
        sourceEntryIds: group.entries.map((entry) => entry.id),
        compressionLevel: 1
      });
      await this.repo.markEntriesCompressed(group.entries.map((entry) => entry.id), now);
    }
  }

  async getDialogueMemoryContext(input: { npcActorId: string; characterId: string }) {
    const [fragments, recentEntries] = await Promise.all([
      this.repo.listFragments({ npcActorId: input.npcActorId, characterId: input.characterId, limit: 3 }),
      this.repo.listRecentEntries({ npcActorId: input.npcActorId, characterId: input.characterId, limit: 3 })
    ]);
    return limitMemoryContext([
      ...fragments.map((entry) => `记忆碎片：${entry.summary}`),
      ...recentEntries.map((entry) => `近期记忆：${entry.summary}`)
    ]);
  }
}
```

Helper rules:

- `estimateImportance` returns `3` when message mentions `救命`, `救了`, `送给`, `帮你`, `任务`, `欠你`; otherwise `1`.
- `summarizeDialogue` must truncate player message and NPC reply to 60 characters each.
- `compressSummaries` joins at most 5 short summaries and then truncates to 220 characters.
- `limitMemoryContext` returns at most 4 lines and 500 characters.
