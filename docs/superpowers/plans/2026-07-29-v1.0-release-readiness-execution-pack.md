# v1.0 发布就绪执行包

**目标：** 把通过本地功能验收的 `v0.10.7` 候选变成可部署、可恢复、可观测、能向 10-30 名朋友发码的 `v1.0.0`。

**前置门禁：** AI 原生闭环与产品收口包均已通过；内容和兼容版本被冻结；不再增加新玩法。

**架构：** 发布证据分为四层：聚焦合同测试、真实 PostgreSQL/浏览器链路、10 并发负载、7 天预发持续运行。每一层保护不同风险；测试通过不能替代部署和持续运行证据。

---

## 1. 发布完成定义

只有以下条件同时成立，才允许设置 `PRODUCT_VERSION="1.0.0"` 并发放激活码：

- 完整非 mock 玩家链路通过；
- 真实 DeepSeek 与模板 fallback 的 AI 意图路径通过；
- 10 并发玩家运行 1 小时无错误和资产异常；
- 隔离预发环境连续运行 7 天，无人工改库、补资源或重置；
- 世界重置、数据库备份和恢复各实弹演练一次；
- 管理员可以处理账号、激活码、公告、AI、经济和世界异常；
- 已知问题、反馈渠道、内测说明和首批激活码准备完成；
- 冻结候选 bytes 与所有报告对应，不用旧报告证明新代码。

## 2. 明确不做

- 不在本包继续调整核心玩法或新增内容；
- 不把本地开发 `docker-compose.yml` 当成生产部署方案；
- 不把加速 7 天模拟当成真实 7 天预发运行；
- 不把 mock Playwright 当成真实业务闭环；
- 不因为朋友内测就提交 API key、数据库密码或弱 `SESSION_SECRET`；
- 不实现复杂监控平台、Kubernetes、多区域部署或自动扩缩容；
- 不在没有目标服务器的情况下声称已经对外部署。

## 3. 真实 E2E 合同

### 3.1 玩家主链路

在每次运行创建的临时 PostgreSQL 数据库中，通过真实 HTTP 和浏览器完成：

```text
生成一次性激活码
-> 注册
-> 登录
-> 创建角色
-> 新手引导
-> 腐林移动
-> 自动战斗
-> 首件装备掉落
-> 查看/对比/装备
-> 采集
-> 回城
-> 市场卖出与买入
-> 修理装备
-> NPC 产生需求目标/任务
-> 接受并完成任务
-> 奖励、好感与可信记忆入账
-> 大厅聊天、在线列表、排行榜、掉落广播
-> 退出并重新登录验证持久化
```

### 3.2 AI 双路径

- 普通 CI/E2E 使用 deterministic fake 或 template fallback，不依赖公网；
- `pnpm verify:ai-intent -- --provider=deepseek` 使用真实 provider 做固定有限场景；
- 两条路径必须产生同一合法执行类型，但不要求选择和文案完全相同；
- E2E 断言最终数据库事实、账本、事件和玩家 UI，不断言模型逐字输出。

### 3.3 运营链路

独立 admin 测试覆盖：

- 批量生成激活码并作废未使用码；
- 禁用账号后 session 立即失效，恢复后可重新登录；
- 发布系统公告并在玩家同步流中出现；
- 查看 NPC、经济、账本、AI 预算和 world runtime；
- 世界重置保留账号/审计/激活码规则，重建世界后新建角色可玩。

## 4. 10 并发性能合同

新增无第三方负载框架依赖的 Node/TypeScript 脚本 `pnpm verify:load`。脚本使用 10 个独立账号/session 模拟真实客户端节奏：

- `/game/sync` 每 3 秒一次；
- presence heartbeat 使用客户端生产间隔；
- 少量聊天、移动、采集、战斗和市场 mutation；
- AI 对话单独限量，不作为 sync 延迟基线；
- world tick 保持启用；
- 先运行 `--duration=2m` smoke，再运行 `--duration=60m` release gate。

报告输出：

```text
commitSha
productVersion and compatibility versions
database identity hash (not credentials)
clients
duration
requestCount by route
statusCount
latency p50/p95/p99 by route group
sync payload bytes p50/p95
world runtime lag
database pool active/queued peak
AI calls/tokens/fallbacks
ledger drift before/after
negative asset violations
server 5xx and unhandled errors
```

首批内测门槛：

- HTTP/server 5xx = 0；
- 资产重复、负数、账本漂移 = 0；
- `/game/sync` p95 <= 100ms；
- 非 AI mutation p95 <= 250ms；
- sync p95 payload <= 128 KiB；
- world runtime 在测试结束后最多落后 2 个 tick，并能自动追平；
- 数据库连接等待队列不持续增长；
- 实际请求频率符合单轮询器设计，没有每个面板独立轮询。

若开发机噪声导致延迟超标，先记录机器与数据库条件，在目标预发主机复测；不得直接删除阈值。

## 5. 生产部署合同

### 5.1 可移植制品

在不知道最终云厂商的前提下，交付最小可移植容器方案：

- server 多阶段 Docker image；
- web 静态构建 image；
- 反向代理示例负责 HTTPS 终止和 `/api` 路由；
- production compose 示例只作为单机内测模板；
- PostgreSQL 可以同机私网运行或使用托管实例，但绝不公开数据库端口；
- schema migration 作为发布前一次性命令运行，应用进程不自动迁移。

创建文件：

- Create: `.dockerignore`
- Create: `deploy/Dockerfile.server`
- Create: `deploy/Dockerfile.web`
- Create: `deploy/web.conf`
- Create: `deploy/compose.production.example.yml`
- Create: `docs/deployment/production.md`
- Modify: `docs/deployment/database.md`

### 5.2 环境变量

生产启动前检查：

- `NODE_ENV=production`；
- `SERVER_HOST=0.0.0.0` 仅在容器网络内暴露；
- 唯一可信 `WEB_ORIGINS`；
- 随机且不少于 32 bytes 的 `SESSION_SECRET`；
- secure/httpOnly/sameSite cookie 行为；
- 真实 `DATABASE_URL`；
- `AI_PROVIDER=deepseek`、模型、超时、输出上限和日预算；
- world tick 启用且 max catch-up 有界；
- admin bootstrap 首次使用后按既有规则停用或轮换。

任何检查只输出是否通过和非敏感摘要，禁止打印 secret。

### 5.3 健康与就绪

- 保留轻量 `/health` 作为进程存活检查；
- 新增 `/ready`，验证数据库可达、迁移版本兼容、world runtime 未严重滞后；
- readiness 不调用 AI、不推进 world、不泄露数据库或内部账号信息；
- 部署完成必须核对返回的 product/compatibility 版本与冻结候选一致。

## 6. 备份、恢复与世界重置

### 6.1 数据库备份

交付使用 `pg_dump`/`pg_restore` 的最小脚本和文档：

- 每日完整备份，文件名含 UTC 时间和 schema/product version；
- 备份写入应用主机以外的持久位置；
- 默认保留至少 14 天；
- 文件权限限制，日志不包含连接密码；
- 备份成功不等于可恢复，必须打开恢复副本并跑校验。

创建文件：

- Create: `ops/backup-postgres.sh`
- Create: `ops/restore-postgres.sh`
- Create: `ops/verify-restored-world.ts`
- Create: `docs/deployment/backup-and-recovery.md`

### 6.2 恢复演练

在独立数据库：

1. 从预发创建备份；
2. 恢复到新数据库；
3. 核对 schemaVersion、账号数、世界 actor、账本健康和最新事件时间；
4. 启动应用并登录测试账号；
5. 原预发数据库不受影响。

### 6.3 世界重置演练

- 先发系统公告；
- 执行 `RESET BLACKPINE` 确认流程；
- 核对账号、activation code、audit 和 AI call log 的保留规则；
- 核对角色、世界、市场、任务、意图和事件已清理/重建；
- 创建新角色并完成首轮玩家链路；
- 记录操作者、时间、版本和结果。

世界重置不能替代备份恢复。

## 7. 7 天预发持续运行合同

### 7.1 观察方式

新增只读采样与汇总脚本，不需要开发者“挂机看七天”：

- system scheduler/cron 每小时执行一次 snapshot；
- snapshot 写 JSONL 到部署 artifact 目录，不写进数据库业务表；
- 每日汇总一次，结束时生成 7 天报告；
- 监控失败只报警，不调用修复、重置或补资产接口。

创建文件：

- Create: `apps/server/scripts/capture-soak-snapshot.ts`
- Create: `apps/server/scripts/verify-soak-report.ts`
- Create: `docs/verification/v1.0-soak-report-template.md`

### 7.2 每小时采样

- deployed commit/version；
- `/health` 与 `/ready`；
- world runtime last settled time/lag；
- NPC hunger、active goal/action、全窗口活性；
- 市场库存/交易、资源 charges、任务创建/完成；
- 铜币与物品账本健康；
- AI calls、tokens、fallback、invalid/stale intent；
- session、sync、5xx 和 process restart count；
- 最近备份时间与文件存在性。

### 7.3 故障注入

观察期内只允许一次预先计划的 provider outage 演练：暂时让 DeepSeek 请求失败，确认 fallback 生效且 world tick 继续。演练后恢复配置并记录时间，不修改数据库业务数据。

## 11. 停止条件

- 生产配置或日志输出 secret；
- 数据库公网暴露或使用开发默认密码；
- 备份未做恢复验证就被标记完成；
- 负载脚本绕过真实 session、sync 或 mutation 路径；
- 通过放宽 p95、错误率或账本阈值解决失败；
- 7 天期间人工改库、补资产、重置或静默重启；
- 候选代码变化后继续沿用旧 7 天报告；
- 没有目标服务器却宣称已经完成对外部署；
- 发放激活码前未准备公告、反馈和已知问题材料。
