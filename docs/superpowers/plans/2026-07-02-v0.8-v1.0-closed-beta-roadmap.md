## 0. 对齐结论（产品负责人已确认的四个决策）

1. **验证主轴**：刷宝成长负责基础留存，AI 活世界负责产品差异化。AI 不直接裁决资产和数值，但必须至少拥有一个“结构化意图 → 规则验证 → 世界执行 → 记忆反馈”的可观察闭环，不能继续停留在文案层。
2. **副本**：不进 v1.0。副本积木（多房间、Boss 机制、事件脚本）留给 v1.1+，用内测反馈决定副本形态。
3. **多人形态**：大厅级——在线玩家列表、全服聊天、排行榜、稀有掉落广播。野外维持私人实例，不做共享野图（引擎双轨统一推迟）。
4. **节奏**：原 16-17 周估算已失效。v0.10.6 根因修复和 v0.10.7 AI 原生闭环均通过后，才重新估算 v1.0 收口时间。

## 1. v1.0.0 的定义与门禁

v1.0.0 = 第一个可以发激活码给 10-30 个朋友、无需开发者盯着也能持续运转的版本。

发布门禁（全部满足才能发码）：

- [ ] 新玩家从注册到第一件掉落装备 ≤ 15 分钟，全程无需口头指导。
- [ ] 世界连续运行 7 天无人工干预：无死锁、无经济崩溃、NPC 保持活性（模拟报告 + 预发环境实测双证据）。
- [ ] 经济活性指标达标：7 天模拟中 NPC 空闲率 < 30%、资源持续再生、铜币守恒断言通过、任务持续产生。
- [ ] 大厅可用：在线列表、聊天、排行榜、掉落广播在 10 并发下正常。
- [ ] 审核报告全部 Critical（C1-C4、E1-E3）与 Important（I1-I9）关闭。
- [ ] 世界重置实弹演练一次成功（保留账号，重建世界，含回滚预案）。
- [ ] 真实 E2E（非 mock）覆盖：注册→建角色→采集→战斗→掉落→装备→市场→NPC 任务→聊天。
- [ ] v0.10.6 并发、同步、恢复和 HUD 四个修复包全部验收通过。
- [ ] v0.10.7 至少一个 AI 原生 NPC 意图闭环通过真实模型和模板 fallback 双路径验收。
- [ ] 管理端可以：看玩家/NPC/经济/AI 状态、禁用账号、作废激活码、重置世界。
- [ ] 内容毕业线核算完成：休闲玩家（日 1 小时）毕业周期 ≥ 10 天，并已明示毕业后钩子。
- [ ] 发布说明 + 已知问题清单 + 玩家反馈渠道 + 系统公告通道就位。

明确不在 v1.0 范围：副本、共享野外地图、玩家间交易、公会、PVP、组队、WebSocket 实时推送、生活职业系统、完整移动端适配（v1.0 只做窄屏可浏览状态/聊天的降级）。

### 4.0 物品与装备统一层（第 1 周，本版一切内容的地基）

现状问题（审核 R2 的深层版本）：装备和道具是两个互不相通的系统——`ItemDefinition.category` 连 `equipment` 类目都没有，`training_sword` 等新手装备是 `game.service.ts` 内联硬编码的裸属性对象，`characterEquipment.itemKey` 是无定义引用的自由文本；库存写路径散布在 8 个文件、4 个模块。直接在这个底子上做词缀掉落会把碎片化放大一个数量级。

统一层分三块，全部属于"MUD 引擎"的职责：

1. **content：统一物品定义注册表**
   - 所有"东西"都是 `ItemDefinition`：`category` 扩展为 `food | material | ore | equipment`（未来 `consumable` 等）；equipment 类目的定义携带 slot、基础属性（攻/防/敏/血）、maxDurability、可词缀性。
   - 词缀池同样是 content 数据：affix id、适用槽位、数值范围、稀有度权重。
   - 具体 `ItemId` 由 content 注册表拥有；shared DTO 使用 string，routes/service 通过 content 运行时校验，避免 shared/content 反向依赖。
   - 附内容校验测试（id 唯一、引用完整、数值范围合法）。
   - 现有新手装备迁入 content 定义，删除 `STARTER_EQUIPMENT` 内联硬编码。
2. **game-rules：item-rules / loot-rules 纯函数**
   - 收编现有 `addInventoryItem`（堆叠数学）、`equipment-rules`（耐久/修理）。
   - 新增：`rollEquipment(seed, itemDefId, rarity)` 种子确定性词缀生成、`canEquip` 校验、装备属性聚合。
3. **server：唯一写路径 `ItemService`**
   - 统一两种存在形态：**可堆叠条目**（itemId + quantity）与**唯一实例**（装备 = 定义引用 + 稀有度 + 词缀 roll + 耐久状态，随装备栏扩展一起做实例表迁移）。
   - 统一操作原语：`grant / consume / transfer（角色↔NPC↔托管↔市场）/ equip / unequip / destroy`——任务交付、对话让渡、市场买卖、掉落入包全部变成对这些原语的调用。
   - 每个原语：事务内、原子增量、写账本事件（与 v0.10 的 I2 统一账本天然衔接）。
   - game / npc-task / dialogue / npc 四个模块全部改为依赖此服务，删除 8 处分散写路径。

与 v0.7.1 的关系：v0.7.1 是在现有结构上做急救（事务 + 条件更新），其事务模式和并发测试会原样迁移进 `ItemService`，不是重复劳动——先止血，再归一。

验收锚点：新增一种物品或装备只改 `packages/content`；全仓库 `grep` 库存/装备写 SQL 只命中 `ItemService` 一处。

### 4.1 成长系统

- XP → 升级曲线（`game-rules` 纯函数：`xpToNextLevel(level)`，建议 1.35-1.5 次方曲线，1→10 级约覆盖内测两周活跃量）。
- 每职业每级属性成长（攻/防/敏/血，写进 `packages/content` 职业定义，不硬编码）。
- 升级事件 + 前端升级反馈（这是最便宜的多巴胺，别省）。
- 等级作为区域门槛（进入第二区域需要 ≥ 4 级左右，用数据说话可调）。

### 4.2 装备掉落系统（最小可惊喜版，建立在 4.0 之上）

- 稀有度四档：普通（白）/ 优良（绿）/ 稀有（蓝）/ 史诗（紫）。传奇与特效词缀推迟。
- 词缀池（4.0 的 content 注册表）：攻击、防御、敏捷、生命上限、采集速度、修理折扣等 6-8 条。绿 1 条、蓝 2 条、紫 2 条+数值上浮。
- 掉落生成即 4.0 的 `rollEquipment`：种子确定性纯函数，复用战斗种子体系，可测试可回放。
- 装备栏从 2 扩到 4：武器 / 胸甲 / 头部 / 饰品（新部位白装底子进 content；装备实例表迁移在此完成）。
- 怪物掉落表扩展：装备条目 + 物品等级随区域缩放；掉落入包走 `ItemService.grant`。
- 前端：掉落高亮、装备对比面板（新旧属性并排 diff——刷宝游戏的核心 UI，值得花时间）、稀有度配色。

### 4.3 第二区域与遭遇刷新

- 新区域"旧矿坑"（原路线图 v0.4 就规划过 old mine）：更高物品等级、2-3 种新怪（含一个小头目式强化怪）、铜矿/铁矿资源点。
- **内容驱动化重构（R1/E5 落地，加第二张图的前置条件）**：进入区域、地图结算、遭遇查找全部改为读 `packages/content` 的 zone 注册表，删除 `enterCorruptForest` 式专用方法/路由，改为 `enterZone(zoneId)` 通用入口。做完的标准：加第三张图只需要在 content 里加数据。
- 遭遇刷新机制：每角色地图实例内遭遇战胜后进入冷却（分钟级，content 可配），配合 E2 的逃跑代价，堵死无限刷。

### 4.4 客户端底盘（v0.8.0 与 4.0 并行的第二条地基线）

详见配套 spec《客户端 HUD 与交互架构设计》。要点：输入上下文栈 + 快捷键注册表（结构性根除 C4 类问题）、GameShell 拆分与三层状态架构、**`sync_events` 单调游标 + 单一 `/game/sync` 增量同步端点 + 单轮询器**（防止 v0.9 聊天/在线/进度各开轮询导致请求失控；进度条冻结问题在此关闭）、事件驱动反馈层（掉落/升级多巴胺管线）+ 全局稀有度色板、面板注册表（v0.9 大厅/离线报告即插即用）、新手引导框架骨架（v1.0 填内容）。I8（错误码/401 拦截）在此实施。

## 5. v0.9 大厅与活世界体感（4 周）

目标：朋友们感觉到"我们在同一个世界玩"+"这个世界记得我"。两个体感，一个版本。

### 5.1 大厅级多人

- 数据：聊天消息表、在线状态（session 心跳/`last_seen`）、排行榜查询（等级榜/财富榜）。
- 接口：扩展 v0.8 的 `/game/sync` 增量端点（chat/presence 字段按需附带），**不新开独立轮询**；不做 WebSocket——10-30 人规模单轮询器足够，payload 结构已按推送兼容设计。
- 前端：大厅/聊天作为面板注册表的新面板挂载，聊天输入接入 text-entry 输入上下文。
- 稀有掉落广播：蓝装以上掉落写全服广播事件，进聊天流（"{玩家} 在旧矿坑拾获了 {稀有装备}！"）——把 v0.8 的刷宝和多人缝在一起，这条是大厅的灵魂。
- 前端：大厅面板（在线列表 + 聊天 + 排行榜 tab），聊天输入框要接入 C4 的键盘守卫。
- 最小防滥用：聊天长度限制、发送频率限制（服务端）、admin 可删除消息。

### 5.2 AI 放大器（严格遵守 AI 边界清单：新 purpose = policy + fallback + 审计 + 边界测试）

- **离线世界报告**（本版最高性价比功能）：登录时生成"你不在的 X 小时里……"摘要——数据源为 `npc_events`/`world_rumors`/市场价格变动/自己挂机结算结果，规则层选材，AI 只做改写（新 purpose `offline_summary`，模板 fallback 必备）。
- **AI 预算熔断**（本版新增 AI 调用面，配套上保险）：基于 `ai_call_logs` 的全局日 token 预算（env 配置），超限自动降级为模板 fallback（记 `disabled`），管理端 AI 状态面板显示预算余量；每账号每日 `offline_summary` 限 1 次。
- NPC 记忆连续性体感：对话 prompt 主动引用 `system_verified` 记忆（"上次你送来的矿石帮了大忙"），favor 态度分级在对话开场白中可感知。纯 prompt/表达层工作，不动权限。
- 传闻个人化：传闻挖掘扩展到玩家高光事件（稀有掉落、任务完成），让玩家在传闻里看到自己的名字。

### 5.3 验收

- [ ] 两个账号互相看到在线、能聊天、能在排行榜看到对方。
- [ ] 蓝装掉落 30 秒内出现在另一账号的聊天流里。
- [ ] 下线 2 小时再登录，看到包含真实事件的离线报告；AI 关闭时模板报告同样成立。
- [ ] 对同一 NPC：完成任务前后对话开场白可感知变化（人工验收 + prompt 快照测试）。
- [ ] `offline_summary` purpose 通过全部边界回归测试（无奖励承诺/OOC/新事实注入）。

## 6. v0.10 运营防线（3 周）

目标：出事的时候你有工具，而不是连夜改库。安全/运维类审核项集中在此版清偿。

- **真实世界重置**（I4）：单事务清空 21 张世界表 + 重新初始化 + 审计，显式保留账号/激活码/审计；前端二次确认 + 演练一次。
- **统一账本 + 守恒校验器**（I2）：任务托管/发放/退款、对话让渡、工资全部入账本；"全世界铜币守恒"作为管理端仪表 + 模拟断言 + 集成测试三处复用。
- **模拟报告升级**（E6）：1/3/7 天报告加活性指标（NPC 空闲率、资源存量趋势、货币流速、任务触发率、饥饿分布），管理端可一键跑（对内存克隆跑，非破坏性）。
- **账号运营**：禁用账号 + 全 session 撤销、激活码作废（revoke）、审计覆盖（安全审查发现 5/10）。
- **安全收尾**：全局 setErrorHandler（I6）、登录/注册限流（I7）、ADMIN_BOOTSTRAP 实现或删除（I9）、注册防枚举与登录时间侧信道拉平（Minor 顺带）。
- 管理端仪表整合：玩家详情、经济面板、AI 状态既有页面串成一个能回答"世界现在健康吗"的首页。
- **系统公告通道**：admin 可发全服公告（进聊天流置顶/高亮）——内测期间重置、停机、迁移的玩家沟通渠道。配套定内测期迁移策略：优先非破坏性迁移，世界重置为最后手段且必须提前公告。

验收：

- [ ] 预发环境执行一次完整重置演练：重置→世界重新初始化→新账号可正常游玩。
- [ ] 守恒校验器在管理端实时可见，模拟与集成测试断言接入。
- [ ] 用一个测试账号完整走一遍"被盗处置"流程：禁用→踢下线→恢复。
- [ ] 错误处理/限流上线后全量测试依然全绿。

## 7. v1.0.0 内测候选（2-3 周）

目标：收口，不加新系统。只做三类事：打磨、验证、准备。

- **内容毕业线核算**（先做，决定打磨重点）：明确定义内测内容量——等级封顶 10 级、两张野图、四槽位装备紫装毕业；按掉率/XP 曲线核算休闲玩家（每日 1 小时）到毕业约 10-14 天，重度玩家 4-6 天。若核算显示 3 天内刷穿，优先加深度（小头目词缀独占、更陡的紫装掉率）而不是加广度。毕业后的留存钩子明示为"等 v1.1 副本"，内测公告直说。
- **新手前 15 分钟打磨**：引导框架（v0.8 骨架）填规则与文案——首次受伤/饥饿/掉落/升级/任务的解释时刻、键位说明面板（从 HotkeyRegistry 自动生成）、开场引导文案。
- **可用性基线**（HUD spec §8）：长文本统一防溢出、键盘全流程可达、稀有度色板对比度、窄屏降级布局（明示 PC 优先，手机可浏览状态和聊天）。
- **数值调参**：用 v0.10 的模拟报告跑 3 组参数（掉率、XP 曲线、经济流速），选定内测初始参数并记录依据。
- **真实 E2E**：Playwright 直连真实 server + 真实 Postgres（替换全 mock），覆盖门禁清单里的完整链路；CI 接入。
- **性能基线**：10 并发模拟玩家跑 1 小时，记录 p95 延迟和 DB 负载，作为内测对照基线。
- **部署与备份**：生产环境部署流程文档化、每日备份 + 恢复演练一次、`.env` 生产配置核对（AI 预算上限、限流参数）。
- **内测运营准备**：激活码批量生成、玩家反馈渠道（群 + 内置反馈入口二选一）、已知问题清单、内测公告/说明文档、观测指标口径（日登录、会话时长、7 日留存代理指标——都能从 sessions/game_events 查）。
- 发布 v1.0.0，发码，开始内测。
