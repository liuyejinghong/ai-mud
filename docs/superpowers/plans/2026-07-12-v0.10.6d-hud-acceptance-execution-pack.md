# v0.10.6D HUD 架构与验收执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 保留已认可的场景/行动优先 HUD 方向，同时让界面保持一屏、组件化、响应式且可测试。

**架构：** 把数据编排移入 controller，通过注册表渲染有明确职责的面板，保留唯一弹层管理器和输入上下文栈；窄宽度使用布局模式切换，不把桌面栏位纵向堆叠。

**技术栈：** React 18、TypeScript、CSS Grid、Testing Library、Playwright。

### 任务 2：提取 Controller 与 Selectors

- [ ] **Step 1: Create selector tests**

Cover selectors for:

```ts
selectSceneObjects(state)
selectContextualObjective(state)

```

Objectives must use game language, for example:

```text

采集中：下一批基础铁矿石将在本轮结束后入账。
饥饿虚弱：前往市政厅申请一份应急口粮。
```

- [ ] **Step 2: Move orchestration into `useGameController`**

The controller owns API mutation state, sync, lobby data, active modal, dialogue/market state, and error channels. It returns a stable view model and command methods; panels never call fetch directly.

```ts
interface GameController {
  state: GameStateDto;
  view: GameViewModel;
  commands: GameCommands;
  modal: ActiveModal | null;
  closeModal(): void;
}
```

- [ ] **Step 3: Keep input architecture centralized**

Hotkey registration and input context remain in GameShell/controller. Extracted panels receive commands and never add window keydown listeners.

### 任务 4：提取弹层与面板注册表

- [ ] **Step 1: Move each modal into its own file**

All modals remain controlled by the single `ActiveModal` union and ModalManager. No modal adds document-level listeners.

- [ ] **Step 2: Add an auxiliary panel registry**

Use:

```ts
interface PanelRegistration {
  id: "map" | "rumors" | "offline" | "lobby" | "tasks";
  title: string;
  badge?: (view: GameViewModel) => number | string | null;
  visibleWhen: (view: GameViewModel) => boolean;
  render: (props: PanelRenderProps) => ReactNode;
}
```

The registry controls auxiliary tabs/drawers. Primary scene/action/status areas are not registry entries and cannot be displaced by optional features.

### 任务 6：实现固定视口响应式模式

- [ ] **Step 1: Replace the 1180px waterfall rule**

Do not set `.game-shell { height: auto; overflow: auto; }` for gameplay widths. Define CSS variables and explicit tracks:

```css
.game-shell {
  --hud-gap: 12px;
  height: 100dvh;
  overflow: hidden;
}

@media (min-width: 1200px) {
  .game-shell { grid-template-columns: 280px minmax(0, 1fr) 280px; }
}

@media (min-width: 900px) and (max-width: 1199px) {
  .game-shell { grid-template-columns: 250px minmax(0, 1fr); }
  .game-auxiliary { position: fixed; inset: 12px 12px 12px auto; width: min(360px, 40vw); }
}
```

Auxiliary content is opened as a tabbed drawer at mid width, not placed below the left rail.

- [ ] **Step 2: Bound every dynamic region**

Scene text, event log, lobby, inventory, task tracker, rumors, and offline report each have stable min/max tracks and internal overflow. Hover, badges, loading text, and empty states cannot change column dimensions.

- [ ] **Step 3: Add Playwright viewport assertions**

For 1440x900, 1180x900, and 980x900:

```ts
const metrics = await page.evaluate(() => ({
  innerHeight,
  scrollHeight: document.scrollingElement?.scrollHeight ?? 0
}));
expect(metrics.scrollHeight).toBeLessThanOrEqual(metrics.innerHeight + 1);
```

Also assert the scene, primary action, current action or empty state, event-log entry point, and movement access are visible without page scrolling.

- [ ] **Step 4: Run and commit**

```bash
pnpm --filter @ai-mud/web e2e --grep "HUD viewport"
git add apps/web/src/features/game/GameShell.css apps/web/e2e
```
