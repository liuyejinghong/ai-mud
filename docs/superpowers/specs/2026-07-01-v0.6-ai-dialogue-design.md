# v0.6.0 AI 对话护栏层设计规格

## 1. 目标

`v0.6.0` 的目标是把 AI 第一次安全接入游戏运行时，让玩家可以和两个长期 NPC 进行受约束的自然语言对话：

- 黑铁匠伯林：`blackpine_blacksmith_borin`
- 市政官艾廉：`blackpine_officer_elian`

本版本只做对话，不做 AI 任务、AI 奖励、AI 记忆压缩、AI 副本生成。AI 可以表达 NPC 的性格、处境、需求和态度，但不能直接改变金币、物品、经验、装备、市场、战斗或任务状态。

## 2. 设计原则

- AI 是表现层和意图建议层，不是规则裁判。
- 服务端规则仍然拥有资产、任务、战斗、经验、库存和经济状态的最终裁决权。
- 所有 AI 输出必须是结构化 JSON，并通过 schema 校验。
- 所有 AI 回复必须短，默认面向 MUD 对话窗口，不允许返回长篇小作文。
- AI 请求必须可审计：记录 NPC、玩家、模型、prompt 版本、输入摘要、输出摘要、token 用量、耗时、失败原因。
- 没有 API Key、AI 超时、schema 失败或安全校验失败时，游戏必须仍可运行，用模板回复兜底。
- 玩家输入可以自由文本，但必须有限长、有限频、服务端校验。

## 3. DeepSeek 接入边界

根据 DeepSeek 官方 API 文档，当前 OpenAI 兼容接入参数为：

- `base_url`: `https://api.deepseek.com`
- 推荐模型：`deepseek-v4-flash`
- API Key 环境变量：`DEEPSEEK_API_KEY`
- JSON 输出：`response_format: { "type": "json_object" }`

官方文档还说明旧模型名 `deepseek-chat` 和 `deepseek-reasoner` 将在 `2026-07-24 15:59 UTC` 废弃，因此本项目不使用旧模型名。

项目侧不直接依赖 DeepSeek SDK 专有类型，而是实现一个 `AiProvider` 接口：

```ts
export interface AiProvider {
  completeJson(input: AiJsonCompletionInput): Promise<AiJsonCompletionResult>;
}
```

首版实现：

- `DeepSeekAiProvider`：真实 HTTP/OpenAI-compatible 调用。
- `TemplateAiProvider`：无 Key、测试、失败兜底时使用。
- `FakeAiProvider`：单元测试中注入固定 JSON。

## 4. 对话产品形态

### 4.1 玩家入口

在游戏主界面中，玩家位于黑松哨站时，可以看到可交互 NPC 列表。首版只显示：

- `!` 或对话标识不是本版本重点；本版本 NPC 只有聊天入口，不显示任务感叹号。
- 伯林和艾廉各有一个“交谈”按钮。
- 点击后打开对话弹窗。

### 4.2 对话弹窗

弹窗包含：

- NPC 名字、职业、简短状态。
- 最近 6 条对话消息。
- 快速回复按钮，例如“最近缺什么？”、“你今天在忙什么？”、“我能帮上什么吗？”
- 自由文本输入框。
- 发送按钮。
- 加载状态和失败提示。

本版本不做流式输出。AI 返回后一次性显示短回复。

### 4.3 回复长度

服务端限制：

- 玩家输入最多 300 个中文字符或等效长度。
- AI 回复正文最多 180 个中文字符或等效长度。
- AI 输出 JSON 总体 `max_tokens` 首版控制在 300-500 范围。
- 如果 AI 返回超长内容，服务端截断并记录校验事件。

## 5. 数据模型

新增三类持久化记录。

### 5.1 `ai_call_logs`

用于审计每次模型调用。

字段：

- `id`
- `provider`
- `model`
- `promptVersion`
- `purpose`: 首版固定为 `npc_dialogue`
- `accountId`
- `characterId`
- `npcActorId`
- `requestHash`
- `inputSummary`
- `outputSummary`
- `status`: `success | fallback | rejected | error`
- `latencyMs`
- `inputTokens`
- `outputTokens`
- `errorCode`
- `createdAt`

不记录完整 API Key，不记录隐私敏感凭据。玩家原文可以记录到对话表，但 AI 调用日志只保留摘要和哈希。

### 5.2 `npc_dialogue_messages`

用于保存最近对话上下文。

字段：

- `id`
- `accountId`
- `characterId`
- `npcActorId`
- `speakerType`: `player | npc | system`
- `message`
- `safetyFlags`
- `createdAt`

首版上下文只读取同一玩家和同一 NPC 最近 6 条消息，不做长期记忆。

### 5.3 `npc_relationships`

用于给后续 AI 任务和记忆做基础，但首版只轻量使用。

字段：

- `id`
- `characterId`
- `npcActorId`
- `familiarity`
- `trust`
- `lastInteractionAt`
- `shortSummary`

首版对话成功后只小幅增加 `familiarity`，不让 AI 直接修改关系数值。

## 6. AI 输出 Schema

首版 NPC 对话只允许以下 JSON：

```json
{
  "reply": "短回复，必须符合 NPC 人设，不超过 180 个中文字符。",
  "mood": "neutral",
  "safety": {
    "containsRewardPromise": false,
    "containsRuleChange": false,
    "containsOoc": false
  },
  "suggestedIntent": {
    "type": "none",
    "reason": "本版本不创建任务，只能解释 NPC 当前需求。"
  }
}
```

允许的 `mood`：

- `friendly`
- `neutral`
- `guarded`
- `annoyed`
- `worried`

允许的 `suggestedIntent.type` 首版只有：

- `none`
- `express_need`

即便 AI 返回 `express_need`，服务端也只把它当成文本表现，不创建任务、不发奖励、不改库存。

## 7. Prompt 输入上下文

服务端构造结构化上下文：

- NPC 固定设定：姓名、职业、性格、说话风格、禁区。
- NPC 当前真实状态：位置、饥饿、钱包、库存摘要、当前行动、最近事件。
- 玩家状态摘要：等级、职业、位置、饥饿、最近一次和该 NPC 对话。
- 世界状态摘要：黑松哨站、市场是否缺食物/矿石、市政金库大致状态。
- 最近 6 条对话。
- 玩家当前输入。

禁止放入：

- API Key、session token、密码、内部错误堆栈。
- 完整数据库行。
- 不必要的长日志。

## 8. 安全校验

服务端在 AI 回复进入游戏前执行：

- JSON parse 失败：使用模板兜底。
- Schema 失败：使用模板兜底。
- `reply` 为空：使用模板兜底。
- `reply` 超长：截断，记录 `rejected_length`。
- 出现明显越权承诺，例如“我给你 100 金币”“你获得装备”：拒绝并兜底。
- 出现 OOC 或模型自述，例如“作为 AI 模型”：拒绝并兜底。
- 出现要求玩家提供密钥、密码、现实身份信息：拒绝并兜底。

所有拒绝都写入 `ai_call_logs`，方便后续调 prompt。

## 9. 成本与性能

首版默认：

- `AI_NPC_DIALOGUE_ENABLED=false` 时完全走模板。
- `AI_NPC_DIALOGUE_ENABLED=true` 且 `DEEPSEEK_API_KEY` 存在时才调用模型。
- 单账号 NPC 对话冷却：每 5 秒 1 次。
- 单条输入长度限制：300 字符。
- 单条输出限制：180 字符。
- 请求超时：8 秒。
- 失败后不重试或最多 1 次轻重试。

Prompt 中 NPC 固定设定保持稳定，方便命中上下文缓存。动态上下文只放短摘要。

## 10. API

新增游戏 API：

- `GET /game/npcs/dialogue-targets`
  - 返回当前位置可交谈 NPC。
- `GET /game/npcs/:npcActorId/dialogue`
  - 返回该玩家与该 NPC 最近对话。
- `POST /game/npcs/:npcActorId/dialogue`
  - 输入 `{ message: string }`
  - 返回最新消息列表和本次 NPC 回复。

后台 API：

- `GET /admin/ai-calls`
  - 查询最近 AI 调用日志。

## 11. 测试策略

必须覆盖：

- 无 API Key 时使用模板回复。
- 有 fake provider 时返回结构化 NPC 回复。
- AI 返回非法 JSON 时兜底。
- AI 试图承诺奖励时被拒绝。
- 玩家超长输入被拒绝。
- 只有伯林和艾廉出现在首版可对话目标里。
- 前端能打开 NPC 对话弹窗、发送快速回复和自由文本。
- 管理后台能看到 AI 调用日志。

不要求：

- 真实 DeepSeek API 的 CI 测试。
- 流式输出。
- AI 任务创建。
- NPC 长期记忆压缩。

## 12. 验收标准

- 玩家可以和伯林、艾廉对话。
- 回复短、像 NPC、不会 OOC。
- AI 不能发金币、物品、经验、装备。
- 无 Key 或 AI 失败时，玩家仍收到合理模板回复。
- 所有 AI 调用有审计记录。
- 测试、类型检查、构建、E2E 全部通过。
