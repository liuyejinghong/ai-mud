# v0.4.0 经济基础闭环设计

## 1. 版本目标

v0.4.0 的目标是把 v0.3.0 已经跑通的挂机行为，接入第一版可持续经济底座。

本版本先做“玩家和市政集市之间的库存、买卖、价格、税收、铁矿石和修理资源约束”。后续 NPC 自主工作、AI 任务、AI 讨价还价、铁匠打造和多城镇贸易，都应复用这套经济账本，而不是各自写一套临时交易逻辑。

v0.4.0 不追求经济完全真实，重点是先保证三件事：

- 物品来自真实产出或市政库存，不凭空无限购买。
- 金币、银币、铜币有统一记账方式，可以用于后续税收、工资、任务奖励和交易。
- 基础铁矿石进入资源链，为装备修理和后续打造留出资源约束。

## 2. 范围边界

v0.4.0 包含：

- 魔兽式货币单位：金币、银币、铜币。
- 服务端统一用铜币整数记账。
- 市政集市库存账本。
- 玩家向市政集市出售物资。
- 玩家从市政集市购买物资。
- 库存驱动的动态价格第一版。
- 交易税作为第一类货币回收口。
- 基础铁矿石 `iron_ore`。
- 第一类矿点：废弃铁矿脉。
- 装备修理的第一版成本模型：铜币 + 铁矿石。
- 市政库存兜底和世界重置兼容。
- 前端集市界面，展示库存、价格、税费和玩家持有量。

v0.4.0 不包含：

- NPC 自主买卖和工资流转。
- NPC AI 讨价还价。
- NPC 发布 AI 经济任务。
- 铁匠 NPC 的真实个人账本。
- 装备耐久完整 UI。
- 装备打造。
- 多城镇差价和商路。
- 饱腹度和食物消耗。
- 日常/周常任务。

这些内容不是放弃，而是需要等市政集市和交易账本稳定后再接入。v0.4.0 的经济层应该像“轨道”，后续 NPC 和 AI 只是使用轨道运行。

## 3. 玩家可见体验

### 3.1 货币显示

玩家状态栏中的货币改为三段显示：

```text
金币 0 | 银币 12 | 铜币 35
```

服务端内部只保存铜币总额。例如：

```text
1 金币 = 100 银币
1 银币 = 100 铜币
1 金币 = 10000 铜币
```

前端只负责格式化展示，不能自行计算交易是否合法。

### 3.2 市政集市

黑松哨站新增市政集市入口。玩家可以：

- 查看市政库存。
- 查看每种物品的当前收购价和出售价。
- 向集市出售野莓、兽肉、粗糙兽皮、基础铁矿石。
- 从集市购买库存中存在的物品。
- 看到交易税。

集市不是无限商店。某个物品库存为 0 时，玩家不能购买。玩家出售物品后，物品进入市政库存，后续玩家或 NPC 都应从这份库存里购买。

### 3.3 基础铁矿石

腐林新增一个固定资源点：

- 名称：废弃铁矿脉。
- 产出：基础铁矿石。
- 基础采集周期：60 秒。
- 每周期产出：1 个基础铁矿石。
- 首版位置：腐林中一个固定格子。

固定矿点用于确保修理系统有基础材料来源。后续可以扩展矿洞、铜矿、银矿、稀有矿脉和天气/事件影响。

### 3.4 修理入口

v0.4.0 可以先做最小修理入口，不需要完整装备耐久 UI。

规则先落地：

- 修理必须消耗铜币。
- 修理必须消耗基础铁矿石。
- 玩家身上或市政库存中没有足够铁矿石时，修理不能完成。
- 修理价格由规则包计算，服务端执行扣款和扣材料。

如果 v0.4.0 实现时现有装备还没有耐久字段，可以先只暴露“修理规则和接口骨架”，并在 UI 上隐藏入口。不能为了赶功能做一个只花钱、不消耗矿石的假修理。

## 4. 经济模型

### 4.1 货币单位

数据库字段统一保存 `copper_balance`：

- 角色钱包：`characters.copper_balance`。
- 市政金库：后续可扩展 `municipal_treasury.copper_balance`。
- 交易流水：金额字段全部保存铜币。

前端和 DTO 可以返回格式化结果：

```ts
type MoneyDto = {
  copper: number;
  silver: number;
  gold: number;
  totalCopper: number;
};
```

### 4.2 市政库存账本

市政集市新增库存表：

- `id`
- `settlement_id`
- `item_id`
- `quantity`
- `target_quantity`
- `base_buy_price_copper`
- `base_sell_price_copper`
- `updated_at`

首版只有黑松哨站一个 `settlement_id`。保留字段是为了后续多城镇扩展。

### 4.3 动态价格第一版

价格由规则包纯函数计算：

```text
库存系数 = target_quantity / max(current_quantity, 1)
收购价 = base_buy_price * clamp(库存系数, 0.5, 2.0)
出售价 = base_sell_price * clamp(库存系数, 0.8, 3.0)
```

含义：

- 库存少，集市更愿意收购，出售也更贵。
- 库存多，集市压低收购价，出售更便宜。
- 价格有上下限，避免早期经济被极端库存打穿。

v0.4.0 不做复杂竞价。后续 NPC AI 可以在这个价格基础上判断是否划算，但不能绕过账本凭空交易。

### 4.4 税收

所有玩家和市政集市的交易都收税：

- 玩家购买：按成交价收 5% 交易税。
- 玩家出售：税从玩家应收金额中扣除 5%。
- 税额进入市政金库或暂时作为系统回收。

如果市政金库表暂时不实现，交易流水仍必须记录 `tax_copper`，并在服务端把税额从流通货币中移除。这样后续补市政财政时可以迁移。

### 4.5 不设置生硬每日吸收上限

v0.4.0 不先做“每天最多卖多少”的硬上限。资源产出已经受挂机时间、采集周期和资源点数量约束。首版优先通过这些机制控制产出。

如果测试中出现刷钱过快，优先调整：

- 资源点总量。
- 采集周期。
- 基础收购价。
- 目标库存。
- 价格上下限。

只有这些还不够时，再考虑更拟真的限制，例如集市资金不足、市政采购计划或运输瓶颈。

## 5. 资源链

### 5.1 食物链预留

v0.4.0 只把食物放进集市买卖，不实现饱腹度消耗。

物品：

- 野莓 `wild_berry`
- 兽肉 `beast_meat`

后续饱腹度系统会复用这些物品，并把“吃饭消耗”接入经济循环。

### 5.2 材料链

物品：

- 粗糙兽皮 `rough_hide`

兽皮暂时只作为可交易材料，后续用于皮甲、背包、任务和 NPC 需求。

### 5.3 矿石链

物品：

- 基础铁矿石 `iron_ore`

基础铁矿石是 v0.4.0 必须落地的资源，因为装备修理不能只花钱。修理和打造的底层原则是：

- 钱用于支付服务费用、税费和 NPC/市政收入。
- 矿石用于真实材料消耗。

后续可以增加：

- 铜矿石。
- 银矿石。
- 魔铁矿。
- 特殊副本矿。
- 矿石品质和装等。

## 6. 装备修理第一版

### 6.1 修理成本

规则包提供纯函数：

```text
修理铜币 = 装备等级 * 耐久损失比例 * 基础修理系数
修理铁矿石 = ceil(装备等级 * 耐久损失比例 / 10)
```

首版如果装备没有耐久字段，可以先定义默认损失比例和接口，不对玩家开放真实修理按钮。

### 6.2 材料来源

修理材料来源按优先级：

1. 玩家背包中的基础铁矿石。
2. 玩家选择从市政集市购买铁矿石后再修理。

服务端不能自动从市政库存扣材料帮玩家修理，除非玩家明确同意支付对应购买费用和税费。

### 6.3 后续铁匠扩展

v0.5 或更后续版本接入 NPC 铁匠时，铁匠可以有自己的库存、报价和利润判断。但铁匠也必须遵守：

- 没有矿石不能修。
- 没有材料不能打造。
- 给玩家奖励或赠送装备时，必须从自己库存扣除。

## 7. 引擎边界

### 7.1 内容包负责“有什么”

`packages/content` 定义：

- 物品分类。
- 基础价格。
- 基础装等。
- 资源点和采集产出。
- 市政初始库存建议值。

### 7.2 规则包负责“怎么算”

`packages/game-rules` 定义纯函数：

- 货币格式化。
- 动态价格计算。
- 税额计算。
- 买卖交易结果预览。
- 修理成本计算。

规则包不访问数据库，不修改库存。

### 7.3 服务端负责“是否合法并落账”

`apps/server` 负责：

- 校验玩家钱包。
- 校验玩家背包。
- 校验市政库存。
- 扣钱、扣物品、增减库存。
- 写交易流水。
- 返回最新游戏状态。

所有交易必须在事务里完成。不能先扣玩家物品再因为库存写入失败而留下半笔交易。

### 7.4 前端负责“怎么操作”

`apps/web` 负责：

- 显示市政集市。
- 展示买价、卖价、税额、库存和玩家持有量。
- 让玩家输入数量或用快捷按钮选择数量。
- 提交买卖意图。

前端不能自行决定成交价，也不能只在本地改背包。

## 8. 数据模型

建议新增：

- `characters.copper_balance`
- `market_inventory`
- `market_transactions`

`market_transactions` 字段建议：

- `id`
- `settlement_id`
- `character_id`
- `transaction_type`：`buy` 或 `sell`
- `item_id`
- `quantity`
- `unit_price_copper`
- `gross_copper`
- `tax_copper`
- `net_copper`
- `created_at`

交易流水是后续排查经济崩溃的关键。内测阶段如果发现价格失衡，先看流水，而不是凭感觉调数值。

## 9. 接口建议

- `GET /game/market`：返回市政集市库存、价格、税费预览和玩家持有量。
- `POST /game/market/buy`：玩家购买物品。
- `POST /game/market/sell`：玩家出售物品。
- `POST /game/repair/quote`：返回修理报价。
- `POST /game/repair`：执行修理。若装备耐久 UI 未开放，可先不暴露到前端。

`GET /game/state` 可以返回简化后的 `marketSummary`，但不要把完整集市列表塞进每次状态查询，避免后续市场变大后浪费响应体。

## 10. UI 原则

市政集市首版可以使用右侧面板或弹窗，不需要做复杂商店页。

每一行物品至少展示：

- 名称。
- 分类。
- 市政库存。
- 玩家持有。
- 当前收购价。
- 当前出售价。
- 税额提示。
- 买入按钮。
- 卖出按钮。

如果价格因为库存变化而变动，界面要显示刷新后的价格。买卖成功后写入主日志，让玩家明确看到交易发生。

## 11. 验收标准

v0.4.0 完成时必须满足：

- 玩家货币以金币、银币、铜币显示。
- 服务端内部金额全部用铜币整数计算。
- 玩家可以出售野莓、兽肉、粗糙兽皮和基础铁矿石。
- 玩家出售后，市政库存增加，玩家背包减少，玩家货币增加，税额被扣除。
- 玩家可以购买市政库存中存在的物品。
- 玩家购买后，市政库存减少，玩家背包增加，玩家货币减少，税额被扣除。
- 市政库存为 0 时不能购买。
- 基础铁矿石能通过废弃铁矿脉挂机采集获得。
- 动态价格随库存变化而变化，并受到上下限保护。
- 交易流水记录成交价、数量、税额和净额。
- 修理成本模型包含铜币和基础铁矿石，不能只花钱修理。
- 不引入 AI 调用。
- 不引入 NPC 自主行动。

## 12. 测试策略

### 12.1 规则测试

- 金币、银币、铜币格式化。
- 库存少时价格上升。
- 库存多时价格下降。
- 价格上下限生效。
- 税额四舍五入或向上取整规则稳定。
- 修理成本同时包含铜币和铁矿石。

### 12.2 服务端测试

- 买入成功事务。
- 卖出成功事务。
- 库存不足拒绝购买。
- 钱不够拒绝购买。
- 背包不足拒绝出售。
- 交易税写入流水。
- 铁矿石资源点可启动采集行动。

### 12.3 前端测试

- 集市面板展示库存和价格。
- 买卖按钮调用正确接口。
- 成功交易后刷新背包、货币和库存。
- 错误提示不覆盖主操作区域。

### 12.4 浏览器验证

- 注册/登录/进游戏。
- 出城采集铁矿。
- 返回黑松哨站。
- 打开市政集市。
- 出售铁矿石。
- 购买一个库存物品。
- 确认日志、背包和货币变化。

## 13. 后续扩展

v0.4.0 之后，建议按这个顺序扩展：

1. v0.5 NPC 经济行动：农民、矿工、铁匠使用同一套集市账本买卖。
2. v0.6 固定任务和市政任务：任务提交物资进入市政库存。
3. v0.7 饱腹度：玩家和 NPC 定时消耗食物。
4. v0.8 AI 任务：NPC 基于真实库存和需求发布任务。
5. v0.9 铁匠打造和修理：铁匠拥有个人库存和利润判断。

## 14. 自检结论

这个范围和之前讨论保持一致：

- 不让 AI 或 NPC 凭空造物。
- 不让动物掉金币。
- 不用硬性每日回收上限替代真实产出控制。
- 把税收作为货币回收口。
- 把基础铁矿石纳入首版，因为装备修理需要材料约束。
- 先做可复用经济账本，再让 NPC 和 AI 使用它。
