# v0.10.6 根因修复设计

状态：已批准，待执行
日期：2026-07-12
输入：`docs/reviews/2026-07-12-v0.10.5-product-code-acceptance-report.md`
取代：`docs/superpowers/specs/2026-07-06-v0.10.6-playability-ui-remediation.md` 作为 v0.10.6 的执行依据；旧文档保留为首次 UI 反馈记录。

## 1. 版本目标

v0.10.6 不是新功能版本，而是内测前的根因修复版本。它要把当前“能展示但不能可靠运行”的 Demo 收口成：

- 并发请求不能重复发放资产或制造负余额；
- `/game/sync` 是客户端唯一同步入口，任务、传闻、饥饿、行动和背包状态一致；
- 后台世界生产由调度器驱动，玩家读请求不生成任务、不调用 AI、不改变公共世界；
- 新玩家和返回玩家都不存在永久软锁；
- NPC 任务能在 NPC 对话中发现、接取、提交；
- 1440x900 和 980x900 都能在一屏内完成主要判断；
- 前端功能通过组件和注册表接入，不再继续扩大 GameShell；
- 真实 PostgreSQL E2E 覆盖主玩法闭环。

## 2. 范围边界

### 本版必须完成

1. 采集周期并发幂等。
2. 市场与修理的非负资产写路径。
3. NPC 任务、传闻移出玩家请求路径。
4. `/game/sync` 读模型补齐任务、传闻和结算后状态。
5. 行动轮询稳定在配置间隔，不因对象引用变化重启。
6. 饥饿归零后的有限市政救济。
7. `availableActions` 只描述当前真正可执行的动作。
8. NPC 对话内任务闭环。
9. 市场失败不关闭弹窗；本地时间和地点名称正确。
10. HUD 组件化、管理后台工作区分离、登出入口。
11. 1440x900、1180x900、980x900 浏览器验收。
12. 真实后端 E2E 和并发 PostgreSQL 集成测试。

### 本版不做

- 完整 AI 副本。
- NPC AI 日计划或行为意图。
- 新地图、新装备、新掉落表、新经济数值。
- 玩家交易、共享野图、公会、PVP。
- WebSocket。
- 完整移动端玩法。
- 市场库存与 ItemService 的全面模型统一；本版只保证现有双模型写路径一致、非负、可审计。

## 3. 版本与执行包

`v0.10.6` 只有一个正式产品版本。A-D 是执行模块，不是对外 SemVer：

| 模块 | 目标 | 依赖 | 可并行性 |
| --- | --- | --- | --- |
| A 资产一致性 | 采集、市场、修理并发安全 | 无 | 最先执行 |
| B 同步与世界生产 | sync 统一、任务/传闻调度化、轮询稳定 | A 的迁移编号与并发约束 | A 后执行 |
| C 玩家闭环 | 救济、任务交互、错误与时间语义 | B 的同步读模型 | B 后执行 |
| D HUD 与验收 | 组件化、响应式、后台分离、真实 E2E | 可与 A/B 开发并行；最终验收依赖 C | 可并行开发，最后合流 |

迁移编号和兼容版本按 A → B → C 串行分配，避免并行分支同时占用同一个迁移号。D 不新增数据库迁移。

## 4. A：资产与行动并发一致性

### 4.1 采集结算

所有会结算进行中采集的入口必须在数据库事务内：

1. 锁定 active action 行；
2. 重新读取 action payload；
3. 锁定对应 map instance；
4. 根据最新 `settledCycles` 和资源 charges 计算增量；
5. 发放物品、扣减资源、更新 payload、写事件和账本；
6. 提交事务。

禁止使用调用事务前读到的 `CharacterActionRecord` 直接结算。锁等待后的事务必须重新读取。

锁顺序固定为 `character_actions → map_instances → inventory`，取消、到期结算和同步结算使用同一顺序，避免死锁。

### 4.2 市场与铜币

市场物品行在报价前 `FOR UPDATE`。资产扣减使用条件原子更新并检查影响行数：

- 玩家扣款：`WHERE copper_balance >= amount`；
- 市政扣款：`WHERE copper_balance >= amount`；
- 市场扣库存：`WHERE quantity >= amount`；
- 角色/NPC 物品扣减：沿用 ItemService 的条件更新。

买入、卖出和修理任一步失败，整个事务回滚。数据库增加非负 CHECK 约束，作为服务层之后的最后防线。

### 4.3 验收

- 20 个并发同步请求只结算一次同一采集周期。
- 两个并发买家争抢最后一件库存，只有一个成功。
- 同一角色并发发起两笔超出余额的购买，最多一笔成功，余额不小于 0。
- 并发卖出不能让角色物品或市政余额为负。
- 并发修理同一装备不能重复收费。

## 5. B：统一同步与世界生产

### 5.1 读写职责

玩家请求允许结算“该玩家自己的到期/周期状态”，但不允许生产公共世界内容。边界如下：

- `/game/sync`：可结算当前玩家行动和饥饿；纯读取 NPC 任务、传闻、大厅数据。
- world runtime scheduler：推进 NPC、检测任务需求、生产任务、生产传闻。
- AI 文案：不得在数据库长事务内等待。

`listTasksForAccount()` 改为纯读。`syncOpenTasks()` 和 `syncRumors()` 不得从任何 game route 调用。

### 5.2 后台生产两阶段

任务与传闻使用两阶段生产，避免在事务中调用模型：

1. 规则阶段：读取已提交世界事实，生成有限候选；
2. AI 阶段：在事务外生成受约束文案，失败使用模板；
3. 提交阶段：短事务内重新检查需求、阻断任务、NPC 余额和 source 唯一性，再写入。

多进程并发由数据库唯一约束兜底：

- NPC 同时只能有一个 `open/accepted` 任务；
- 同一 `(source_type, source_id)` 最多一条传闻。

### 5.3 sync 读模型

`/game/sync` 返回 state 时必须补齐：

- 当前地点允许展示的 NPC 任务；
- 已接任务摘要；
- 最近公共传闻；
- 玩家结算后最新 hunger、injury、inventory 和 action。

公开任务只在 NPC 位于玩家当前可交互地点时出现。野外不展示村内开放任务；已接任务通过紧凑追踪器查看。

`settleReadableState()` 返回 `stateChanged`，不能依赖“碰巧写入某条 sync_event”决定是否返还变化后的 state。

### 5.4 轮询

轮询节奏只依赖稳定标量：

- `activeActionId`；
- `isActionActive`；
- 配置间隔。

服务端返回同一行动的新对象不得触发即时重轮询。目标：空闲 15 秒一次，行动中 3 秒一次；失败使用有上限的退避，不并发重入。

## 6. C：玩家恢复与任务闭环

### 6.1 有限市政救济

玩家满足全部条件时获得“申请口粮”动作：

- 位于黑松哨站；
- hunger ≤ 1；
- 背包没有食物；
- 铜币不足以购买市场最便宜的一份普通食物；
- 过去 24 小时没有领取过救济。

优先从市政集市扣除一份最低装等食物。库存不足时允许市政应急库存注入一份基础口粮，但必须记录 `system_source → player` 账本和 `municipal_relief` 原因。该兜底是防卡死机制，不参与普通市场价格计算。

### 6.2 可执行动作契约

`availableActions` 是服务端承诺，而不是按钮建议：

- hunger=0 或仍在养伤时不下发出城动作；
- 没钱时市场仍可打开，但购买按钮按价格禁用；
- 只有满足救济条件时下发 `claim_relief`；
- 野外不下发 NPC 任务交互；
- action active 时只下发与该行动兼容的动作。

### 6.3 NPC 任务

NPC 对话目标 DTO 包含当前任务的 `id/status/title`。对话弹层直接提供：

- `open`：接取；
- `accepted` 且材料足够：提交；
- `accepted` 且材料不足：显示缺口；
- `completed/expired`：只显示结果，不显示动作。

主 HUD 不再常驻展开村内开放任务。已接任务进入紧凑追踪器，点击后打开详情。

### 6.4 错误、时间和地点

- mutation helper 返回成功/失败，只有成功才关闭弹窗。
- 市场错误显示在市场弹窗内部。
- 玩家事件时间使用浏览器本地时区格式化。
- 离线简报使用内容注册表解析地点名称，模板不展示 ISO 原始字符串和内部 ID。
- AI provider/status 只进管理后台，不显示在 NPC 对话标题。

## 7. D：HUD 架构与响应式

### 7.1 组件边界

`GameShell` 只负责：

- game controller/provider；
- 输入上下文与 hotkey registry；
- modal manager；
- 顶层布局选择。

状态、场景、行动、日志、大厅、小地图、装备、背包、传闻、离线报告和管理后台拆成独立组件。目标是 `GameShell.tsx ≤ 300` 行；不以机械拆文件为目标，公共规则进入 selector/controller，展示逻辑进入 panel。

### 7.2 布局断点

- `≥1200px`：三栏固定视口；各栏内部滚动。
- `900-1199px`：左侧状态栏 + 主区两栏；小地图、传闻、大厅进入辅助 tab/drawer，不得堆到主区下方。
- `<900px`：降级为可查看状态、日志和聊天的单栏；完整野外操作不作为 v0.10.6 门禁。

1440x900、1180x900、980x900 必须断言 `document.scrollingElement.scrollHeight <= innerHeight + 1`。弹窗可以覆盖视口，但不能扩大页面高度。

### 7.3 新手引导

恢复面向玩家的首次引导，不展示开发验收术语。步骤只覆盖：

1. 进入旧矿坑或腐林；
2. 使用 WASD/小地图移动；
3. 开始采集并等待一个周期；
4. 查看背包入账；
5. 返回哨站处理 NPC、集市和装备。

引导状态属于客户端偏好，以 `characterId + tutorialVersion` 存入 localStorage；可折叠、可重置，不影响服务端权威状态。

### 7.4 游戏与后台分离

管理员登录后默认仍进入游戏。顶栏提供“游戏 / 管理”工作区切换，管理工作区使用 tab 按需挂载单个管理面板，不再把所有后台组件渲染在游戏下方。顶栏提供登出。

## 8. 测试与发布门禁

### 必须新增

- PostgreSQL 并发集成测试：采集、买入、卖出、修理。
- service 测试：任务/传闻不再由读取触发。
- hook 测试：activeAction 对象更新不导致即时重轮询。
- route 测试：sync state 包含地点正确的任务和传闻。

- 组件测试：对话任务动作、市场错误留在弹窗、UTC 转本地时间。
- Playwright：1440/1180/980 布局和弹窗快捷键。
- 真实 E2E：注册、建角、采集周期入账、战斗、掉落、装备、市场、NPC 任务、聊天。

## 9. v0.10.7 决策门

v0.10.6 通过后，不直接进入 v1.0 收口。先单独设计 v0.10.7“AI 原生 NPC 意图闭环”：NPC 根据天气、需求、库存和记忆提出当日/临时计划，规则验证后执行，结果进入事件和记忆，玩家可在对话中观察其因果。

v0.10.7 不属于本修复包，必须另行完成产品设计确认和执行计划。
