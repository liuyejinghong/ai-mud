# v0.2 Playable Loop Slice Design

状态：已确认
日期：2026-07-01

## 1. 目标

v0.2 的完整目标是让玩家拥有第一个可玩的 MUD 闭环：创建角色、进入新手村、探索腐林、采集资源、触发自动战斗、受伤回村并获得基础掉落。

本规格只覆盖 v0.2 的第一段，版本建议标记为 `v0.2.0`：

- 角色创建和选择。
- 新手村作为登录后的第一个游戏界面。
- 腐林野外方格地图。
- 键盘 `W/A/S/D` 和鼠标方向按钮移动。
- 基础资源采集。
- 背包中能看到采集所得物品。

自动 ATB 战斗、受伤回村、怪物掉落进入下一段 `v0.2.1`。这样第一段可以快速形成可点、可走、可采集的最小可玩面，同时不把战斗数值和探索状态搅在同一个实现批次里。

## 2. 设计取舍

### 推荐方案：垂直小切片

先实现“角色 -> 村子 -> 腐林 -> 移动 -> 采集 -> 背包反馈”的一条垂直路径。服务端先持久化角色、位置和背包，客户端做 MUD shell。

优点：

- 最快得到可操作体验。
- 后续战斗、经济、NPC 都能复用角色、地图、背包和命令通道。
- 测试边界清楚：不需要先模拟完整世界经济。

缺点：

- 第一段还没有战斗刺激。
- 采集资源的经济价值暂时只进入背包，不进入市场。

### 备选方案：先做战斗规则包

先在 `packages/game-rules` 做 ATB 战斗、怪物和掉落，再接 UI。

优点：规则先行，战斗质量更早可测。

缺点：用户打开游戏仍然看不到可玩的世界入口，反馈周期慢。

### 备选方案：先做世界数据库全量模型

先把地图、角色、背包、物品、资源点、事件和未来战斗全部建表。

优点：后续扩展更从容。

缺点：前期建模容易过度，且还没有实际玩法压力校验字段是否合理。

结论：采用垂直小切片。只建 v0.2.0 必须用到的数据结构，但命名和边界保留 v0.2.1/v0.3 扩展空间。

## 3. 功能范围

### 3.1 角色创建和选择

登录后的玩家如果没有角色，看到角色创建界面。

首批职业：

- 战士：高生命、高护甲，基础采集速度正常。
- 游侠：高敏捷，移动和采集更轻快，后续战斗攻速更快。
- 术士：高智力，首段只展示属性差异，战斗法术留到 v0.2.1。

角色字段：

- `id`
- `accountId`
- `name`
- `classId`
- `level`
- `xp`
- `hp`
- `maxHp`
- `injuryUntil`
- `currentLocation`
- `createdAt`

首段只允许每个账号创建一个角色。多角色槽位后续再加，避免先做角色管理复杂度。

### 3.2 新手村

新手村是安全区，不做探索格子移动。

首段村子只需要：

- 当前地点标题：黑松哨站。
- 简短地点描述。
- 可进入野外入口：腐林。
- 背包摘要。
- 角色属性摘要。

后续 v0.3 会把市政厅、集市、铁匠铺、任务牌接入这里。v0.2.0 不实现交易和 NPC 对话。

### 3.3 腐林地图

腐林是第一张野外探索地图。

首段地图规则：

- 地图大小：`5 x 5`。
- 玩家从南侧入口进入，初始坐标为 `(2, 4)`。
- 地图中有固定出口格，回到新手村。
- 地图中有若干可采集资源点。
- 地图中预留怪物群位置字段，但 v0.2.0 不触发战斗。

移动规则：

- `W`：向北，`y - 1`。
- `S`：向南，`y + 1`。
- `A`：向西，`x - 1`。
- `D`：向东，`x + 1`。
- 不能走出地图边界。
- 每次移动由服务端校验并返回新状态。

客户端可以显示一个简单方格小地图：

- `@` 表示玩家。
- `R` 表示资源。
- `E` 表示出口。
- `?` 表示未探索或普通区域。

地图生成首段采用确定性内容模板，不调用 AI。后续 AI 事件、天气、蘑菇等动态事件在 v0.5 进入。

### 3.4 采集

首段采集是一个即时动作，不做长时间挂机进度条；挂机耗时和中断机制留到 v0.2.1/v0.3。这样可以先验证资源点、背包、命令和 UI。

资源类型：

- `wild_berry`：野莓，食物类。
- `beast_meat`：兽肉，食物/材料类。
- `rough_hide`：粗糙皮革，材料类。

采集规则：

- 玩家站在有资源的格子上才能采集。
- 每个资源点有剩余次数。
- 采集成功后资源进入背包。
- 资源点耗尽后从地图状态中标记为空。
- 每次采集写入服务端日志事件，客户端显示文本反馈。

首段不做：

- 市场出售。
- 饱腹度消耗。
- 资源刷新。
- NPC 抢采。

这些留给 v0.3 经济世界。

## 4. 架构边界

### 4.1 服务端权威

客户端只提交意图：

- `createCharacter`
- `enterZone`
- `move`
- `gather`
- `returnToVillage`

服务端负责：

- 校验账号 session。
- 找到当前角色。
- 校验移动边界。
- 校验资源点存在。
- 更新角色位置和背包。
- 返回新的游戏状态。

### 4.2 包边界

`packages/content`：

- 职业定义。
- 腐林地图模板。
- 资源定义。

`packages/game-rules`：

- 移动边界校验。
- 采集结果计算。
- 背包堆叠规则。

`packages/shared`：

- 角色 DTO。
- 地图 DTO。
- 背包 DTO。
- 游戏命令/响应 DTO。

`apps/server`：

- 数据库 schema。
- 角色、世界状态、背包 repository。
- HTTP routes。

`apps/web`：

- 游戏 shell。
- 角色创建页。
- 地点视图。
- 方格地图。
- 快捷键和鼠标方向按钮。
- 背包/日志展示。

## 5. 数据模型

首段需要新增持久化表：

- `characters`
- `character_inventories`
- `character_world_states`

设计原则：

- 账户和角色分离。
- 背包用 `item_id + quantity` 堆叠。
- 当前地图状态先存为 JSON，便于快速迭代腐林资源点；后续如果资源/NPC/事件复杂，再拆成规范表。

建议：

- `characters.current_location` 存 `village:black_pine` 或 `zone:corrupt_forest`。
- `character_world_states.zone_state_json` 存腐林坐标、已探索格、资源点剩余次数。
- `character_inventories.item_id` 使用 content 稳定 ID。

## 6. UI 和交互

首段 UI 不做营销页，登录后直接进入游戏 shell。

游戏 shell 布局：

- 左侧：角色状态和背包摘要。
- 中间：地点描述、事件日志、主要操作。
- 右侧：小地图和方向按钮。
- 底部：输入栏预留，但首段不实现复杂文本命令。

键盘：

- 在腐林中监听 `W/A/S/D`。
- 在输入框聚焦时不触发移动。
- 鼠标方向按钮和键盘使用同一条命令路径。

移动反馈：

- 成功：日志显示“你向北移动，树影遮住了回路。”
- 失败：日志显示“边界被倒伏的黑木挡住。”
- 资源格：日志提示“这里有可采集的野莓。”

## 7. 错误处理

- 未登录：返回 `UNAUTHENTICATED`。
- 没有角色：返回需要创建角色的状态。
- 非法职业：返回 `VALIDATION_ERROR`。
- 移动越界：返回 `VALIDATION_ERROR`，不改变位置。
- 不在野外地图：移动或采集返回 `VALIDATION_ERROR`。
- 没有资源：采集返回 `VALIDATION_ERROR`。

所有资产变化必须服务端计算。客户端不能直接改背包。

## 8. 测试和验收

必须覆盖：

- 职业内容定义存在且稳定。
- 移动规则阻止越界。
- 采集会减少资源点次数并增加背包数量。
- 未登录不能访问游戏状态。
- 已登录但无角色会看到创建角色入口。
- 创建角色后进入新手村。
- 进入腐林后可以用键盘或鼠标移动。
- 站在资源点可以采集并看到背包数量变化。

验收：

- 新账号注册登录后，3 分钟内能创建角色并进入新手村。
- 玩家能进入腐林并移动至少 3 格。
- 玩家能采集至少一种资源。
- 背包显示采集所得。
- 刷新页面后角色和背包状态仍在。

## 9. 不做范围

v0.2.0 不做：

- 自动 ATB 战斗。
- 受伤回村。
- 怪物掉落。
- 饥饿。
- 市场经济。
- NPC 日程。
- NPC AI 对话。
- AI 地图生成。
- 副本。
- WebSocket 实时推送。

这些都保留在既定路线图中，不能在 v0.2.0 实现时顺手扩张。

## 10. 自检

占位符扫描：未发现占位文本或未定义行为。

一致性检查：本规格与主路线图一致，把 v0.2 Playable Loop 拆成 `v0.2.0` 和 `v0.2.1`；第一段不包含战斗，第二段接自动 ATB。

范围检查：本规格只覆盖一个可测试垂直切片，可独立写实施计划。
